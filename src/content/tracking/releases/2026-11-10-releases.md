## 模型

### 1. Claude Fable 5.2 / Mythos 5.2：同一底模、降价与可选快档

Anthropic 11 月 9 日发布 Fable 5.2 与 Mythos 5.2，两者是同一个底层模型，Fable 带较强的网络安全与生物防护、面向全部用户，Mythos 通过验证计划开放给相关研究机构。价格降到每百万输入 8 美元、输出 40 美元，缓存读取 0.20 美元；可选 fast mode 把生成速度提到最多 2.5 倍，价格 16/80 美元。官方称输出比 Fable 5.1 快最多 30%，并给出 1M 上下文。基准上，FrontierCode 2.0 在 Xhigh 档 49.1%（Opus 5.5 45.5%、GPT-6 Astra 42.8%），FrontierSWE v2 69.9%，OSWorld 2.1（离线集、部分）89.3%；官方还称这次实验在 30 小时内形式化了费马大定理，对应热点条目 2 的 28.7 小时（公告取整）。Claude Code 2.1.321 已把 `claude-fable-5-2` 设为默认 Fable 模型。

来源：[Introducing Claude Fable 5.2 and Claude Mythos 5.2](https://www.anthropic.com/claude-fable-and-mythos-5-2)｜Anthropic｜2026-11-09｜A；[Claude Code v2.1.321](https://github.com/anthropics/claude-code/releases/tag/v2.1.321)｜2026-11-09｜A

### 2. GPT-6 Cyber：面向授权范围的网络安全模型

OpenAI 11 月 5 日发布 GPT-6 Cyber，定位是找可利用漏洞并开发修复的网络安全模型，官方摘要强调它被训练为停留在授权范围内。本轮只读到 RSS 摘要，正文页两次取数均为 403，因此能力边界、基准与访问方式留待下一轮核对。它与 Fable/Mythos 的 cyber 防护一起，显示专用安全模型这条线在成形。

来源：[Introducing GPT-6 Cyber](https://openai.com/index/introducing-gpt-6-cyber)｜OpenAI｜2026-11-05｜A（官方 RSS 摘要；正文未读）

### 3. Ripple-65B Preview：65B 稠密模型在美国开放权重里拿到 agentic coding 最高分

Ricursive Intelligence 11 月 5 日（北京时间；HN 提交时间，页面未标日期）发布 Ripple-65B Preview，65B 稠密 Transformer、支持 1M 上下文，官方称在 TerminalBench 2.1 上拿到 80.52，超过更大的开放权重模型（Reflection Beam 501B 80.1、Meta Muse Spark Open 816B 76.4 等），并给出约 3200 万美元的全研发成本与 140 万次 rollout 的 RL 训练量。模型可在 Hugging Face、Together、OpenRouter 等渠道取用，官方强调能在 DGX Spark 这类本地设备上运行。这些数字均为厂商自报，基准设置与复现条件未独立核验。

来源：[Ripple-65B Preview](https://www.ricursive.com/ripple)｜Ricursive Intelligence｜2026-11-05（北京时间；HN 提交时间，页面未标日期）｜A（厂商发布，数字自报）

### 4. Kimi K3.1 Pro：2.8T MoE 开放权重，许可与基准争议同时出现

Moonshot 11 月 4 日在 Hugging Face 放出 Kimi K3.1 Pro 权重：2.8T 总参数、104B 激活、93 层、1M 上下文、原生多模态，定位 agentic 模型；许可为自定义的 `kimi-k3.1-pro`，不是标准开源许可。窗口内社区出现多条审计线索：有分析称权重约 1.56 TB、许可含年收入门槛；有 PDF 审计称模型「回忆并执行了从未给出的隐藏测试规则」；也有人称其生成假的 OpenAI 密文。这些指控均未独立复核，按线索保留。

## Agent 与运行工具

### 5. Codex 0.167.0：命令中心、跨后端会话与更细的审批点

OpenAI Codex 11 月 6 日转稳定。用户可见的变化包括：`codex agents --no-daemon` 打开 agent 命令中心，会话选择器标记未读结果；在终端会话选择器里切换已连接的后端并保留草稿；TUI 支持本地图片附件预览；在「Sign in another way」里配置 API key 与云厂商，实验项可引导 Google Cloud Vertex AI；`/experimental` 可选用 macOS/Windows 系统代理；审批提示打开时可在 transcript 里展开 patch 详情。变更记录里还有一批 Guardian 审查相关提交：受管命令检查点要求新的人工批准、对记录下来的 exec 调用做直接审查、按服务评估自适应审查。影响：Codex 的审批面从「模式开关」细化为「按命令、按后端、带检查点的复核」。

来源：[rust-v0.167.0](https://github.com/openai/codex/releases/tag/rust-v0.167.0)｜OpenAI｜2026-11-06｜A

### 6. Claude Code 2.1.319 / 2.1.321：MCP 任务后台化、权限语义与默认模型

2.1.319（北京时间 11 月 7 日凌晨）把 MCP 任务搬到后台：服务器以 task 形式跑工具调用时，Claude Code 立即转后台、完成后再告知模型，并给出 `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` 让它等待。新增 `permissions.denyInsteadOfPrompting`：本该等待权限提示的调用直接拒绝、回合继续，终端、子代理和 teammate 都适用。auto mode 在遥测或特性开关关闭、又经过 LLM 网关时，改为询问或拒绝，不再回退到内置分类器。修复项里有一条 worktree 创建时的沙箱逃逸、一条构造环境前缀绕过 Bash 权限检查、一条 `sed` 跳过权限检查。2.1.321（北京时间 11 月 10 日凌晨）默认 Fable 5.2，修 MCP OAuth 重定向把 refresh token 发给别的主机，收紧「含邮箱与 User-Agent 的 shell 命令」检查，并调整 mods 的权限行为：Claude 写的 mod 在 auto/bypass 模式下自动开启，mod 自身工具调用不再触发权限提示（deny 规则与组织策略仍生效）。

来源：[v2.1.319](https://github.com/anthropics/claude-code/releases/tag/v2.1.319)、[v2.1.321](https://github.com/anthropics/claude-code/releases/tag/v2.1.321)｜Anthropic｜2026-11-07 / 2026-11-10（北京时间；GitHub 记为 11-06 / 11-09 UTC）｜A

### 7. OpenAI Agents SDK 0.24.0-alpha.7：Classic 与 native 双轨、应用自持存储与预算

11 月 8 日的 alpha 把执行栈分成两条：保留的 v0 运行时通过 `agents.classic` 导入，新 native 执行并行推进。新增 `SessionStore`、`SQLiteSessionStore` 与 `CustomStorage`，让应用自己持久化根会话与工具结果；对不确定的工具效果要求显式核对，不自动重放。`RunBudget` 在下次请求前限制请求数、token 或估算成本；`before_complete` 可以接受、返回 `ContinueTurn` 或停止一个提议答案；`transform_context` 只改采样输入、不改存储历史。还加了 provider 托管的 `FileSearch`、`CodeInterpreter`、`ImageGeneration` 与 MCP 资源/提示读取。升级注意：Environment 默认 `write_policy="strict"`，需要兼容的 Linux/macOS executor；模型目录把 `gpt-6-astra` 等默认推理档从 low 调到 medium。

来源：[Agents SDK v0.24.0-alpha.7](https://github.com/openai/openai-agents-python/releases/tag/v0.24.0-alpha.7)｜OpenAI｜2026-11-08｜A

### 8. Google ADK 2.14.0：执行环境、A2A 与评测转稳定，堵住技能脚本的任意命令

发行说明标注 2026-11-04、GitHub 发布 2026-11-07 的 ADK 2.14.0 把执行环境与沙箱（`BaseEnvironment`、`LocalEnvironment`、Daytona、E2B）、A2A、评测与部分核心运行时从实验转稳定；新增 `MultiRunConfig`（`adk eval --num_runs`）与并行度，评测可多次运行合并分数；`ToolArgsMatcher` 支持精确、忽略大小写、数值容差与 LLM 语义匹配。安全上最实的一条是 `RunSkillScriptTool` 不再接受自由形式的 `command`，模型改为传 `args`/`short_options`/`positional_args`，脚本只能从技能目录运行、只支持 `.py`/`.sh`/`.bash`——官方说这堵住了一个可被提示注入用来跑任意 shell 的洞。`MongoDbMemoryService` 加了向量检索与 TTL；30 节点工作流跑 200 轮的性能官方称提升 23%、峰值内存降 9%。

来源：[v2.14.0](https://github.com/google/adk-python/releases/tag/v2.14.0)｜Google｜2026-11-04（发行说明）/ 2026-11-07（GitHub 发布）｜A

### 9. Qwen Code 0.27.0 / 0.27.1：多子问题、渠道过滤与可选个人记忆

0.27.0（北京时间 11 月 8 日凌晨）让托管代理会话同时挂起多个子问题、任意顺序回答，草稿与错误按子问题隔离；Web Shell 加任务问答热图与「解释待选项但不回答」的侧任务；GitHub 渠道编辑器支持仓库 allowlist/blocklist；shell 工具的 sed 模拟处理 CRLF 与 Unicode，取消的命令标记为中断并保留部分输出。0.27.1（11 月 9 日）加入 opt-in 的个人记忆（Mem0 支撑）、LSP 的用户级设置、默认后台执行可配置，以及一批托管代理诊断与 daemon PR 监听的基础设施。影响：Qwen Code 继续把「托管代理」从能跑补到有审批、有记忆、有渠道治理的形态。

来源：[v0.27.0](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.0)、[v0.27.1](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.1)｜Qwen｜2026-11-08 / 2026-11-09（北京时间；GitHub 记为 11-07 / 11-09 UTC）｜A

### 10. Kimi Code 2.5.0 / 2.5.2：会话创建时选环境、运行中切模型

2.5.0（11 月 4 日）支持在创建会话时指定 SSH、Docker 或自定义命令环境（`--environment`、`--environment-cwd`），可以在 agent 工作时切 `/model` 与 `/effort`（当前回合保持原设置，下一回合生效），支持 fork 正在运行的会话或从历史回合 fork，多目录项目的技能按目录合并、主目录优先。2.5.2（11 月 6 日）修 MCP 工具定义变化时的重复声明、Web UI 的 steering 排队与 HTTP 下的项目创建。影响：远程/容器环境从「先连上再开跑」变成会话属性，模型切换也不再需要中断。

来源：[@moonshot-ai/kimi-code@2.5.0](https://github.com/MoonshotAI/kimi-code/releases/tag/%40moonshot-ai%2Fkimi-code%402.5.0)、[@moonshot-ai/kimi-code@2.5.2](https://github.com/MoonshotAI/kimi-code/releases/tag/%40moonshot-ai%2Fkimi-code%402.5.2)｜Moonshot AI｜2026-11-04 / 2026-11-06｜A

### 11. dsh 0.2.2-rc.1：apply_patch、变更请求与工作树、跨 CLI 委派

DeepSeek harness 11 月 4 日发布 0.2.2 首个候选版。新增默认关闭的 `apply_patch` 工具，一次完成多文件新增、编辑、删除、移动并在 Review 里查看；「变更请求与工作树」进入主包，在独立 Git 工作树里跑会话、看本地与 PR 差异、把选中代码和评论交给 agent；实验性 `subagent_oar` 插件可把独立任务交给本机 Codex 或 Claude CLI。上下文与权限侧：全局与项目 AGENTS.md 分别计预算，避免项目指令挤掉全局；切到更小上下文的模型前先用原模型压缩；Web Fetch 不再拒绝非公网地址（部署需自行限制网络）；Node PTC 增加 VM Script 模式（顶层 await、动态导入、可选跨调用状态）。Breaking：最低 Node 24.9，PTC 控制通道改 birpc、SSH helper 协议从 2 升到 3，原生与 PTC 工具执行拆成按 Agent 作用域的插件。
