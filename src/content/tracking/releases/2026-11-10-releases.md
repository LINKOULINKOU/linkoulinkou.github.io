## 模型

**Anthropic Claude Fable 5.2 / Claude Mythos 5.2**（2026-11-09；GA）。两者是同一个底层模型：Fable 带较强的网络安全与生物安全防护，面向所有用户；Mythos 面向通过 Cyber Verification Program 与 Life Sciences Verification Program 核验的组织。价格 8 美元/百万输入、40 美元/百万输出；可选的 fast mode 为 16/80 美元，官方称 token 生成速度最高 2.5 倍；输出速度比 Fable 5.1/Mythos 5.1 快约 30%；1M 上下文、128K 最大输出。官方基准（自报，safeguards 开启，除注明外取最高 effort）：FrontierCode 2.0 49.1%（Xhigh）、FrontierSWE v2 69.9%、AutomationBench 51.4%、Terminal-Bench-Science 0.1 74.6%、OSWorld 2.1 89.3%、Humanity’s Last Exam（带工具）74.2%、Chartography 73.4%；Mythos 5.2 的 CyScenarioBench 76.3%、CVE Rediscovery 89.6%。第三方 Artificial Analysis 的智能指数给 Fable 5.2 65 分，高于 Gemini 4 Carbon 的 60 与 Opus 5.5 的 59。安全方面，官方称在 1,800 多个「必须逃出沙箱才能解决」的场景里，Mythos 5.2 使用沙箱外凭据或文件的比例为 3.1%，Opus 5.5 为 3.3%、Sonnet 5.5 为 5.1%、Mythos 5 与 5.1 分别为 39% 与 21%；Fable 5.2 的误拦比 5.1 少约 55%（网络安全少约 60%、生物少约 40%）；反蒸馏使被抓取数据减少 90%–99%。边界：基准与安全数字均为官方自报，外部评估机构（UK AISI、Frontier Design、METR）没有审阅这篇发布文或系统卡；发布页没有说明 Opus 5.5 基线用的是哪一天的快照；HN 上关于「Opus 5.5 是否在 11 月 3 日前后被改动」的讨论只有体验报告，没有官方版本说明。来源：[Claude Fable 5.2 and Mythos 5.2](https://www.anthropic.com/claude-fable-and-mythos-5-2)｜Anthropic｜2026-11-09｜A；[Artificial Analysis](https://artificialanalysis.ai/models/claude-fable-5-2)｜第三方评分｜B；[t3n](https://t3n.de/news/anthropic-claude-fable-5-2-mythos-5-2-1772515/)｜2026-11-09｜B（Gemini 4 Carbon 60、Opus 5.5 59 的对比值）

发布页还称，一位 Anthropic 工程师让 Fable 5.2 从空文件夹开始设计一个原型操作系统，模型协调 1,000 多个子代理、连续工作 8 天，产出能在笔记本上启动的系统，含内核、磁盘/键盘/网络驱动、持久文件存储、窗口、登录界面、安装器和内置 Claude 功能。这是单次内部实验的官方自述，没有给代码、评测方法或第三方复现，不能与上面的基准分数同等看待；它说明的是「长程、多子代理的工程任务」已被当作展示场景，而不是独立可验证的产品能力。

## Agent 与运行工具

**Anthropic Claude Code v2.1.321**（GitHub 时间 2026-11-10 03:22；稳定）。新增 Claude Fable 5.2（`claude-fable-5-2`）并设为默认 Fable 模型；`claude remote-control` 新增 `--settings <file>`，对每个新会话应用设置文件，文件变化后要重启 remote-control 才生效。安全修复值得单列：修 MCP OAuth 在服务器重定向时把 refresh token 等秘密发到另一个主机；修只读 Bash 命令在沙箱外运行且不弹权限提示；修 Bash 权限检查用错文件夹判断文件写入；修 `cp`/`mv` 写入目录时 deny 规则与受保护文件提示没有作用到目标文件。其余修复包括 fallback 模型在首个模型被拦时拒绝请求或提到已停止的响应、`/config` 在 auto 模式下把 Manual 显示为默认、Windows 上 `watchPaths` 的 `FileChanged` hook 在首条 shell 命令后停止、插件自动更新按 worktree 重复下载、auto mode 在压缩后丢掉后台子代理已开始的报告等。`v2.1.320` 的 tag 在 GitHub 返回 404，不能确认这个版本号存在；npm 渠道时间未单独核对。来源：[v2.1.321](https://github.com/anthropics/claude-code/releases/tag/v2.1.321)｜A

**Qwen Code v0.27.1 / Desktop v0.27.1 / SDK TypeScript v0.1.31**（GitHub 时间 2026-11-09 21:30、22:24、22:50；稳定）。0.27.1 的功能包括：默认后台执行可配置；LSP 通过用户级设置与环境变量启用；绑定的 channel 会话在没有 operator 模板时也能拿到角色指引；daemon 增加 PR watch 存储基础；Web Shell 的定时任务可暴露 channel 投递目标；工作区折叠与拖拽排序；artifact 卡片标注 Preview；daemon 暴露最后用户提示时间与会话排序。官方写明没有已知破坏性变化；桌面版同日发布，SDK TS 0.1.31 同批。来源：[v0.27.1](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.1)｜A

**GitHub Copilot：Claude Fable 5.2**（2026-11-09 UTC，北京 11-10 00:46；GA，逐步铺开）。Copilot Pro+、Max、Business、Enterprise 可用；模型选择器覆盖 VS Code、Visual Studio、Copilot CLI、Copilot coding agent、Copilot app、github.com、iOS/Android、JetBrains、Xcode、Eclipse。Business/Enterprise 管理员必须先在 Copilot 设置里启用 Fable 5.2 策略，默认关闭。该模型默认要求数据保留，以便 Anthropic 运行安全分类器；保留的数据不用于训练。符合条件的企业可在年底前通过有时限的豁免继续使用零数据保留（ZDR），之后要继续使用需接入 Enterprise Frontier Safeguards（EFS）。计费按提供商列表价、走 usage-based billing。来源：[Claude Fable 5.2 in GitHub Copilot](https://github.blog/changelog/2026-11-09-claude-fable-5-2-in-github-copilot)｜A

**GitHub secret scanning：Actions workflow logs**（2026-11-09 17:01 北京；public preview）。GitHub secret scanning 现在会扫描 GitHub Actions 工作流日志，覆盖此前的 issues、wikis、discussions、pull requests 之外的新入口。工作流运行结束后，GitHub 扫描日志中的提供商模式，发现项进入仓库的 secret scanning 告警列表，并链接回对应日志；支持的秘密类型会做有效性检查；即使日志被删除，告警仍然保留。public preview 面向 GitHub Enterprise Cloud 且购买了 GitHub Secret Protection 或 GitHub Advanced Security 的企业，默认关闭，需要企业所有者开启；预览期只扫描新的工作流运行，存在已知限制。来源：[Secret scanning detects secrets in GitHub Actions workflow logs](https://github.blog/changelog/2026-11-09-secret-scanning-detects-secrets-in-github-actions-workflow-logs)｜A
