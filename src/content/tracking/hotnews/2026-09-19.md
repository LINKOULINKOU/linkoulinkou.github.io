## 本期要点

- **ZCode（智谱官方编码代理桌面端）被逆向披露静默上传工作区**：完整 .git（约占包体 87%）、LFS、reflogs 加密后传至云端，UI 隐私开关无效，加密私钥只在服务端；官方承认上传发生、称已修复并将开源，上传范围与「即毁」承诺仍是争议点（A/B；见条目 1）。
- **Claude Code v2.1.278 将 auto mode 权限分类器默认迁至服务端**（不另计费、有账单回退告警）——权限判定过程移出本地（A；见条目 3）。
- **Jev 发布 4 天即出现开源复刻潮**：OpenJev（647 分）、Laya（175 分）等多个项目同周出现（A/B；见条目 4）。

## 本期主线：harness 的信任边界正在云化，且被同时审视

两条独立信号同题：ZCode 被披露**数据侧**的静默上云——本地工作区（含 .git）被打包上传，而解密私钥只在云端，用户对「传了什么、存到哪」没有可见性（条目 1）；Claude Code 把 auto mode 的**权限分类器默认迁到服务端**——判定过程同样移出本地，换取免计费与统一策略（条目 3）。一暗一明，但方向一致：harness 的安全与隐私边界越来越多由云侧组件承担，本地可审计性下降。综合判断：本周治理主线（披露制度化）发展到「harness 自身成为事件主角」，社区对「云侧黑盒」的容忍度正在快速下降——Z.ai 被迫承诺开源就是标志。

### 1. ZCode 被披露静默上传工作区：官方承认、承诺开源，范围与「即毁」仍存争议

**发生了什么**：研究者 ferstar 9/18 发布逆向记录（HN 314 分）：排查 `~/.zcode` 占用 700MB 时发现，登录状态下 ZCode 会把**整个工作区打包上传**——完整 .git（objects/LFS/reflogs，约占包体 87%）、LFS 资产缓存、全局配置——加密后传至阿里云 OSS；**RSA 公钥由服务端即时下发、私钥只在云端**，用户连自己磁盘上的密文都无法解密；起因是一份 313MB 商业项目卡在上传队列。受影响版本审计（3.12.3）：关闭「Optimize Experience」与「Repo Snapshot Indexing」开关**仍然打包上传**；3.14.0 审计：上传管线代码已被物理移除、云凭据端点返回 404。Z.ai 9/18 17:44 声明：上传来自「codebase indexing」（本地索引、会话检查点恢复、Repo Wiki 用途），云端生成 Wiki「可能」上传仓库数据、生成后立即销毁、早期默认开启、**已修复**；ZCode 将开源并接受第三方审查；全员补偿一次周配额。HN 亦有平衡性批评：有评论指原帖混淆「git log（遥测类）」与「git 仓库（内容）」，并称其他家 harness 也上传 git log。

**影响与判断**：事实底线已无争议——Z.ai 不再否认上传发生；争议收敛到三点：上传范围、开关有效性、「即毁」如何被外部验证（与「检查点恢复」功能在逻辑上互相矛盾）。对工作流的直接含义：harness 的「免费功能」可能有数据侧对价，引入任何新 harness 前应审计其网络行为（呼应 09-09 归档的 Coop 条目：先读隔离/边界实现）。**边界**：本条为作者审计自报 + 官方声明的并置，两边的「范围」说法不一，以可复现代码为准；声明原文经 ferstar 与 IT 家转引，未直接核。
