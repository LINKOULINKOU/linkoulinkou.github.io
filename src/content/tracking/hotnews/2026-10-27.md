这一期有两条实质变化：OpenAI 把带 computer use 的中端模型压到批量的价格档，并当天铺进 Codex 与 Copilot；另一位前 GitHub 负责人发布了一个把「评审」重新设计的代码托管站——用 agent 打分和 findings 取代 PR 时间线，并把 agent 的会话写进仓库变成可检索的记忆。第三条是一个把模型能力做成无状态命令行的工具，形态比能力更值得看。

## 本期值得了解

### 1. GPT-6.1 Terra：中端价格把 computer use 变成可批量跑的循环

OpenAI 10-26 发布 GPT-6.1 Terra，官方定位是「快速、高效，兼顾视觉推理、精确的 computer use（让模型直接看屏并操作界面）与更自然的写作」，API 当日可用，同一天进入 GitHub Copilot，官方称也进入 Codex。它能接受文本与图像输入，工具调用需要走 Responses API。

真正改变工程判断的是价格结构：每百万输入 token \$1、输出 \$5，缓存输入只要 \$0.05（未命中价的 5%），30 分钟保留的缓存写入 \$1.25、12 小时 \$2.50；上下文 105 万 token、单次最多输入 92.2 万、输出上限 12.8 万。两条容易被忽略的计价细节：输入超过 27.2 万 token 时整次请求按输入与缓存 2 倍、输出 1.5 倍计价；Batch 与 Flex 半价，Fast 模式双倍。推理档位可设为 none／low／medium（默认）／high／xhigh／max。

为什么值得理解：computer use 的成本结构由「每一步都要把屏幕截图喂进模型」决定，一次任务几十步就是几十次带图请求，价格直接决定这类循环能不能常驻跑。OpenAI 在开发者账号上给的对比是，在自家的 Agents' Last Exam（考察 agent 使用复杂专业软件的基准）上，Terra 达到 Astra 级表现、任务完成速度 3 倍以上、每 token 成本只有十分之一；Simon Willison 按价目核对后指出它的定价约为 Sol 的一半、Luna 的十倍，位置相当于 Anthropic 的 Sonnet 档。Copilot 的公告给了另一组口径：早期测试中它在终端任务与 C# 任务上明显多于 GPT-5.6 Terra，特点是「在边界清楚的任务上走集中的几步」。

边界要摆在结论旁边。第一，Agents' Last Exam 与「3 倍更快」都是 OpenAI 自设基准与自报口径，Copilot 的早期测试也没给数字。第二，OpenAI 的 Ted Sanders 在 HN 评论里自己把定位说窄了：技术沟通比 Astra 和 Sol 好，视觉与 computer use 相近但快得多，其余多数任务更弱——这意味着它不是替换，而是路由里多了一档便宜的执行层。第三，官方支持的工具清单里有一项 tool_search，也就是让模型自己按需发现工具；这正好和上一期讲稿里「由运行框架预先裁剪工具清单」是两条相反的路子，值得并排观察。

### 2. Entire：把评审面从 PR 时间线换成 agent 评分，把会话写进仓库

Entire 10-26 上线，创始人 Thomas Dohmke（前 GitHub CEO）称它是「第一个为 agent 与人协作而建的 Git forge（代码托管站）」。它没有沿用 PR（拉取请求）的线性评论区，而是给了三个原语：

第一是 Trail，代替 PR 的评审面。它的理由很直接：当写代码和审代码的都是 agent，PR 时间线已经变成「只有 agent 会读的审计日志」，人打开它得不到判断依据。Trail 把每次推送触发的自动评测分数提到页面顶部，评审 agent（跑在 Daytona、E2B 的云沙箱里，底层用 Claude Code 与 Codex）各自独立给分并写理由，例如安全、Slop（一眼看上去像凑数的改动）、需要人工复核三类；分数不变绿就继续改再推。同一 Trail 可跨多个仓库，findings 带严重级别，可以被人或 agent 关闭，合并前可按仓库设 gate，把人工批准与 CI 通过作为硬条件。

第二是分布式 Git 托管。它自建了兼容 Git 的服务端（分布式对象存储加事务化 ref 数据库），可按区域复制，官方自测称推送比 GitHub 快 89 倍、比 Cursor Origin 快 6 倍，并把 Buildkite、Depot 作为 CI 集成。

第三是 Continuous Memory：把 agent 的会话与提示词同步进 Git 仓库，并让它对 coding agent 持续可查——这是把「记忆」从某个产品的私有存储挪到仓库这个共享底座上。

值得理解的地方在于它把两个原本分散的东西接到了一起：验证从「人读 diff」变成「agent 打分 + gate」，上下文从「会话历史留在客户端」变成「跟着仓库走、任何人任何 agent 都能检索」。判断边界也清楚：89 倍是厂商自家基准；打分由 agent 给出，等于同一族模型既写又评，评分是否稳定、能不能被操纵没有公开数据；Slop 这类指标是它自己定义的；Trail、Continuous Memory 都还没有第三方复现。

## 其他值得关注

### 3. Gemini API CLI：不造 agent，只给已有 agent 一个无状态的能力外壳

Google 10-26 在 X 上推广 gemini-api 这个命令行工具，明确定位是「给你已经在用的 agent 用」，点名 Codex、Claude Code、Antigravity、Cursor、OpenClaw、Hermes 等，并强调它不是新的 coding agent。分工写在 README 里：agent 负责上下文与计划，它只负责一次 API 调用。因此它无会话、无记忆、每次调用独立；换来的是一组面向 agent 的接口约定——自描述（`--help`、`--schema`、`--usage` 让 agent 现场查参数与返回结构）、`--dry-run` 打印将要发出的请求（凭证打码、不发网络、不读系统钥匙串）、输出可流式、可直接落盘、JSON、紧凑的 TOON 或 `--jq` 过滤。能力面覆盖文本与多模态分析、图像／音视频／语音生成、转录，以及后台托管 agent：起一个长任务后只返回 interaction ID，由宿主自己保存并在需要时取结果。

形态上的意义：它和 MCP 解决同一个问题（让 agent 用上外部能力），走的是 shell 而不是协议。好处是零依赖、任何有 shell 的 agent 都能接、失败面小（文本加退出码，可 dry-run 预演）；代价是没有工具级权限与类型约束，agent 只能靠读帮助文本猜参数，且没有服务端状态可对齐。

时间上要说清楚：仓库 4 月就公开，9-30 起持续发版，最新 0.4.4 是 10-23；10-26 是公开推广与说明，不是首次开源。本条讲的是形态，不是新版本。

## 值得继续追问

- 条目 1 的 27.2 万 token 计价拐点与 105 万上下文是矛盾的组合：真正的长程任务很快会越过拐点付双倍价。这一档在中型仓库的 coding 循环里到底落在拐点哪一侧，需要实测而不是看标价。
- 条目 2 的 agent 自评闭环：写代码与打分的都是 Claude Code 与 Codex，同一族模型既产又验。它的分数稳定性、对「Slop」这类自定义指标的操纵空间，是判断这套评审面能不能替代人读 diff 的关键，目前无公开数据。
