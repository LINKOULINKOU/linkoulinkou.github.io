这一期的主线是「把验证插进流程」：Claude Ship 让 agent 自己评审、修 PR，并按团队写的策略决定哪些能自己批；Hugging Face 的指南用 Terminal-Bench 与 SWE-bench Verified 的返工数据说明基准本身也在出错；Greptile 实测七代模型后得出「怎么看屏幕取决于模型」。模型侧则是 GLM-5.4 用循环层把 750B 撑到 2T–3T 的水平。

## 本期值得了解

### 1. GLM-5.4：28 层跑两遍，750B 达到 2T–3T 水平

Z.ai 11-23 的博客给出架构：GLM-5.4 把 GLM-5 基座的 28 层权重共享地跑两轮，隐藏状态在两轮间被细化，不加参数就把网络做深。为在 750B 规模上控成本，门控渐进更新防止跨轮激活范数爆炸，混合 KV 缓存让多跑一轮只多一份滑动窗口，稀疏注意力索引复用让第二轮零额外开销。30B 等参数对照里只多约 10% 训练算力就更优，推理 200 tok/s（对照 70–80）；官方承认有「马拉松式思考」的超长循环。API 与开放权重均未发布。

来源：[Toward Generalized Coding with Our First Loop Transformer](https://z.ai/blog/glm-5.4)｜Z.ai｜2026-11-23；[HN 讨论](https://news.ycombinator.com/item?id=50605103)（1,069 分）

### 2. Claude Ship：agent 评审、修 PR，再按策略自己批

Anthropic 11-23 开测 Claude Ship：正式可用的 Code Review 做多视角审查与对抗式复核；beta 的 PR Steward 专治 CI 失败、合并冲突与评审意见，但被设计成不得批准或合并，开发者可 `@claude stop`；beta 的 Claude Approvals 读仓库里的策略文件，例行改动自己批、特定情形要求人工签核，可先用 observe-only 模式跑一段再接分支保护。开发者入口是 `/ship`。官方称团队合并 PR 翻倍、回滚比例降四成以上。

来源：[Introducing Claude Ship](https://claude.com/resources/articles/introducing-claude-ship)｜Anthropic｜2026-11-23；[HN 讨论](https://news.ycombinator.com/item?id=50618513)（27 分）

### 3. 基准自己在出错：89 个任务返工 28 个，SWE-bench Verified 六成有问题

Hugging Face 11-23 的评测指南给了几组返工数据：Terminal-Bench 2.1 在用户报告后修了 89 个任务里的 28 个，其中一个提示写 PostgreSQL、测试却期望 Spark SQL；CritPt 不公开参考解，物理学家只能自己先解题，审的 56 道里 21 道有错；OpenAI 审计 SWE-bench Verified 发现 138 道题里 59.4% 有实质问题，7 月还估计 SWE-bench Pro 约三成任务有问题并撤回推荐。文中引用的一项综述称，任务或奖励设计的缺陷可让分数相对偏移最多 100%。

来源：[How to build and maintain an agentic evaluation](https://huggingface.co/blog/agentic-evals)｜Hugging Face（Avijit Ghosh、Ben Burtenshaw、Irene Solaiman）｜2026-11-23

### 4. agent 该怎么「看」屏幕：取决于模型，不取决于流派

Greptile 11-19 用同一批 172 个 OSWorld 任务测了七代模型的三种观察方式。对三个最强模型，加不加无障碍树、按不按元素 ID 点击都没有差别；四个较弱模型靠树与 ID 点击提升 9 到 37 分，三个翻倍以上。但树有盲区：Figma 的画布、Doom 这类游戏完全没有树，文字溢出这类 bug 只在画面上可见。所以他们的 TREX 同时用两者，能用 ID 就用 ID，画布与游戏退回坐标，并每出一个新模型就重跑这套实验。

来源：[How should an LLM see a computer?](https://www.greptile.com/blog/trex-computer-use)｜Greptile｜2026-11-19

### 5. Shirudo：不打补丁也能先挡住漏洞

OpenAI 与 Cisco 11-23 开源 Shirudo：一个跑在 Linux 上的 eBPF 运行时，让运维不等补丁、不重启，先临时拦住触发漏洞的那一个操作，同时放行合法请求。受控测试里，一套由 Codex 生成的 shield 挡住了针对运行中 Elasticsearch 的 Java4Shell 攻击尝试。它解决的矛盾很具体：补丁要几天到几周，而漏洞利用与正常请求可能走同一个系统调用，整段封掉会把服务打死。

来源：[OpenAI and Cisco introduce Shirudo](https://openai.com/index/introducing-shirudo)｜OpenAI｜2026-11-23
