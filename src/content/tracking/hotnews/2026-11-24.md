## 本期值得了解

### 1. Claude Ship：把修 PR 和批 PR 分成两件事

Anthropic 11-23 开测 Claude Ship，核心是把修 PR 和批 PR 拆开。Code Review 读完整改动、给出问题清单并分级，已正式可用；PR Steward 拿这份清单和 CI 报错去改代码，被限定为不能批准也不能合并，每次推送后说明改了什么、怎么撤回；Claude Approvals 再看另一层：仓库里有一份人写的策略文件，它据此判断某次改动可以按规则放行，还是要人来签。团队可以先开观察模式，看它会怎么判，再决定是否把自动批准接入分支保护。PR Steward 和 Claude Approvals 仍在测试阶段，开发者入口是 Claude Code 的 `/ship`。

来源：[Introducing Claude Ship](https://claude.com/resources/articles/introducing-claude-ship)｜Anthropic｜2026-11-23

### 2. GLM-5.4：同一组层算两遍，换更深的处理

Z.ai 公布了 750B 模型 GLM-5.4 的做法：用同一组 28 层先算一遍，再拿第一遍的结果算第二遍。第二遍沿用同一组参数，但处理的是更新后的信息，不是把原输入重算一次。Z.ai 让两遍之间的信息逐步更新，避免第二遍把中间数值放大到后续层难以处理。再算一遍需要额外计算，但有些工作不用重做：第二遍只为附近的内容额外保留缓存，查找较早的内容时沿用第一遍选中的位置。Z.ai 在 30B 规模上比较了循环版和不循环的同参数量模型，称循环版多用约一成训练算力、结果更好；这个对照说明的是小模型上的取舍，不是 750B 旗舰的性能测试。

来源：[Toward Generalized Coding with Our First Loop Transformer](https://z.ai/blog/glm-5.4)｜Z.ai｜2026-11-23

### 3. 榜单该怎么读：任务和判据本身会出错

Hugging Face 的新指南指出，agent 评测的通过率不只取决于模型，也取决于题目怎么出、测试怎么判。做代码任务时，模型要按题目要求改动代码，完成后再由评测系统运行预先写好的测试。题目和测试采用不同要求时，按题目做对也可能拿不到分；测试没有覆盖关键要求时，没完成任务的改动也可能过关。这两种错都会记进通过率，最后看起来却都像模型自己的表现。作者建议公开足够让外部读者检查的任务和测试，并记录每次修订。拿榜单做选型时，先看测的是不是自己要交给 agent 的工作，再看不同模型是否在同一版本的任务和测试上比较。

来源：[How to build and maintain an agentic evaluation](https://huggingface.co/blog/agentic-evals)｜Hugging Face｜2026-11-23

### 4. 桌面 agent：控件清单提高了部分模型的操作得分

Greptile 在同一批 172 个 OSWorld 任务上比较了七个模型的三种屏幕操作方式。它不仅测试只看截图，也测试加上控件文字清单后按坐标点击，以及直接用清单里的编号操作。给出清单并允许按编号操作后，四个得分较低的模型提高了 9 到 37 分，表现最好的三个基本没变。只给截图时，模型得先从画面里找目标、再报坐标；按编号操作可以跳过坐标这一步。但清单也代替不了截图，因为有些屏幕内容没有对应的控件。Greptile 的工具因此同时保留截图和控件清单。换模型时，他们用同一批任务重测，再判断控件清单是否仍能带来收益。

来源：[How should an LLM see a computer?](https://www.greptile.com/blog/trex-computer-use)｜Greptile｜2026-11-19
