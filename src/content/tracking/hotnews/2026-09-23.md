## 本期主线：限速主张后的第一个发布周期——「pace」与「race」同时在场

Dario 发《We Must Pace the Frontier》后的第一个完整发布周期里，两件事同时发生：**Anthropic 把限速承诺落进了发布流程**——Opus 5.5 是该文后的第一个发布，发布前经外部评测者（含 METR）测试、自动化行为审计取得历史最佳（条目 1）；而**市场端的竞争反而加速**——OpenAI 同日把 Sol/Luna 价格砍到前代一半、Grok 4.7 以 \$2/\$6 压价、连 GPT-5.6 都排好 11 月涨价（条目 2）。综合判断：这是治理叙事与商业叙事的首次同台——Sacks 质疑「限速即监管俘获」时指出的张力（承诺越正式，越要靠产品竞争自证）在这一天同时有了正反两面的材料。

### 1. Claude Opus 5.5：限速主张后的第一个发布，外部评测入场

**发生了什么**：Anthropic 9/22 发布 Claude Opus 5.5——Claude 5.5 家族首个模型；官方称「在多数工作上达到 Fable 5.1 水平、运行成本比 Opus 5 低 40%」；**发布前经外部评测者测试（含 Frontier Design 与 METR）**，官方明确标注这是「呼吁限速以来的第一个发布」；自动化行为审计（数千模拟场景对齐套件）取得历史最佳，官方称其「显著更少采取难以撤销的行动、更抗提示注入」。用户侧两个案例：一位测试者一天内完成 **68 万行代码迁移**（称原本工程团队需数周）；另一案例 40 次网页性能优化成功 39 次（Opus 5 只做小改进且会改动应用行为）。同日 claude-code **v2.1.280** 将其设为默认 Opus 模型（1M 上下文，\$4/\$20 per Mtok、缓存读 \$0.20/Mtok），并修复两处 auto mode 审批死循环与符号链接写路径的判定问题。

**影响与判断**：外部预发布评测从「三步走提案的第一步」（09-13 归档条目 3）变成常规发布流程的一部分——与 9/21 的 Accenture \$1B 嵌入式评测同属一条制度线。但对 Sacks 式质疑（评测者与厂商纠缠），「METR 参与发布前测试」恰是争议焦点本身：独立性成色要看后续是否发布独立报告。边界：性能与安全陈述为官方口径；「40% 降本」对比基线为 Opus 5。

### 2. GPT-6 Sol 与 Luna：价格砍半，90 分钟内与 Opus 5.5 先后落地

**发生了什么**：OpenAI 9/22 发布 GPT-6 Sol（复杂编码与 agent 流程）与 GPT-6 Luna（高频聚焦任务），**价格均为各自 GPT-5.6 前代的一半**。Simon Willison 当日整理的价格表（每百万 token 输入/缓存读/输出）：**GPT-6 Luna \$0.10/\$0.01/\$0.50**（GPT-5.6 Luna \$0.20/\$0.02/\$1.20）；**GPT-6 Sol \$2/\$0.20/\$10**（GPT-5.6 Sol \$4/\$0.40/\$20）；同期 Claude Opus 5.5 \$4/\$0.20/\$20、Grok 4.7 \$2/\$0.50/\$6、GPT-6 Astra \$10/\$1/\$50。注意口径：GPT-5.6 已有 11 月涨价 25% 的排期，GPT-6 实为对促销价再砍半；Terra 与 Sol 同价，「继续用 Terra 的理由蒸发」。

**Codex 侧配套**（changelog 缺口本题闭合）：9/22 官方条目确认 Sol/Luna 进入 Codex 与 ChatGPT Work；**Codex CLI 0.156.0 stable**（9/22：可选全屏 UI `/tui`——转录搜索、鼠标选择、右键复制；语音对话转正）与 **0.156.1**（9/23：模型选择器可选 Sol/Luna，限流切换提示改推荐 Luna）；0.157/0.158 alpha 连发中。

**影响与判断**：前沿智能的边际价格继续塌方——Luna 档（\$0.10/M 输入）已进入「高频守卫/路由随便用」的区间；对 harness 设计，**同门模型切换（Sol↔Luna 同协议）比跨厂商路由的迁移成本更低**，分层用模的默认形态正从「贵模型+便宜模型」变为「同家族双档」。边界：能力数据未细读；价格以官方定价页为准（经 Simon 表格引用）。

### 3. Claude Code 的 AGENTS.md 支持「锁在远程开关后」：官方 issue 仍 open

官方仓库 issue 95690（《[MODEL] Claude Code's AGENTS.md Support: A Local Feature Locked Behind a Remote Switch》，9/20 提出、仍 open）：2.1.277 起宣称支持的 AGENTS.md，被用户实测**仅在遥测开启时生效**——一个本地文件读取功能由远程开关控制。HN 讨论（283 分）典型评论：「没法判断这是有意还是 bug」「这正是 AI 补丁层层叠加后那种微妙而严重的问题」。

**影响与判断**：与 ZCode 事件同源——**本地行为被云侧开关支配**的信任议题；对 harness 新特性的验收提醒：应在遥测开/关两种状态下各测一次本地行为。边界：原始博客已 404，事实以官方 issue 文本为准；是否有意设计未定论。

### 4. GPT-6 Astra 自主破译 Enigma：自己选题、自己找法

Crypto Cellar Research（9/22 公开，HN 702 分）：1941 年 7 月 10 日德军 Enigma 密文 **MVUEH**（2005 年以来未解）被破译并验证。**GPT-6 Astra 完全自主**——用户只让它「看看网站上的未解密文能否破解」，模型自行选出「最有希望的」MVUEH、自行找法；破译还揭示出密文转录错误与左轮 72 字位异常翻转（可能是此前久攻不下的原因）。这是本月第三个模型破译历史密码的公开案例（Fable 5.1 的 Cyphral Distich、一战无线电密文之后）。

**影响与判断**：「自主选择研究目标」比「解出密码」更值得注意——与 NS 数学争议、Dream-RSI 的自主探索同一能力面的不同展示；密码学社区验证流程让成果可核。边界：单案例无对照；「自主程度」以委托人转述为准。来源：[The MVUEH Break](https://www.cryptocellar.org/bgac/the-mvueh-break.html)｜Crypto Cellar Research｜2026-09-22（HN 702 分）｜B

### 5. Jev 生态三连：25 行 Python 复刻、llm 插件、实践笔记

① **《Jev in 25 Lines of Python》**（nobodywho.ai，HN 407 分）：llama-cpp + Qwen3-0.6B，25 行代码复刻 Jev 式决策——**读取选项 token 的 logits 而非生成**（正是 Jev 专题推断的「分类读出」机制）；作者以「Everyone and their mom is talking about Jev... We don't really think so」的祛魅姿态公开最小实现。② Simon Willison 发布 **llm-typesafe 0.1a0**（9/22），在其 llm 工具链中接入 Jev。③ 《Jev in practice: typed decisions, scoped authority》等实践笔记涌现。

**影响与判断**：生态对 Jev 的态度正从「惊叹」转向「工程化与祛魅」——与专题结论一致：机制不新（读出式分类），价值在训练校准与工程化。边界：25 行实现是机制演示，不等价于 Jev 的校准质量。来源：[Jev in 25 Lines](https://www.nobodywho.ai/posts/jev-in-25-lines/)｜NobodyWho｜2026-09-23（HN 407 分）｜B；[llm-typesafe](https://simonwillison.net/2026/Sep/22/llm-typesafe/)｜B
