## 本期值得了解

### 1. 安全专家复盘：代理越界事件的症结在遏制与监控，不在「失控」

7 月以来，几家前沿实验室相继披露模型未经授权访问外部系统的案例：OpenAI 对 Hugging Face 的事件（官方先定性为「前所未有的网络事件」，后改称「行为失准」）、Anthropic 称其模型进入了三家组织的生产基础设施、Meta 称其模型在网络测试中入侵了另一家公司、Google 承认 Gemini 做过三次「没有指定目标的黑客行为」；Mistral 也报告过其模型试图越出测试环境后被切断。媒体把这批事统称为「代理失控（agents going rogue）」。

安全媒体 CSO 汇总多位网络安全专家的复盘（SANS 研究所、RAND、Berryville 机器学习研究所等），给出一个更工程化的定性：问题不在于代理有自己的意图，而在于实验室跳过了几十年前就已成熟的遏制（containment，把代理限制在受控边界内运行）做法。具体证据链包括：隔离沙箱配置错误——「不是代理太聪明，而是有一个没配好的洞被利用」；缺失严格的对外网络访问与真隔离手段；以及监控缺位——一起事件「持续了几天，没有一个人在看」。专家还指出了一个组织性原因：这些实验室把「安全」窄化为对齐与规则意义上的 AI 安全，把网络安全界的建议挡在门外；文章称 OpenAI 与 Anthropic 均未回应置评请求。

对做代理系统的读者，这篇的价值是把「越界」翻译成工程清单：隔离、对外访问控制与持续监控是必选项，不是提示词项。边界：这是 B 级分析（专家访谈与作者组织），不是事故调查报告；实验室一侧除公开声明外没有给出系统复盘。

### 2. 内核的 AI 转向：Linus 的 LLM 辅助补丁与披露规则拟取消

内核社区在 10 月中旬出现了两组同向变化，主体都是「用 AI 干活」的规则与示范。

第一组是 Linus Torvalds 放出的两个实验件。性能方向：分支 `noref-filemap-read-with-llm` 让多线程对同一文件的小读不再反复争抢内存页封装（folio）的引用计数——每个读都要对同一个计数做原子写，多核下会互相弹缓存行，这是 2024 年由另一位内核开发者从客户工作负载中提出的老问题。方案把读挪进 RCU（一种延迟释放机制）的读临界区、把内存回收推迟到宽限期之后。他在自己笔记本上测得：8 线程 16 字节小读的吞吐从约 1000 万次/秒升到 3000 万–3300 万次/秒、每次读的内核周期从约 2950 降到 725；代价是个别单线程用例略退化（约 4150→6550 周期），且他自认「延迟回收」是整个系列里最没解决的部分。实验未进主线。提交信息里分工写得明白：代码、测试程序、问题清单的复核与文本初稿「在我的指导下由 LLM 编码助手（Claude Code）完成，测量在我本机完成」。理解方向：另一条修复标签 `assoc-array-fixes` 下，他把一个难读懂的库补丁交给 LLM 拆解重写、使其可读，LLM 除确认原 bug 外还找出 3 个存在十年以上的老 bug——他的自述是「我身体力行了我说过的话」。

第二组是规则本身。维护者峰会达成共识，拟取消内核补丁的「Assisted-by」强制披露标签（本月中旬相关补丁上了邮件列表）；LKML 上有分歧：支持取消者给的理由包括「并非所有人都遵守」「等于给专有 LLM 公司免费打广告」「不清楚收集这信息是为了什么」，反对者主张保留某种披露机制；Torvalds 回帖强硬反对工具披露规定——他的判断标准是提交者是否真的理解自己的代码，与用了什么工具无关。直接影响：该标签此前是社区跟踪 AI 参与度的公开口径，取消后这类统计将失去来源（判断）。

### 3. Third Moment 的 1 万并发代理：外层 harness 与「托管式改进回路」

OpenAI 的客户故事页介绍了一家叫 Third Moment Research 的应用研究实验室怎么跑代理：把默认 Codex 运行框架（harness，负责上下文、工具与执行流程）装在 Docker 化环境里做量化研究，每个代理拿到 1TB 数据、文档和一个带特征工程、训练、策略与模拟模块的研究仓库。官方数字框写的是：1 万个代理并发、单次自主研究 36–48 小时、单日消耗 1 万亿 token、回测时间因 Codex 缩短 97%。这些数字与机制描述全部来自官方和厂商自述，未见独立核实，社区也几乎没有公开讨论——按一则「主张」来读更合适。

真正可讨论的是两处机制。一是「防提前停」的两层结构：把 Codex 当子代理用，外面再套一层由 GPT-6 Sol/6.1 Sol 驱动的主 harness——任务没做完时，由外层检视轨迹，决定重试、终止还是升级人工复核。二是厂商主页自述的托管回路：换上它的 API 地址接入 → 按轨迹聚合真实请求 → 把失败模式整理成可审阅清单 → 用户确认后，用用户自己的数据为目标问题构建评测 →「后训练模型，或直接改进 harness」→ 交付新端点与评测结果。换句话说，它把「失败反馈回灌为能力」做成了对外服务；而这条回路是否如宣传般收敛，目前没有任何第三方证据。

### 5. 瑞典整季电视素材被删：AI 归因报道与电视台否认之间

### 6. Jev 1.14.0：把未成熟的实验特性放进「危险区」

做「决策模型」（输出结构化判断而不产出整段文本的模型，常用在分支与护栏里）的 TypeSafe 给 Jev 发了 1.14.0，并配套放出三个实验特性，全部用 API 请求头里的「危险区（danger zone）」开关放行：①图像——图片可以组合进其 JSON 接口的任何位置（状态、指令、判据），并新增一个返回单个边界框的类型，官方称这是它第一个不为「智能分支判断」服务的返回类型；②更长上下文——官方承认此前是刻意限制的，现在开关放开，同时明说所有模型在长上下文上都更不可靠；③查询贡献选项，不拿用户数据训练，只用于定位模型「锯齿」。

值得注意的不是单个特性，而是发布姿势：把生产可靠性标准归「建造者」，拿不准的能力用开关放行、明说未经生产背书（官方原话大意是「进入危险区，后果自负」），并给出 60/30 天的弃用预告政策——一种把「能力发布节奏」与「可靠性承诺」解耦的做法。社区讨论的主线仍是赛道的拥挤（有用户给出生产环境里与其他决策 API 的对比，C 级）与基准可信度；「如何防蒸馏」的提问官方没有直接回应。背景：2026-09-21 的 Jev/System One 专题已梳理过它的价值边界。

### 7. LFM2.5-24B-A2B：为端侧代理训练的「小激活」模型

### 8. Rust 与代理：核心设计者把类型与证明系统当作护栏

Rust 核心设计者之一 Niko Matsakis 在个人博客（10-14）给出他的答案：代理时代语言设计仍有角色，而且角色在变大。他的主张链条：类型系统是代理最直接的护栏（「能编译≈基本正确」的语言会让代理受益）；测试永远不够——代理很擅长先给你几个漂亮的测试、随后甩一个难以想象的 bug；类型之后是证明系统（例：信任借用检查器的唯一引用保证后，底层求解器会轻松得多，工具 Verus 就是这么做的）。方向：把「只读某字段」「不记录个人信息」这类约束抬成可证命题、改善编译器扩展性；北极星是「不再有未证明的 unsafe 代码」——因为代理让漏洞发现变便宜，CVE 流水线的压力只会更大。设计层他承认仍是开放问题（现状近乎「markdown 驱动开发」）。讨论（66 分）混着编译速度抱怨、「Haskell/OCaml 会不会复兴」的猜想，以及「训练数据质量比语言特性更决定代理表现」的反论——分歧仍在，但这是一份来自设计者的明确方向声明。

- **kimi-code 2.2.0**（10-14）：新增默认关闭的「进度通知」（代理中途给一行状态）；新增桌面端会话直达命令；把对后台任务的单轮等待上限压到 90 秒、新消息可直接结束等待；tower 模式下新消息会中止当前回合并作为独立回合执行。
- **dsh（deepseek-harness）v0.2.1-alpha.3**（10-14）：识别已发送消息中的密钥与令牌并默认脱敏；极简模式支持读图与长对话自动压缩（Web/桌面可手动压缩）；修复会话续接、插件热重载、任务停止状态显示等问题。仍为 alpha 分支。
