这一期有两条把「省」做成了机制：一个 27B 开放模型不靠梯度、只跑前向就把自己的权重改好，6.6 个点写进权重、不用每次推理再付；另一份 718 家公司的论文说，agent 让代码量多了三成，但完工量没涨、评审时间多拖了 49%。另有一条 harness 的价值判断、一个把窗口管理器塞进浏览器的 IDE，以及欧洲法律做成 MCP。

## 本期值得了解

### 1. 模型改写自己的权重：不靠梯度，只跑前向，提升写进权重

11-16 的论文提出「自我改写」（self-rewriting）：给一个开放 27B 模型它自己的权重、被评分的答案和运行自己的能力，它诊断失败、改写对应权重，在没见过的题上提升 6.6 个百分点，且连续八轮只升不降——每轮先在练习题上验证，只提交有效的改动。它还能修复一个被损坏的自身副本：那份副本几乎什么都解不出，模型不重训、也不读原始权重，就把它拉回原模型 80% 以上的图像任务准确率。作者称这种能力随规模出现：同一家族里小模型改不动甚至改坏自己，只有最大的能提升并自修。与 test-time scaling 的区别是收益写进权重、每次作答不再付费；与训练的区别是只跑前向。论文是 v2，尚未见同行评审。

来源：[Language Models Can Rewrite Their Own Weights](https://arxiv.org/abs/2611.21885)｜Jiajun Fan 等｜2026-11-16（v2 11-18）；[HN 讨论](https://news.ycombinator.com/item?id=50577265)（491 分）

### 2. 718 家公司的数据：代码多了三成，评审慢了近一半

一份哈佛博士生的求职论文（未见同行评审）追踪 718 家公司、725,938 名工程师：采用 AI 编码 agent 后，代码产出增加约 30%，但完工量没有可测的提升，代码通过评审的时间延长 49%——瓶颈从写代码挪到了人这一道关卡。这条值得和本周另两篇并读：Claude Code 团队说验证回路让他们能同时跑几十上百个 agent，而 Anthropic 工程文里那套 chaos loop 的核心也是「把判据变成可自动跑的东西」。三者指向同一个约束：产出速度上去后，能自动判定对错的能力才是吞吐上限。

来源：[Harvard researchers find AI coding agents shifted the bottleneck to code review](https://complexdiscovery.com/harvard-researchers-find-ai-coding-agents-shifted-the-bottleneck-to-code-review/)｜ComplexDiscovery（转述工作论文）｜2026-10-13 发布，本周 HN 讨论 331 分；原论文未直接读取

### 3. DreamCoder：把窗口管理器搬进浏览器的 coding harness

写了《Mastering Emacs》的作者花 15 个月做了 DreamCoder：一个跑在浏览器里、三平台通用的 coding harness，核心是平铺窗口管理器。每个 pane 有最小、舒适、最大三档尺寸，用约束求解器在「我要开新终端」和「别把已有窗口挤成一条缝」之间平衡，塞不下就推到隐藏窗口栏（仍是实时画面）。它把「用 tmux 开十个 claude 轮流看哪个卡住」这件事做成产品能力：workspace 像虚拟桌面，右上角 minimap 按 pane 脉冲显示在干活还是被阻塞，空闲变绿。快捷键是 Emacs 风格（`Alt+x` 全局、`Alt+c` 局部、`Alt+m` 后按编号或 WASD 跳转）。默认支持 Qwen、Gemma、DeepSeek、GLM 等开放权重模型，作者特意提到 Qwen 3.8 27B 在本地的表现。

来源：[Announcing DreamCoder](https://www.masteringemacs.org/article/announcing-dreamcoder)｜Mickey Petersen｜2026-11；[HN 讨论](https://news.ycombinator.com/item?id=50581110)（285 分）

### 4. 量化编译器：同样体积，KL 低 12 倍

一个 MIT 许可的量化编译器 LookAtMyQuant 换了优化顺序：先测「每一块权重被压缩时对输出的伤害有多大」，再在文件体积预算内为每块挑编码，而不是全模型用同一套量化位宽。结果按模型分档给出——Gemma 4 E2B 同体积 KL 比 Q4_K_M 低 12 倍；Qwen3.8-27B 从 53.7 GB 压到 7.2 GB（2.1 bit/权重），540 道数学题解出 401 道与原始持平，HumanEval 73.8%、MMLU 78.8%、GSM8K 94.5% 均高于同尺寸的 UD-IQ2_XXS；Inkling 2 Mini 被压成 3.85 GB 到 12.76 GB 六个档位。配方是训练后量化加 trellis 码、按 Fisher 信息逐行分配位数、再用约 4,000 步蒸馏复量化，作者称一次约 34 美元 GPU 时间。

来源：[lookatmyquant](https://github.com/ShinMegamiBoson/lookatmyquant)｜ShinMegamiBoson｜2026-11；[HN 讨论](https://news.ycombinator.com/item?id=50591853)（582 分）

### 5. 欧洲法律做成一个 MCP：2.8M 份官方文件、按时间点查询

Pandex 11-22 上线：把欧盟与七个欧洲国家的立法与最高法院判决做成一套 API 加一个 MCP server，覆盖 2.8M 份官方文件、37M 条引用连回原文，41 家机构中 33 家标注为完整收录。对 agent 有用的三点是：跨语言语义检索（英文提问命中法文判决）、按时间点取法（每条条文带历史版本与生效日期）、以及可核验的覆盖清单——它明说自己收了什么、没收到什么。这类「把领域语料做成带引用与版本的工具」正是 agent 落地时最缺的一层。

来源：[Pandex: Europe's law, in one API](https://www.pandex.io)｜Pandex｜2026-11-22；[HN 讨论](https://news.ycombinator.com/item?id=50593481)（139 分）

### 6. 把 P vs NP 做成公开的 agent 流水线

一个叫 pequalnp.com 的站点把「证明 P≠NP」拆成可认领的开放步骤：把一条提示贴进 Claude Code、Cursor、Codex 或 Gemini CLI，agent 领一道题、用 Lean 写证明，所有结果过同一个检查器；站点实时展示已检查的引理、被推翻的断言、被判死的路线，并明确写着「权重不是概率，两边都不是证明」。目前没有赞助、也未公布任何已检查结果。它的价值不在数学进展，而在形态：把长期开放问题做成有认领、有检查器、有公开台账的流水线，且不把 agent 的自我陈述当作证据。

来源：[Agent swarm trying to solve P vs. NP](https://pequalnp.com/)｜2026-11-23；[HN 讨论](https://news.ycombinator.com/item?id=50604314)（114 分）
