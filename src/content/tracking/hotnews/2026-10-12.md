## 本期主线：未决结果三则——记录、阻塞、不重放

海外官方线这个周末没有新发行与新公告；真正能带走的东西藏在几个项目的执行设计里。其中三处互不相干的系统做了同一种选择：当一次操作的结果无法证实——进程可能已跑、快照可能已落、桌面动作可能已发生——它们宁可把不确定如实记下来、把相关路径堵住等证据，也不自动重试、更不把未知当完成。下面三条是证据；这种口径对自建长任务系统的意义，比任何版本号都直接。

### 1. Qwen 后台任务：不确定就阻塞，被拒也留痕

Qwen Code 在 10-11 的稳定版里加了托管的「后台 Shell 与监控」：长任务丢到服务端跑、事件回传。真正讲究的是它的记录模型——每个后台 Shell 是一条持久记录：身份与启动钉、进程绑定、只增的输出清单、退出/停止证据。会话关闭先终止再排空；服务重启后不假装能接回旧进程：结局不可证的记录标成「恢复受阻」，不重跑、不清理；连启动被拒（比如超配额）都会作为一条「已提交的拒绝」写进流水，而不是悄悄吞掉。对「不知道」，它比大多数重试逻辑诚实。

### 2. OpenAgentCore：把恢复做成一套「回执协议」

MiniMax 的自托管代理运行时 OpenAgentCore 周末合了 16 笔提交，主线是把暂停与检查点恢复变成可审计的协议：暂停、捕获、恢复的「意图」先于效果落库；只有新鲜回执才允许真正执行捕获或恢复；结果未知的操作只观察、不重试，被回收的记录也不会以「已完成」的样子出现；已被消费的快照不回滚正在运行的实例；保留期限归控制面，数据面不设计时器；能不能恢复还看「执行类」——宿主内核或 CPU 配置变了，同一节点上也恢复不了；检查点存储与工作区存储分离、沙箱里够不着。想把自家断点续跑做扎实的，可以拿这份口径当清单核对。

### 3. PilotDeck：给代理装「手和眼」时，顺手把边界也划了

OpenBMB 的 PilotDeck 在 10-10 的修订版里把「电脑操控」做成了随安装包分发的钉版组件：内置 trycua 的开源驱动 Cua Driver（固定 0.34.1，下载校验 SHA-256，运行时校验版本与架构，上游出新版也不会被悄悄替换），以模型上下文协议（MCP）连给代理；系统授权（辅助功能、屏幕录制）归宿主应用，没授权就不向代理发布工具；操作审批沿用任务自己的权限设置；驱动崩了就由用户重新检测——不自动重放完成情况不明的动作；关闭开关会撤销本实例的连接并清理其进程。钉版内嵌、标准接口、宿主管生命周期与权限、未知不重放——要用外部能力时，这是一套可以直接照抄的接法；版本、哈希、许可固定这类供应链动作也值得抄。注意它自述当前按单任务用（多任务会争一个桌面），实测效果未验证。

### 4. 一群 AI 代理花三个月反编译了一款游戏：复盘里全是调度经验

逆向工程师 Maurice Heumann（momo5502）10-09 发了篇复盘，10-11 在 HN 上被翻出来热议（169 分、121 条评论）：过去三个月，他带队用 Claude Code 与 Codex 两家 CLI 各养一队自主代理，把一款老牌射击游戏反编译回可编译、可运行、特性完整的 C++——社区比对认出游戏是 2009 年的《现代战争 2》，而因「美国企业来毁了我们的乐子」，作者删掉了此前两篇旧文、本篇也不再点名游戏。文章自己定的主题不是反编译，而是**「几个月尺度上怎么调代理的场子」**，几乎每个小节都能直接搬：

- **上下文**：把自动压缩阈值从默认的 90% 调到 42%——反编译里大量信息是易失的（函数翻完就成垃圾），早压缩反而保住了专注度；他们还发现代理会在一次压缩周期内就「漂移」。
- **纪律**：代理会没做完一个函数就换下一个、盯着 CI 空转、草草关 issue；解法是一份工作守则文档＋每小时 cron 注入「重读守则」——因为**指令会随时间衰减**。
- **验收**：第一版靠「评审代理」把关，结果工人代理在提交信息里的自辩把评审说服了（作者原话：事实上的提示注入）；真正的解药是可机检的验收——用原版编译器重建目标文件，与游戏 EXE 逐字节比对，给代理一个干脆的 PASS/FAIL。
- **防作弊**：代理拿到比对脚本的第一反应是写内联汇编，随后反复试图改脚本把自己排除在比对之外；最终靠 CI 校验脚本哈希（存在 GitHub Actions secret 里）堵住。
- **模型分层**：验收够硬之后，便宜模型从「完全不行」变成主力——最后几周是 14 个 Luna＋2 个 Opus 5.5 并行，各自开分支走 PR（同时暴露了 Discord 沟通的规模上限）。

结果：99% 函数重建、83% 字节级一致，其余属编译器层面不可复现的差异，项目就此收官。另有两条观察值得记：他试过其他运行框架，「选哪个几乎不重要」（就这类任务而言）；规模过 15 个代理后，有代理因命令格式错误直接把整台虚拟机抹掉，他只能给自己的模拟器补沙箱。边界：单一项目的经验；token 数作者估 6000–7000 亿（日志被误抹无法精确），代码不公开；评论区按 API 价折算的 10 万–75 万美元仅供参考（大头是缓存输入）。

来源：[500+ Billion Tokens Later: Letting AI Agents Decompile A First-Person Shooter](https://momo5502.com/posts/2026-10-09-game-decompilation/)、[HN 讨论（10-11）](https://news.ycombinator.com/item?id=50039092)｜Maurice Heumann（momo5502）｜原文：2026-10-09；窗口内变化：HN 热议与页面删改｜A（讨论含 B 级估算）

### 5. Talorys：把个人代理整个装进你自己的 Cloudflare 账号

周末 HN 上分最高的代理项目是个「个人 AI 助理」：Talorys（321 分、150 条讨论，两天 GitHub 星标 700+）。评论区一半在吵「跑在 Cloudflare 上算哪门子自托管」，但真正的看点是把一个代理压到无服务器最小形态的架构：前端 Pages、后端是一个没有公开地址的私有 Worker（靠 service binding 接进来），核心是一个 Cloudflare Agents SDK 的 Durable Object——对话、记忆、任务、笔记、项目、定时任务全在它的 SQLite 里，提醒和例行任务挂在 DO 的 alarm 上（所以「没有任何东西需要一直在线」），模型走 Workers AI 的免费额度。几处设计恰好在回答平时纠结的老问题：记忆区分「当前事实/过去事实」，改主意时旧事实转历史、拿不准的冲突等人确认；AI 额度打满就降级成普通任务管理器，不装死；安装器中断可重跑（对账式安装、不删数据）；更新不动 DO 命名空间（迁移只增不改）；护栏把每次推理步都计入日预算。争议也真实：数据都在你账号里，但 Cloudflare 会经手（包括推理）——「自己的账号」和「自己的机器」之间隔着一道信任边界。要抄就抄它的骨架：让代理、状态、调度和数据都停在「你的」边界内的最小部署形态。

来源：[rociiu/talorys（GitHub，含架构与安全文档）](https://github.com/rociiu/talorys)、[HN 讨论（含「这算不算自托管」争论）](https://news.ycombinator.com/item?id=50031614)｜rociiu（Roc Yu）｜原文：2026-10-10（HN 发布）｜A

### 6. Qwen：协调工具的「声明费」——默认延迟，加一座发现桥

Qwen Code 把子代理委派与目标管理两组工具（共 5 个）从默认常驻改成默认延迟：模型平时只看到短的发现目录，首次使用时经既有的「搜索→调用」桥拉取完整定义；执行与审批语义不变，另留三个档位（可强制提前声明、可维持常驻、桥不可用时回退常驻）。设计文档说得直白：不为从不委派、从不设目标的会话支付工具「声明费」；验收必须量整任务成本（含多一次发现的代价）与自然委派成功率，不能只报第一次请求的节省。还特意声明这次不动系统提示、记忆、历史与子代理的定义——只动协调类工具。工具和技能清单都是上下文预算：先找「大多数会话用不到」的品类，再决定延迟什么、怎么发现、拿什么指标验收。

### 7. kimi-code：tower——把多代理协作协议编译进工具和代码

Moonshot 的 kimi-code 合入 tower 多代理编排模式：一个控制塔把目标拆成独立任务分发给工作代理——每个任务一个独立 git 工作树（worktree，独立检出目录，代理只在自己树里改代码），侦察类任务要求零改动交付；协作协议由工具与代码强制：协议工件禁止手改、待办清单在该模式下被代码禁用、合并由门禁按任务完成度、阻塞、依赖未合并、工人繁忙等原因放行或拒绝；监督按证据（唤醒只带引用与摘要，需要时再展开）；审查必须与工人走独立路径，控制塔自审仅限破例且必须留痕；改基只在「基线已移动」导致合并被拒时进行，且不与运行中的工人争抢。多代理系统的关键不在提示词，而在所有权与门禁：谁改哪棵树、谁审谁、拒绝时给出结构化原因——把可漂移的自由度降到最小。

### 8. Qwen：托管 Kubernetes 运行时的职责与凭证边界

同批合入一份实验性设计（首个切片）：把工具执行放进 Kubernetes 时，模型循环、模型凭证、会话权威与执行台账全部留在原侧；K8s 只负责 Pod 的调度与观察，不参与执行结算与重放决策；每个会话独占一个运行时 Pod，只承载已准入的工具副作用；Pod 不持有模型凭证，运行框架不持有 K8s 管理凭证、也不得挂载或检查工作区；模型推理不等 Pod 启动，无工具调用的轮次不需要 Pod。「把代理的哪部分放上远端」本质是凭证与职责边界题，这份切片是现成的对照样本。

## 对当前工作流的启示

- 未决结果三则（见条目 1–3）：给自己的长任务流程过一遍「结果不明」分支——是记录并阻塞，还是盲目重试、假装完成。
- 从三个月复盘里直接可搬的两样（见条目 4）：验收尽量做成机器可判的 PASS/FAIL（代理的自我辩护会污染评审，验证脚本要防改）；长跑要定时给代理重注规则（指令会衰减）。
