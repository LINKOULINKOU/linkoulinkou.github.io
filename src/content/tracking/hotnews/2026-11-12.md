今天最值得看的是两处接口变化：Google 把决策模型做成多模态 API，一次前向给上千个问题打分，输出 token 不计费；MCP 的文件传输扩展草案把大文件彻底移出模型上下文，客户端只传元数据、字节直接进目标存储。另有一条反方观点：subagent 的摘要把任务讲丢，同任务更慢更贵；以及 48 个 agent 读 lidar 找玛雅遗址的完整流程。

## 本期值得了解

### 1. 决策模型开始看视频：一次前向答 1,000 个问题，输出不计费

Google 11-11 上线 Gemini Decisions API，模型是 gemini-decision-1：一次请求可带一段多模态输入（文本、图像、音频、视频、PDF，最多 256K token）和最多 1,000 个独立问题，支持 yes/no、多选与 rubric 打分，模型直接给每个选项打分，不做逐 token 解码。官方称端到端 150–250 毫秒，16K token 以内问题数从 1 增到 100 时延迟基本不变；价格每百万输入 0.10 美元、输出不计费。它和 Jev、OpenAI 的决策模型同类，但多模态覆盖最广；Simon 用一段视频测 yes/no，得到 0.05/0.92 这类概率，而 Jev 与 OpenAI 常给 1.0/0.0。

来源：[Gemini Decisions API](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)｜Google｜2026-11-11；[Simon 实测](https://simonwillison.net/2026/Nov/11/gemini-decisions-api/)

### 2. Subagent 的摘要把任务讲丢：同任务更慢、更贵、信息更少

一位开发者 11-11 的笔记把 subagent 的老问题讲清楚了：主 agent 写几段摘要派活，摘要漏掉关键约束，subagent 却以为信息完整，认真做了一堆无用功。他引用另一组测量：137k token 的会话里，Opus 5.5 自己做 67 秒、0.38 美元，交给带摘要的 subagent 要 123 秒、0.57 美元。替代方案是 fork——把完整对话复制给子代理，Codex 与 Claude Code 都已支持，由模型自己选；fork 更贵但知道此前的纠正与否决。他还在试一种折中，让子代理在需要时回查原会话。

来源：[Subagents considered harmful?](https://nikvdp.com/notes/subagents-considered-harmful/)｜nikvdp｜2026-11-11

### 3. MCP 把大文件移出上下文：只传元数据，字节直接进对象存储

MCP 11-10 公布文件传输扩展草案 io.modelcontextprotocol/files：工具在输入 schema 里用 `x-mcp-file` 标记文件参数，客户端先只发元数据，服务端校验权限与配额后返回 `upload_required` 与上传地址，字节走 HTTPS PUT/POST 直达目标，不经过 JSON-RPC，也不进模型上下文。回调用 `requestState` 串起多轮请求，服务端可校验未被重放；下载放在结果的 `_meta` 里，客户端按 size 与 digest 校验。凭据字段分 `omit` 与 `include`，草案建议 host 对 omit 目标做来源白名单。目前没有参考实现，官方计划年底前定稿。

来源：[Exploring File Uploads and Downloads in MCP](https://blog.modelcontextprotocol.io/posts/exploring-file-uploads-and-downloads-in-mcp/)｜MCP｜2026-11-10

### 4. 48 个 agent 读 lidar 找玛雅遗址，72 小时拿到官方回复

11-11 HN 953 分：一位非考古学家让 48 个 agent 分头看约 1,200 km² 的 lidar 影像，按一份精确指南找金字塔、平台与广场，筛掉自然山丘与道路；几小时内标出一批村落，再让 agent 查文献与档案，确认其中一处大型遗址未登记，随后生成报告、译成西班牙语发给墨西哥 INAH。作者次日更正：这处遗址其实在 2025 年的一篇论文里已被测绘，agent 查文献时漏了，所以是「重新发现」。流程本身值得看：没有专用分类器，agent 就是看图，再接力做文献核对、报告与对外联络。

来源：[My AI Agents (Re)discovered a Maya Site in 72 Hours](https://pietromiotti.com/latest/maya-site)｜Pietro Miotti｜2026-11-11

### 5. AWS 把本地云模拟器做成 agent 技能

AWS 11-11 开源 aws-emulator：本地起一个 AWS API 端点，把 CLI 或 SDK 指过去，就能在没有账号的情况下跑云上代码，适合开发机与 CI；官方明确不用于生产或安全测试。对 agent 更直接的是仓库自带 aws-emulator skill：装好后让 coding agent 自己起模拟器、改环境变量、跑测试，不用把真实 AWS 凭据交给它。Werner Vogels 同日写文说，这是把「工程师当年靠测试环境积累的判断」交给 agent 的第一步。

来源：[aws-emulator](https://github.com/aws/aws-emulator)｜AWS｜2026-11-11；[Vogels 文章](https://www.allthingsdistributed.com/2026/11/aws-emulator-and-the-engineers-job-when-agents-write-the-code.html)

### 6. 0.8B 的端侧 agent 模型：单步工具调用稳，多步检索弱

Tether AI Research 11-11 发布 BotPsy：0.8B 参数，基于 Qwen3.5-0.8B，专做函数调用与 agentic 工作流，可在设备上跑。官方称它在 1.2B 以下模型中工具使用与 agent 能力最好，单步工具调用在各类 app 上都稳，多步任务增益最大，多步信息检索仍是弱项；训练分四阶段、三类反馈。定位是低到中等难度的个人助理任务，官方明确说不适合高风险场景。

来源：[BotPsy: On-Device Personal Assistant](https://huggingface.co/blog/qvac/botpsy)｜Tether AI Research｜2026-11-11

### 7. AI 生成的代码库为什么变脆：浅测试、过度复杂、错误只给用户看

一位工程师 11-07 的长文在 HN 拿到 632 分：全面用 AI 写代码后，代码库会以四种方式变脆——测试写得浅，只覆盖已有路径与 get/set；代码过度复杂，两三个 helper 能做完的事写成多层；错误只在真实用户那里出现，因为没人再为分析埋点；最终产品按 AI 的方式长出来，人和维护者被挤到边上。文章是个人观察，没有数据；它和「agent 让交付变快」的叙事并列看，能解释为什么评审与测试仍是瓶颈。

来源：[AI usage generates a fragile codebase](https://evanxmerz.com/post/ai-usage-generates-a-fragile-codebase/)｜Evan X. Merz｜2026-11-07
