### 1. ECDSA 曲线种子之谜告破：不是哈希短语，是时间戳播种的随机序列

自 2000 年 FIPS 186-2 将 NIST 的五条椭圆曲线（P-192/224/256/384/521）标准化以来，每一条曲线的「种子」（seed，用来派生曲线系数的哈希输入）从何而来一直是悬案：种子由 NSA 提供、没有解释，长期流传的说法是「某句玩笑话的哈希」（当事人之一 Jerry Solinas 2015 年的回忆也只记得大意）。Anthropic 10-16 公布的结果给出了答案——种子不是任何哈希，而是 C 标准库随机数生成器 lrand48 以 Unix 时间戳为种子、反复抽取 20 字节候选取出的第 n 个输出；P-256 的种子是第 1,842 个候选，生成时间落在 1997–98 年。发现方式：一名员工向内部研究模型提了一个不带线索的开放问题，半小时内完成。

这个结果的价值在于它能被独立检查（重放随机序列即可复现），且方向是「无后门」——它增强了对这些曲线属于随机生成的信心；文章自己也强调这不是密码学突破，没有任何需要改做的事。旁证一并到位：密码学家 Filippo Valsorda 发布三年的种子赏金，由十名 Anthropic 成员在 10-15 01:07 UTC 领取，并捐给 ISRG（Let's Encrypt 的运营方），捐额三倍化为 36,864 美元；他的独立文章与 Anthropic 的表述有两处小出入（生成器写作 drand48、时间 1997–98），核心结论一致。HN 969 分/353 评论。

### 2. 量子线路：把模型放进「提议—评分」闭环，得到超过已发表最优的设计

Anthropic 同日公开的第二项结果来自它的 STEM Fellows 项目：给 Claude Mythos 5 八条用自然语言描述的量子线路需求（来自化学、优化、物理模拟与数论），外加一个自动评估器为每份设计打分。模型自我闭环——提议设计、接收评估器的反馈与分数、据此改进下一版，基本独立完成。结果是部分设计优于已发表的最优线路，个别改进「一个数量级或更多」，直接含义是同等硬件资源下能跑更有用的算法。完整论文 10-15 已上 arXiv（Andi Gu 领衔，合作者包括 Harvard 与 QuEra 的研究者）。

两条研究放在一起看，值得比较的是验证装置：ECDSA 一例是「解出来之后任何人可复现」，量子一例则是「把评估器留在环里、每个设计当即可评分」——后者正是让模型主导研究可被信任的关键结构。HN 161 分/34 评论。

### 3. PostgreSQL 19 的延期：LLM 审查把缺陷发现得太快，维护者消化不了

PostgreSQL 19 原定 9 月下旬至 10 月上旬发布，现已推迟到 11 月 19 日前后，并有 8–10 个重要特性被撤回、推迟到 20。核心 committer、EDB 的 Peter Eisentraut 在 10-09 的博文里给出了一线解释：一部分被撤特性确实有严重的架构缺陷、来不及在 beta 期修；但还有一条长尾——大量边角用例的小缺陷，过去要花约五年陆续修完，现在 LLM 辅助审查把它们一次翻出来，「你面前是一张四十条缺陷报告的单子，平均每条只要三行修复，但每条都有固定开销，然后时间用完了」。

他的核心判断是时点错配：「有效的质量门槛在特性写完之后被抬高了」——这些特性写的时候，LLM 审查还没有现在好用。因此他预期这件事在后续开发周期会自行消退（除非审查能力继续加速），并强调与「vibe coding」无关。社区反应（HN 203 分/17 评论）大体认可「第二个审查环」的投资价值，提醒的是别把未编辑的 AI 缺陷报告直接当 issue 提交；也有评论以此前模型批量上报缺陷的低有效率先例为由保持怀疑。与上期 Claude Code 的审查体系对照：那里是组织内部自建的流水线，这里是一个开放社区被外部工具抬高了门槛——当工具的产出速度超过人类的消化速度，瓶颈会以「发布时间」的形式显形。

### 4. OpenAI 的维护账本：GPT-6 系列删掉八十多万行，Sol 以 14% 成本做到 92% 的发现量

10-14 OpenAI 开发者博客刊出一篇内部实践（Core Experimentation 团队）：把「清理死代码」与「清理陈旧实验」两类维护工作交给 Codex 的 GPT-6 系列。死代码这轮：一句含糊的 prompt（大意「找出并清理死代码，需要的话可以查 Slack、Statsig 等任何来源确认」），GPT-6 Astra 自己去看历史 PR、Slack 讨论、内部追踪器和生产性能剖析表，逐条给出删除依据；五名工程师两周内半职地跑变体，合并 1,400+ 个 PR、删掉 80 多万行。效果可量化：一个服务的容器镜像从 3.31GB 缩到 1.72GB（-48%），测试快照变体清掉约 400 个。

更硬的一节是模型成本对照：同一「陈旧实验清理」任务、同一 prompt，GPT-6 Astra Ultra 花 \$109.06 得 142 项发现（\$0.77/项）；GPT-6.1 Sol Ultra 花 \$15.12 得 131 项（\$0.12/项）——92% 的发现量、14% 的成本；Sol Medium 更低（\$5.27/86 项）。团队把两模型的差异（Sol 会漏掉「被其他旗标依赖的常量旗标」）回收成 prompt 修正，并提出一句方法论：模型换代后这些修正可能过期，prompt 要跟着重勘。文末几个可复用 prompt 里包括一个特别的用法：让模型回放一次最近的会话，A/B 对比「保留/删掉某条 AGENTS.md 指令」对质量与成本的影响。同文给出的 CI 副产物：约 30 个优化 PR 后，CI 中位时长 10→4.5 分钟，一个 63 项测试套件从 592.6 秒降到 29.8 秒（测试全保留）。

边界：效果数字均为团队自报、未独立复核；其「删除安全」依赖对 Slack、内部追踪器与性能剖析的访问，小团队未必具备。来源经 10-16 官方账号转发进入视野。

### 6. dot 的两种观察：无人提示的一天，与一个凌晨三点的值班用例

9-30 期记录过 OpenAI 常驻代理 dot 的设计（自带云电脑、主动研究默认只读、可监控暂停）。10-13 The Register 报道了安全与治理公司 Geordie 的自测：以只读权限接入、未连个人应用后，一个 dot 在没有任何后续人工提示的一天里产生了 155 段活动序列——至少 50 段挤在一个 2 分钟窗口内——消耗超过 30 万 token。dot 常驻至少两个代理（前台交互 + 后台持续采集），并会派生短命子代理（一个去盘点系统内所有代码仓库，另一个把发现持续记账），Geordie 的措辞是「用户不会知道有子代理在工作」。它观察到的差别是：个人代理比企业代理「自己给自己派活」多得多——明说这不是定时任务、也不是用户触发，是 dot 自己起的。

10-16 OpenAI 官方账号给出另一半：一名工程师凌晨三点用 dot 分诊线上事故——dot 调查问题、自动开了一个 Codex 线程，人从手机的 ChatGPT 应用里接管推进。两份材料拼出的常驻代理图景：自主性在真实环境里表现为持续的后台消耗，而它的产出价值，取决于你是否恰好把值班这类场景接上去。

### 7. 一份「基准地图」：90% 的美国工时，任务几乎没有评测覆盖

### 8. harness 值多少：能耗与可靠性两侧的两份实测

两条独立材料把「同一模型换个 harness 或配置，差多少」量化了。其一来自推理云 Neuralwatt（CEO Chad Gibson，10-16）：统计自家云上一个月流量（几乎所有流量是代理流量，编码代理典型一轮输入 10 万 token）后发现，各客户端的「未缓存输入」在 1.6%–11.1% 之间；缓存命中率 92% 对 97%，对应的预填充计算差约 2.7 倍；一次几乎未缓存的请求，能耗约为命中请求的两倍（在 GLM-5.3 上约 2.5 倍）；深会话更贵——上下文过 128k 后，一轮重读半程提示词的开销约等于该深度下 600 轮普通回合。且根因单一：实验室里每一次缓存断裂，都来自 harness 修改了自己已经发送过的前缀。

其二来自 martinfowler.com 上 Naresh Jain 的对照实验（10-13）：同一个 API 服务、同一 Codex 环境，「行为 harness」（架构约定 + 确定性测试反馈）对前沿模型与廉价模型效果相反——GPT-6 Sol 两种条件下都 10/10 通过全部 178 项验收测试，harness 反而带来 10.5 倍 token、约 3 倍时长与约 7 倍成本；GPT-6 Luna 不加 harness 10 次只成 3 次，加上后 10/10，每次运行 \$0.273，比 Sol 的 \$0.406 便宜 33%。作者原以为 harness 会普遍省 token，结果被实验推翻，他给出的结论是：harness 可能是让成本优化型模型达到前沿可靠性的实用路径。

两份材料指向同一侧面的两种用途：harness 既是能耗账本里的主要变量，也是「用小模型省钱」能否成立的前提条件。

## 值得继续追问

- 条目 1：结论任何人可用同法复现，但密码学界与标准机构的正式回应（以及对其他参数集来源的同法清理）尚未出现——值得观察它会不会成为「模型做历史性研究」的可借鉴范式。
- 条目 3：若「审查后置」是普遍效应，其他大型社区项目（内核、语言等）的发布节奏与评审分工应出现相似信号；目前只有 PostgreSQL 一例，且博主预期会自愈——需要第二例来证实或证伪。
- 条目 5：V4.1-Flash-1017 的基准披露了所用 harness（Claude Code / mini-SWE-v2），第三方 harness 下的复测——尤其与 Opus 5、GPT-5.6 Sol 的同预算对比——还缺位。
