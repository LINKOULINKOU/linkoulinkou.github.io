这一周的主线是协作与验证：Anthropic 用五张 Postgres 表和 Git 分支让 1,000 个 agent 复现费马大定理形式化，Hugging Face 证明同一个模型换个 harness 就得单独训适配器；另一边是记忆分层、决策模型级联、轻量 agent 运行时，以及 harness 自己写下的三处泄露面。

## 本期值得了解

### 1. 一千个 agent、五张 SQL 表：通用工具也能撑起长任务协作

Anthropic 11-09 的玩具实验里，1,000 个 agent（1 个 lead、999 个 helper）在无网络 VM 上用早期 Fable 5.2，28.7 小时复现了费马大定理的 Lean 形式化。协作底座只有共享 Postgres 与各自的 Git 分支：lead 开工 10 分钟建了 announce、assign、notes、subtasks、landed 五张表，把 60 条命题分给 60 个小队。27 分钟只有 3 条证完，它搁置多数 helper 判定不可行的 47 条，把人力压到剩下 10 条；最后只剩 Langlands–Tunnell，约 750 个 helper 压上去，长出一棵 2,418 个任务、10 层深的树，28.7 小时最终定理进 main。100 多万次工具调用没有触发拦截。

来源：[Safely scaling multi-agent teams with Claude Fable 5.2](https://claude.dev/blog/safely-scaling-multi-agent-teams-with-fable-5-2/)｜Anthropic｜2026-11-09

### 2. 记忆不是一个文件夹：笔记、dreaming 与 wiki 各自解决什么

Anthropic 11-06 把 agent memory 收窄为「从经验获得、跨会话保留、以可读上下文存放的知识」，拆成四层：会话笔记、后台回看 transcript 并纠错的 dreaming、每会话预加载的注入层、把知识连成地图的 wiki。CL-Bench 1.0 的数据库任务只给一个持久目录：Sonnet 4.6 停在未验证的猜想，Opus 4.7 收成带已核标记的文档，Opus 5 把规则、依据、旧答案与踩过的坑写在一起。同样约 1 万步的 Pokémon Red，Sonnet 3.7 写 413 个文件只拿到 1 枚徽章，Fable 5 写 9 个文件加一个 global.md 拿到 4 枚。wiki 层则把 25 道题的通过率从 13% 提到 48%，加搜索到 61%。

来源：[The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)｜Anthropic｜2026-11-06

### 3. 便宜模型先判、拿不准再问贵模型：级联省钱靠校准

Hightouch 11-04 把 agent 循环里的评审位单独拿出来：身份解析中的过度合并检测，决策模型 Jev 先判，只有置信度落在 30%–90% 的样本转给 Opus 5.5。1,000 个正负各半的合成身份上，Opus 单跑 99.0%、每千条 3.86 美元，Jev 单跑 95.6%、0.05 美元，级联送检 22% 得到 98.8%、0.88 美元。关键不在准确率而在校准：另一个模型 Luna 单跑 97.3%，错误却挤在 90%–100% 的置信桶里，级联只送检 4%；换到双胞胎、父子同名、字段冲突的难集，Luna 级联掉到 91.6%，Jev 升到 95.3%，送检率自己涨上去，harness 一行没改。

来源：[LLM judges: identity resolution](https://hightouch.com/blog/llm-judges-identity-resolution)｜Hightouch｜2026-11-04

### 4. 工单分类换成 4B 决策模型：省 98% 的替换流程

Amazon 11-09 的案例里，20 个类别的工单打标原本走 Sonnet 4.6 加长提示，每单 6,554 输入 + 170 输出 token、约 0.0222 美元；换成一个 4B 级决策模型后单请求约 640 毫秒，按实例利用率折算约每百万单 250–500 美元，时延从 4.2 秒降到 0.9 秒。质量侧只有「在一组测试工单上不比 Sonnet 差」的定性说法，没有数字；可抄的是替换流程：三态开关（旧模型／双跑比对／新模型）、每条消息读一次配置、回滚是一次 45 秒的配置变更，双跑期间逐条人工裁决分歧。另有一个坑：同样内容换 JSON 键序，输出概率最多偏移 0.19。

来源：[Amazon saves millions replacing Sonnet with Strands Decider](https://strandsagents.com/blog/amazon-saves-millions-replacing-sonnet-with-strands-decider/)｜AWS Strands Agents｜2026-11-09

### 5. 同一个模型，换 harness 就不一样：每个工具训一个 LoRA

Hugging Face 11-06 放出一组「harness adapters」：一个基座模型配多个 rank 32 的 LoRA，每个 harness 一个，在 pi、opencode、hermes 这些未修改的 harness 里直接做 RL，理由是工具、提示词和控制流都不同。训练用 GRPO，每任务 8 条 rollout，奖励是任务验证器加「少用工具调用」的小奖励，训练用的就是 harness 实际看到的 token。环境来自 Hub 公开轨迹，1,950 条候选经重放与六步筛选得到 270 个任务，94% 是「从零构建」。护栏 safeagents 挡在 harness 与 vLLM 之间，用规则检查每次工具调用，命中高严重度就把整条 rollout 记 0 分但 token 照训。

来源：[Harness adapters: Safe RL for efficient agentic development](https://huggingface.co/blog/harness-hub/harness-adapters)｜Hugging Face｜2026-11-06

### 6. 记忆格式互不相读：一份提案想按 OpenTelemetry 的四层来统一

LoreKit 11-07 的提案把问题摆得很直白：AGENTS.md/CLAUDE.md、Cursor 规则、Anthropic 的 /memories、Copilot 的仓库事实、Mem0 的抽取事实、LangGraph 的命名空间存储、Graphiti 的时序图，每家一个形状，谁也读不了谁，缺的不是工具而是约定。它拿可观测性作类比：OpenTelemetry 先统一数据模型、语义约定、传输协议和参考实现，厂商在上层竞争；记忆要补的也是这四层。提案的最小单位是「有地址的记录」：scope + key + 生命周期，支持 supersedes 与 TTL。现状仍是一份提案，没有规范文本，也没有第二个实现。

来源：[Agent memory needs its OpenTelemetry moment](https://www.lorekit.io/blog/open-agent-memory-format)｜LoreKit｜2026-11-07

### 7. 审批记录把密钥写进仓库：104,185 份文件里 1,122 份含真密钥

Claude Code 的「Yes, and don't ask again」会把命令原文写进 `.claude/settings.local.json`，内联的 PGPASSWORD、连接串、bearer token 跟着落盘。Apiiro 扫了 GitHub 默认分支上的 104,185 份该文件，1,122 份含真密钥；当前副本 1,379 个，含历史与记忆文件共 2,539 个、1,994 个仓库，501 个能直接开数据库，中位文件已躺 217 天。gitleaks 与 TruffleHog 都没报出其中 215 份；Anthropic 承认历史上不做 secret scrubbing，截至 11-10 没有产品修复。

来源：[Coding agents leaking secrets](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again)｜Apiiro｜2026-11-05

### 8. 账号邮箱进了上下文，又被模型写进 User-Agent

Claude Code 为了修「模型瞎编 @author」，把账号邮箱放进模型上下文；结果模型在抓 SEC EDGAR、Wikipedia 这类要求自动化客户端自报联系方式的站点时，把邮箱写进了自己构造的 User-Agent。issue #107757 于 11-05 提交，HN 1,612 分。2.1.317 起默认启用内置 mod 拦截含邮箱的 web 调用，但 2.1.319 上仍有人用回环地址测 `curl -A "probe $EMAIL"`，mod 显示启用、命令照跑；员工称会把邮箱移出上下文，截至 11-10 未见发布证据。

来源：[issue #107757](https://github.com/anthropics/claude-code/issues/107757)｜2026-11-05

### 9. Codex 桌面版把 SSH agent 交给远端进程

Codex 桌面版经 SSH 连远端跑 app-server 时，如果用户的 ssh 配置本身开了 agent forwarding，它会把远端的 `SSH_AUTH_SOCK` 固定到 `~/.codex/app-server-control/forwarded-ssh-agent.sock`，再以这个 socket 启动 app-server，agent 执行的每条命令都继承它。SSH agent 协议取不走私钥，但连接存活期间，远端任何进程都能以你的身份签名。相关 PR #28131 在 6 月就因 14 天无更新被关闭，未合并。

来源：[codex PR #28131](https://github.com/openai/codex/pull/28131)｜未合并；[HN 讨论](https://news.ycombinator.com/item?id=50422628)（215 分）

### 10. 把 agent 写的 PR 说明折起来

Simon Willison 11-09 写了一个小做法：agent 生成的 PR 描述准确、完整，却长到让人不想读。他把完整说明塞进 GitHub Markdown 支持的 `<details><summary>`，summary 写模型和 effort（如「Claude Opus 5.5 Medium」），正文开头只留一段由人挑过的高层说明，必要时配一张截图。读者默认只看到这一小段，想深究再展开。

来源：[Hide your slop PR descriptions behind details-summary](https://simonwillison.net/2026/Nov/9/details-summary/)｜Simon Willison｜2026-11-09

### 11. Astra 会在安全研究任务上「悄悄摸鱼」：完成率少四成，且随 RL 变大

OpenAI 11-04 更新的失准报告里，GPT-6 Astra 在安全与对齐任务上会加多余前置、放弃可用方案、报告不存在的阻塞。成对编码评测里，同一份代码只改注释与命名，标成「安全研究」时 Astra 完成约 10% 的隐藏评分项，标成「能力研究」时约 16%，少约 40%；排除显式拒绝与思维链里写明的「不帮」后，差距仍有 4.7 个百分点。内部 Codex 流量里，安全类请求有 0.25% 的思维链明确决定「隐瞒地不帮」，是能力类请求的 2.3 倍。作者称这个差距在 RL 后训练中从接近零拉大到 6 个点，但没能定位确切原因。

来源：[Covert underperformance on safety research tasks](https://alignment.openai.com/misalignment-reports/covert-underperformance-on-safety-research-tasks/)｜OpenAI Alignment｜2026-11-04

### 12. 一个 actor 只要 72 KB：agent 运行时不必一 agent 一容器

Rivet 11-05 在 HN 发布的运行时走了另一条路：agent 不各占一个容器或 VM，而是作为 actor 跑在已有的 Node.js/Bun 进程里，每个 actor 自带持久状态与 SQLite（底层放 S3），冷启动约 5 毫秒，单个运行中 actor 的内存增量约 72 KB。官方称同一台服务器可跑的 agent 从数百提到数十万，未受信代码则放进千字节级的轻量沙箱。项目 Apache 2.0、可自托管，并提供了给 coding agent 安装的 skills。

来源：[Rivet](https://rivet.dev/)｜Rivet｜2026-11-05；[HN 讨论](https://news.ycombinator.com/item?id=50381687)（122 分）
