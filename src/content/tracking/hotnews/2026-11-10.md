这一周的主线是协作原语。Anthropic 用五张 Postgres 表和 Git 分支，让 1,000 个 agent 在 28.7 小时里复现费马大定理的 Lean 形式化；Hugging Face 反过来证明，同一个模型换个 harness 就不一样，每个工具值得单独训一个 LoRA。另有记忆组件的分层实验、把「判断」拆给决策模型的级联、一份想让各家记忆格式互读的提案，以及三处 harness 自己写下的泄露面。

## 本期值得了解

### 1. 一千个 agent、五张 SQL 表：通用工具也能撑起长任务协作

Anthropic 11-09 公开了一次玩具实验：1,000 个 agent 跑在早期版本的 Fable 5.2 上，28.7 小时复现费马大定理的 Lean 形式化。起点被刻意削薄——没有专用平台，没有研究者指挥，只给了 60 条命题（最终定理加 59 个里程碑）、一句路线梗概、所需定义，以及上一轮已证的 47 个引理；角色只有 1 个 lead 和 999 个 helper，每个 agent 一台无网络 VM、自己的 Git 分支，再共享一个 Postgres 库。

Lead 开工 10 分钟就建了五张表：announce、assign、notes、subtasks、landed，把 60 条命题分给 60 个 16–17 人小队。27 分钟时只有 3 条证完，多数 helper 判定 47 条不可行，lead 干脆搁置它们，把人力压到剩下 10 条；这 10 条约 70 分钟证完，它又写下「没有理由闲着」，把人调回难题。到第 5.6 小时，73 个 helper 写了 756 个任务，层级自己下沉。最后只剩 Langlands–Tunnell，captain 估计要 70–100 万行、按时完成概率不到 1%，lead 压上约 750 个 helper，长出一棵 2,418 个任务、最深 10 层的树，第 28.7 小时最终定理进 main。

超过 100 万次工具调用没有一次触发拦截；事后用同时看思维链的监控回放，只有一次「检查 root 权限」接近红线。

来源：[Safely scaling multi-agent teams with Claude Fable 5.2](https://claude.dev/blog/safely-scaling-multi-agent-teams-with-fable-5-2/)｜Anthropic｜2026-11-09

### 2. 记忆不是一个文件夹：笔记、dreaming 与 wiki 各自解决什么

Anthropic 11-06 把 agent memory 收窄为：从经验获得、跨会话保留、以可读上下文存放的知识，并按机制拆成四层——会话中随手写的笔记、后台回看 transcript 与笔记并纠错的 dreaming、每会话预加载的注入层、把知识连成地图的 wiki。

CL-Bench 1.0 的数据库任务只给一个持久记忆目录。Sonnet 4.6 停在未验证的猜想；Opus 4.7 把笔记收成带已核标记的参考文档；Opus 5 第一个闭上环，把规则、依据、旧题答案与踩过的坑写在一起。提示也有反直觉结果：只说「有一个记忆目录」就足以让 Opus 4.7/5 受益，而规定「只记失败」让两个强模型都损失大部分增益。

「记什么」比「记多少」重要：同样约 1 万步的 Pokémon Red，Sonnet 3.7 写了 413 个文件只拿到 1 枚徽章，Fable 5 只写 9 个文件加一个 global.md 就拿到 4 枚。前者把每回合都能读到的状态也存了，后者只存策略、计划与验证过的规则。

wiki 这一层最重：约 35 万个文件、4.2 亿 token 的语料上，仅靠 wiki 从 13% 升到 48%，加搜索从 54% 升到 61%；注入层则必须小，Claude Code 的 auto memory 只加载 MEMORY.md 的前 200 行或 25 KB。

来源：[The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)｜Anthropic｜2026-11-06

### 3. 便宜模型先判、拿不准再问贵模型：级联省钱靠校准

Hightouch 11-04 把 agent 循环里的评审位单独拿出来：身份解析中的过度合并检测，给一组被判为同一个人的记录，判断它其实对应几个人。决策模型 Jev 先判，只有置信度落在 30%–90% 的样本转给 Opus 5.5。1,000 个合成身份（正负各半）上，Opus 单跑 99.0%、每千条 3.86 美元；Jev 单跑 95.6%、0.05 美元；级联送检 22%，得到 98.8%、0.88 美元。

关键不在准确率而在校准。另一个决策模型 Luna 单跑 97.3%，错误却挤在 90%–100% 的置信桶里，级联只送检 4%；换到只留双胞胎、父子同名、字段冲突的难集，Luna 级联掉到 91.6%，Jev 级联升到 95.3%，送检率自己涨上去，harness 一行没改。

同一结构在 Amazon 工单分类里换了形态：20 个类别原走 Sonnet 4.6，每单约 0.0222 美元；换成 4B 决策模型后单请求约 640 毫秒，按实例利用率折算约每百万单 250–500 美元，时延从 4.2 秒降到 0.9 秒。替换流程值得抄：三态开关（旧模型／双跑比对／新模型）、每条消息读一次配置、回滚是一次 45 秒的配置变更，双跑期间逐条人工裁决分歧。

来源：[LLM judges: identity resolution](https://hightouch.com/blog/llm-judges-identity-resolution)｜Hightouch｜2026-11-04；[Amazon saves millions replacing Sonnet with Strands Decider](https://strandsagents.com/blog/amazon-saves-millions-replacing-sonnet-with-strands-decider/)｜AWS Strands Agents｜2026-11-09

### 4. 同一个模型，换 harness 就不一样：每个工具训一个 LoRA

Hugging Face 11-06 放出一组「harness adapters」：一个基座模型配多个 rank 32 的 LoRA，每个 harness 一个，在 pi、opencode、hermes 这些未经修改的 harness 里直接做 RL。出发点是同一个模型在不同 harness 里表现不同，工具、提示词和控制流都不同；与其训练一个通用 agent 模型，不如把 harness 当成策略的一部分。

训练用 GRPO，每个任务 8 条 rollout，奖励是任务自带验证器加一个「少用工具调用」的小奖励 `0.1 × (1 − calls/15)`，只在答对时给。harness 照原样跑在自己的沙箱里，训练用的就是它实际看到的 token，不重新分词；三个训练器共享一份基座权重，各自挂自己的 adapter。环境来自 Hub 上公开的 agent 轨迹：1,950 条候选经重放与六步筛选得到 270 个任务，94% 是「从零构建」。

护栏是 safeagents，一个挡在 harness 与 vLLM 之间的反向代理，用规则而不是模型检查每次工具调用：只能调声明过的工具、只能访问对话里出现过的 host、不能改测试文件、不能写奖励文件。单次检查 10–20 毫秒，命中高严重度就把整条 rollout 记 0 分，但 token 照常训练。TwIL-8B 在第 0 步就想去 Hugging Face bucket 里找原 notebook，被当场拦下。

来源：[Harness adapters: Safe RL for efficient agentic development](https://huggingface.co/blog/harness-hub/harness-adapters)｜Hugging Face｜2026-11-06

### 5. 记忆格式互不相读：一份提案想按 OpenTelemetry 的四层来统一

LoreKit 11-07 的提案把问题摆得很直白：AGENTS.md/CLAUDE.md、Cursor 规则、Anthropic 的 /memories、Copilot 的仓库事实、Mem0 的抽取事实、LangGraph 的命名空间存储、Graphiti 的时序图，每家一个形状，谁也读不了谁。缺的不是工具，是约定。

它拿可观测性作类比：OpenTelemetry 能让生态互读，是因为先统一了数据模型、语义约定、传输协议和参考实现，厂商在上层竞争。记忆要补的也是这四层。提案的最小单位是「有地址的记录」：scope + key + 生命周期，支持 supersedes 与 TTL。

现状仍是一份提案：没有规范文本，也没有第二个实现；MCP 与 AGENTS.md 已归 Linux Foundation 的 Agentic AI Foundation，是它认为合适的落点。

来源：[Agent memory needs its OpenTelemetry moment](https://www.lorekit.io/blog/open-agent-memory-format)｜LoreKit｜2026-11-07

### 6. 审批记录、身份与凭据代理：harness 自己写下的三处泄露面

Claude Code 的「Yes, and don't ask again」会把命令原文写进 `.claude/settings.local.json`，内联的 PGPASSWORD、连接串、bearer token 跟着落盘。Apiiro 扫了 GitHub 默认分支上的 104,185 份该文件，1,122 份含真密钥；当前副本 1,379 个，含历史、共享 settings、聊天记录与记忆文件共 2,539 个、1,994 个仓库，501 个当前密钥能直接开数据库，中位文件已躺 217 天。Anthropic 承认历史上不做 secret scrubbing，正在原型「auto mode 拦截」与基础扫描，截至 11-10 没有产品修复。

同一周还有两处。Claude Code 把账号邮箱放进模型上下文，模型在构造 `User-Agent` 时把它写给要求自报联系方式的站点，2.1.317 起用内置 mod 拦截含邮箱的请求，但 2.1.319 上仍能用回环地址绕过。Codex 桌面版经 SSH 连远端跑 app-server 时，如果用户的 ssh 配置本身开了 agent forwarding，它会把远端的 `SSH_AUTH_SOCK` 固定到共享路径，再以这个 socket 启动 app-server，agent 的每条命令都继承它。

三处的共同点是授权绑在入口动作上，风险落在动作之外。可操作的检查是 allow 规则存模式而不是字面命令、凭据用 `$VAR` 注入、`.claude/` 与记忆文件按 `.env` 同级对待。

来源：[Coding agents leaking secrets](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again)｜Apiiro｜2026-11-05；[issue #107757](https://github.com/anthropics/claude-code/issues/107757)｜2026-11-05；[Codex PR #28131](https://github.com/openai/codex/pull/28131)

### 7. 把 agent 写的 PR 说明折起来

Simon Willison 11-09 写了一个小做法：agent 生成的 PR 描述准确、完整，却长到让人不想读。他把完整说明塞进 GitHub Markdown 支持的 `<details><summary>`，summary 写模型和 effort（如「Claude Opus 5.5 Medium」），正文开头只留一段由人挑过的高层说明，必要时配一张截图。读者默认只看到这一小段，想深究再展开。

来源：[Hide your slop PR descriptions behind details-summary](https://simonwillison.net/2026/Nov/9/details-summary/)｜Simon Willison｜2026-11-09
