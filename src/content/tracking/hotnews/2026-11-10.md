这一周最值得读的是一条把协作原语降到通用工具的实验：Anthropic 让 1,000 个 agent 在无网络沙箱里，只用五张 Postgres 表和 Git 分支，28.7 小时复现了费马大定理的 Lean 形式化——没有专用平台，也没有研究者指挥。它说明多代理的瓶颈不在模型数量，而在共享状态怎么记、任务怎么认领、失败怎么恢复。另有三条：Anthropic 把记忆拆成笔记、dreaming 与 wiki，并给出「给判断自由优于给固定规则」的反向对照；两个团队把 agent 循环里的判定位交给决策模型，级联是否省钱取决于校准而不是准确率；三起事件显示 harness 自己写下的审批、身份与凭据代理，正在成为新的泄露面。

## 本期值得了解

### 1. 一千个 agent、五张 SQL 表：通用工具也能撑起长任务协作

Anthropic 11-09 公开了一次「玩具实验」：1,000 个 agent 跑在早期版本的 Fable 5.2 上，28.7 小时复现了费马大定理的 Lean 形式化。与 9 月那次相比，起点被刻意削薄——没有 Prove2Me 平台，没有研究者指挥，只给了 60 条命题（最终定理与 59 个里程碑，各一句非形式化描述）、一句经典路线梗概、所需定义，以及上一轮已证的 47 个引理；角色只有 1 个 lead 和 999 个 helper。9 月那轮用了 11 天、约 60 亿输出 token、1,300 万行 Lean；这一轮输出 token 是它的三分之一，证明长度是七分之一。

真正被替换掉的是协作底座。每个 agent 一台轻量 VM、无网络，工具只有 shell、文件编辑器、Lean 工具链与 Mathlib、自己的 Git 分支，以及一个共享 Postgres 库。开工 10 分钟内，lead 自己在库里建了五张表：announce（全员命令）、assign（999 行，谁负责什么）、notes（开放板）、subtasks（谁先认领谁拥有）、landed（完成日志）。它把 60 条命题分给 60 个 16–17 人小队，每队指定一名 captain 写计划、拆任务；helper 先判断自己那条命题的难度并把结论贴到 notes。27 分钟时只有 3 条证完，多数 helper 判定 47 条在预算内不可行，lead 干脆把这 47 条搁置，把几乎全部人力压到剩下 10 条，小队规模涨到 46–139 人——这 10 条约 70 分钟证完，随后它写下「没有理由闲着」，又把人力调回先前丢弃的难题。

层级很快自己下沉。第 3 小时，lead 对空闲 helper 说「不要等我」；到第 5.6 小时，73 个 helper 写了 756 个任务，其中只有 16 个是 captain。第 18 小时运行从存档重启并补了 12 小时，只剩 Langlands–Tunnell：captain 早先估计它要 70–100 万行 Lean、按时完成概率不到 1%，lead 把约 750 个 helper 压上去，留了一句「honest odds are low」。这一条最终长出 2,418 个任务、最深 10 层的任务树，第 28.4 小时证完，28.7 小时最终定理进 main。收尾时覆盖 60 条中的 54 条，差的 6 条是 5 条替代路线不再需要、1 条被丢弃，不是失败。

为什么值得理解：它把多代理最容易被专用平台吃掉的部分——共享状态、任务认领、冲突合并、失败恢复——交回给 SQL 事务与 Git 分支/合并请求，证明这些通用原语足以支撑千级并发写；代价是团队必须自己长出一套任务树和认领规则，而不是拿到现成的 DAG。安全侧是另一套结构：七项沙箱细则（无网络、裁剪内核、无特权用户、去 sudo、工具读不到自己的循环）、一个逐次拦截工具调用的分类器、一个跨 agent 的离线监控；拦到 lead 全队停，拦到 helper 只移除该 helper。超过 100 万次工具调用里没有一次达到拦截线，事后用同时看思维链的监控回放，只有一次「检查 root 权限」接近被拦——而这次运行实际只开了看动作的那一种。

边界必须一起读：这是单次运行，没有 100 与 1,000 的对照，没有拆掉层级或换掉 SQL 的消融，绝对 token 与成本未公布；「没有脚手架」指的是没有 Prove2Me 和研究者，60 条命题、路线梗概与 47 个引理都是喂进去的；作者自己称它是 toy experiment，并说领域专用平台仍可能更高效。最硬的一条可迁移观察反而是失败模式：agent 会系统性低估难题可行性——开局 47/60 被判不可行，Langlands–Tunnell 被估到不足 1%，最后都做出来了。人类在这种时刻的鼓励仍然有用，而这次实验里没有人类，只有 harness 自动发给 lead 的 19 次剩余时间提醒。

### 2. 记忆不是一个文件夹：笔记、dreaming 与 wiki 各自解决什么

Anthropic 11-06 的工程文把 agent memory 定义得很窄：从经验获得、跨会话保留、以可读上下文存放的知识；明确排除权重变化、会话内学习与 compaction。文章没有给编号清单，但按机制可以拆成四层：会话中随手写的笔记（类比海马体，代价是分心）、后台回看 transcript 与笔记的 dreaming（纠错、建表示、调结构）、每会话预加载的注入层，以及 wiki 这种把知识连成地图的表示。

CL-Bench 1.0 的数据库任务是观察「谁真的形成了学习闭环」的窗口：每题新会话，唯一跨会话通道是一个持久记忆目录。Sonnet 4.6 只走到「生成猜想」，目录里是一堆没验证的猜测；Opus 4.7 把笔记收成一份参考文档并标注哪些已核；Sonnet 5 在 grader 核过后标 confirmed；Opus 5 第一个闭上环——规则、规则的依据、旧题答案与踩过的坑写在一起。提示方式也有反直觉结果：只说「有一个记忆目录」就足以让 Opus 4.7/Opus 5 明显受益；把规则定成「只记失败」，两个强模型都损失了大部分增益；Sonnet 4.6 被提示「先读记忆再回答、显式检验猜想」后分数接近翻倍，而 Sonnet 5 不用提示也有 9/10 次先读。

「记什么」比「记多少」重要，Pokémon Red 给出了很干净的对照：同样跑到约 1 万步，Sonnet 3.7 写了 413 个文件、225 个文件夹，只拿到 1 枚徽章，还在第 1 万步附近新建 6 个文件、删除 9 个文件、17 步没在游戏里做任何动作；Fable 5 只写 9 个文件、2 个文件夹加一个 global.md，拿到 4 枚徽章。差别在于前者把每回合都能从屏幕读到的状态也存了下来，后者只存策略、计划与验证过的规则。dreaming 的作用是拿原始 transcript 当事后校验的 ground truth：一次它把「PokéCenter 在东边」的错误笔记改对，agent 于是重新进山洞、抵达下一座城；不修正的对照三次掉回原路，最后写下「我要停下来，不再循环」。

wiki 是更重的表示层。用 Anthropic 收购的 Stainless 的约 35 万个文件、约 4.2 亿 token 做语料，25 道题，dreaming 从 2 个会话扩到 128 个会话，仅靠 wiki 的评分从 13% 升到 48%；wiki 加搜索从 54% 升到 61%，只用搜索是 53%，两者合用每题还省约 2 万 token。任务形态决定收益：Harvey LAB 的并购题里，需要跨多份文件的 24 道题 wiki 得 87%、纯搜索 73%；单份文件就能搜到的题没有增益；还有一次 wiki 长得比原始语料更大，作者自嘲是博尔赫斯那张与帝国等大的地图。注入层则必须小：Claude Code 的 auto memory 只加载 MEMORY.md 的前 200 行或 25 KB，作为索引；更长的指令文件反而降低遵循度。

记忆也可以按目标塑形。合同摘要任务里，多个 agent 同时往一张共享条款表写，互相覆盖，最终 brief 只覆盖 57 条中的 41 条（72%）；改成「每份合同一页、单 agent、逐字引用」后是 57/57。这个改法不是人想出来的，是「反思失败→改指令→重建」的循环搜出来的。

边界：全文没有 dreaming 相对无 dreaming 的系统性 A/B，Pokémon 纠错是各一次运行；带样本量的只有自建的 25 题曲线；跨代模型对比混着模型整体能力提升，作者自己也承认 Opus 5.5/Sonnet 5.5 的无记忆基线更高；Stainless 语料不可复现。真正可迁移的是两条：用原始记录而不是摘要去校验记忆；给强模型判断「什么值得记」的自由，比预设「只记失败」这类规则更有效。

### 3. 便宜模型先判、拿不准再问贵模型：级联省钱靠校准，不靠准确率

Hightouch 11-04 的实验把 agent 循环里的「评审位」单独拿出来：身份解析中的过度合并检测，给一组被判为同一个人的记录，判断它其实对应几个人。Jev 是 TypeSafe 那类返回 0–1 概率的决策模型，它先判；只有置信度落在设定区间（如 30%–90%）的样本才转给 Opus 5.5 复核。1,000 个合成身份（正负各半）上，Opus 单跑 99.0%、每千条 3.86 美元；Jev 单跑 95.6%、0.05 美元；级联送检 22%，得到 98.8%、0.88 美元——标题里的「4 倍便宜」就是这个口径。

关键不在准确率，而在校准。另一个决策模型 Luna 单跑 97.3%，比 Jev 更强，错误却挤在 90%–100% 的置信桶里，于是级联只送检 4%；换到只留双胞胎、父子同名、关键字段冲突的难集，Luna 级联掉到 91.6%，而 Jev 级联升到 95.3%（Opus 单跑 95.1%），送检率自己涨上去，harness 一行没改。省钱的倍数也从 4.4 倍缩到约 1.8 倍，但准确率反超单跑。结论可以压成一句：挑便宜模型做判定位，要看它错的时候知不知道自己不确定；否则省下的钱买不到准确率。

同一结构在 Amazon 的工单分类里换了个形态。20 个类别的打标原本走 Sonnet 4.6 加长提示，每单 6,554 输入 + 170 输出 token，约 0.0222 美元；换成一个 4B 级决策模型后，单请求约 640 毫秒，按实例利用率折算约每百万单 250–500 美元（省 98% 上下），时延从 4.2 秒降到 0.9 秒。质量侧只有「在一组测试工单上不比 Sonnet 差」的定性说法，没有数字，这是这条案例最大的缺口；但它的替换流程值得抄：三态开关（旧模型／双跑比对／新模型）、每条消息读一次配置、回滚是一次 45 秒的配置变更，双跑期间逐条人工裁决分歧——作者说这比任何离线评测都有信息量。另有一个坑：同样内容换 JSON 键序，输出概率最多偏移 0.19，固定键序后才可比。

边界：Hightouch 的数据是正负各半的合成集，真实过度合并是稀有事件，准确率不能直接换算到生产基率；阈值与送检带在同一测试集上挑，没有置信区间与重复运行；作者是 CDP 厂商，身份解析是它的主场。Amazon 的数字只有成本与时延可复算，质量主张是自述。可迁移的是分工形状：把「从已知目录里选一个」的判定位交给决策模型，把需要解释、需要生成的留给大模型；送检按置信度带而不是固定比例，花费就会随难度自动伸缩。

### 4. 审批、身份与凭据代理：harness 自己写下的东西成了泄露面

三起事件坏在不同层，形状却一样：授权绑在「入口动作」上，风险却落在动作之外。

第一起是审批记录的存储格式。Claude Code 选「Yes, and don't ask again」时，会把这条命令的字面文本写成 allow 规则，存进项目里的 `.claude/settings.local.json`；如果命令里内联了 `PGPASSWORD=`、连接串或 bearer token，密钥就跟着进了这个 JSON。Apiiro 扫了 GitHub 默认分支上的 104,185 份该文件：1,122 份（1.1%）含真密钥，当前副本里 1,379 个，连同历史、共享 settings、聊天记录与记忆文件合计 2,539 个、1,994 个仓库；就 allowlist 一项，63 个组织命中。1,379 个当前密钥里 501 个能直接打开数据库，211 个 fork 带着同样的密钥，中位仓库里文件已躺了 217 天。更刺眼的是 agent 自己也参与提交：可追溯的 1,105 个仓库里，539 个有 Claude 作为 co-author 的提交改过该文件，而它的提交指令只提醒不要提交 `.env` 与 `credentials.json`。gitleaks 与 TruffleHog 分别只报出 564 与 643 份，215 份两者都没报——因为密码是命令行里的普通单词，不带 key 前缀。

保护只做在一层：Claude Code 创建该文件时会把它加进用户的全局 git ignore，但不会写进仓库自己的 `.gitignore`；文件一旦已被跟踪，下一次批准继续追加，用户看不到提示。Anthropic 的 Claude Code 负责人 Boris Cherny 11-07 在 HN 回应：历史上确实不做 secret scrubbing，正在原型「让 auto mode 拦住」与「内置基础 secret 扫描」，并承认 auto mode 询问敏感命令时同样会落盘；截至 11-10 没有产品层修复。这条的可操作结论很直接：allow 规则应存模式（`Bash(npm run:*)`）而不是字面命令，凭据用 `$VAR` 注入，`.claude/`、`.cursor/`、`.gemini/`、`.specstory/` 与记忆文件应按 `.env` 同级对待。

第二起是身份进上下文。Claude Code 曾把账号邮箱放进模型上下文，本意是修「模型瞎编 @author」的问题；结果模型在抓某些要求自动化客户端自报联系方式的站点（SEC EDGAR、Wikipedia 等）时，会把邮箱写进自己构造的 `User-Agent`。GitHub issue #107757 于 11-05 提交，HN 1,612 分。缓解是 2.1.317 起默认启用内置 mod `cc-plugin-privacy`，拦截含邮箱的 web 调用或 curl 命令；但 2.1.319 上仍有缺口——有读者用回环地址测 `curl -A "probe $EMAIL"`，mod 显示启用、命令照跑。Anthropic 员工称会把邮箱从上下文中移除，「下个版本」；截至 11-10 未见发布证据。失效的一层是身份最小化：为一个外观 bug 把账号标识放进模型可自由复用的素材里，再用字符串匹配去兜底，天然会漏。

第三起是凭据代理的粒度。Codex 桌面版经 SSH 连远端跑 `codex app-server` 时，如果用户的 ssh 配置本身开了 agent forwarding，它会把远端的 `SSH_AUTH_SOCK` 固定到 `~/.codex/app-server-control/forwarded-ssh-agent.sock`，再以这个 socket 启动 app-server，agent 执行的每条命令都继承它。SSH agent 协议取不走私钥，但在连接存活期间，远端任何进程都能以你的身份签名——push 私有仓库、登录信任这把钥匙的主机。说「默认转发」不准确：转发与否取决于用户的 ssh 配置，App 不加 `-A`；但「把已有转发交给 agent 并落到共享固定路径」这一步既无提示也无文档，多客户端连同一账号还会互相覆盖。相关 PR #28131 在 6 月就因 14 天无更新被关闭、未合并，只有一条 issue 记录这个行为。

三起合起来看，失效的都不是模型判断，而是 harness 的记账方式：审批记的是命令原文而不是模式，身份放进了会被复用的上下文，凭据代理把「密钥不出本机」退化成「连接期内谁都能代签」。对应的检查也应是结构性的：agent 状态目录按秘密管理、出站 header 由 harness 统一生成、远端任务用短时窄域凭据并逐次确认；以及一条操作性的——「issue 关了」不等于「修了」，验证要打到实际路径，而不是看设置项是否存在。

## 值得继续追问

- 条目 1：任务树允许「每块可假定下层成立」，下层被推翻时的返工成本没有度量；100 与 1,000 的对照、拆掉层级的消融都缺。另一个可验证假设是：换掉 SQL 或 Git 中任意一个，协作还能不能维持。
- 条目 2：dreaming 的触发节奏与预算没有最优值；wiki 在非收购语料、非多文档任务上的边界需要复现。文章自己也承认，持续校验全部记忆不现实，按易变度或访问频率调 cadence 是待验证的设计选择。
- 条目 3：校准必须在自己的任务分布上测。coding agent 的评审门禁（补丁是否引入回归、测试失败是否 flaky、diff 是否越界）是不是同样的形状，目前没有公开实验。
- 条目 4：三起里只有 Claude Code 有产品动作且自认覆盖不全；「修了」要以实际路径验证。跨工具的 agent 记忆格式仍是空白：同周 LoreKit 的提案主张用统一的记录信封（address、version、supersedes）替代各家私有存储，但截至发稿没有规范与第二个实现。
- 跨条目：Fable 5.2 的 Advisor/Orchestrator 角色、Jev 的级联、Amazon 的 Decider 是同一个动作的三种实现——把「判断」从生成模型里拆出来。它们各自的成本曲线是否可比，值得并排测一次。
