本期没有模型发布，几条独立变化落在同一前提上——先能测量，才谈约束和优化：扩展机制第一次有公开源码，此前不可见的远程开关被要求说明（条目 1）；上下文管理出现可复用的默认阈值（条目 2）；真车赛道、实验室与上线守卫把「测量」推到物理和生产环境（条目 3、5、8）；沙箱评估也在从建议变成清单（条目 4）。claude.dev 的复盘把这句话当作方法论核心：能计数，就能优化（条目 6）。

### 1. Claude Code 的扩展层公开，AGENTS.md 开关事件收尾

HN 讨论帖「Claude Code 只在遥测开启时读取 AGENTS.md」已被标记为已修复（457 分）。Anthropic 工程师在帖内说明：这是灰度发布用的远程开关造成的失误，AGENTS.md 支持（让 Claude Code 读取项目里通用的 AGENTS.md 指令文件）由新的扩展系统 **Mods** 实现，已在 v2.1.281 修复。有个人分析把打包后的程序还原成可读代码，补出了它的行为：该功能是否启用取决于服务端下发的一个开关，取不到就关闭；把遥测关掉、或禁止非必要网络请求，都会让它失效——也就是说，一个读本地文件的功能，当时被远端开关管着。仓库同时公开了随包内置扩展的源码：Mods 是一种插件，可以在代理执行到特定环节时介入；内置四个，分别是 AGENTS.md 支持、会话内差异面板、遥测上报，以及一个把组织策略挡在用户安装的插件之外的模块。官方 issue 里说，这类扩展能力将在数周内正式发布。

对使用者的影响分两层：插件生态将获得正式的扩展接口；而「本地行为被远程开关支配」这次有了官方定性——不是有意设计，而是灰度开关的工程失误，但风险类别真实，验收本地特性应在开关开、关两种状态下各测一次。证据边界要说明：v2.1.281 的发行说明正文没有单列这个修复，「已修复」由工程师回复、第三方实测与用户启动日志三处支持，不是发行说明自证。该版本还有两处会影响日常使用的变化：可以关闭提交时附带的「由 Claude 生成」署名；靠命令替换拼出来的高危删除操作现在一定会先弹确认。**破坏性变更**：用自建机器跑 agent 的部署方式改了传递系统提示词的方式，凡是靠命令行参数注入提示词的包装脚本或钩子都要改用文件方式，升级前请先看官方的迁移说明。另一处口径提醒：npm 的 latest 渠道已是 2.1.281，但 stable 渠道仍指向 2.1.273，不要写成「稳定版已升级」。

### 2. Strands Harness：把上下文管理的阈值写成默认值

Strands Harness（一个开源代理运行框架，Apache 2.0 许可，原文 09-21、HN 09-23 130 分）把上下文管理写进默认配置：工具返回结果超过约 1500 token（模型处理文本的计量单位，直接对应成本）就截断，上下文占用超过 85% 触发压缩，溢出时在循环内恢复。作者自报同模型下比 Claude Code 省 28% 成本，用 Fable 5 时省 77% 且 Terminal-Bench 2.1 得分更高。因为它是默认值而非可选项，这两个阈值可以直接拿来做对照实验的起点。边界：全部数字自报、无独立复现，作者称后续会有论文。

### 3. DrivingBench：真车赛道横评，只有 GPT-6 Astra（Codex）完赛

第三方研究者（Aditya Ramabadran、Simon Mahns、Tobias Gessler）把前沿模型接进一辆真丰田卡罗拉的转向、油门与刹车，在固定锥桶赛道上做评测（数据为 9 月 17 日赛道批次、9 月 20 日生成，HN 09-23 23:14 CST，275 分）；同一对话内最多尝试 3 次，成本按实测 token 计（含事后反思）。结果：**GPT-6 Astra＋Codex 第 2 次完赛，用时 5 分 22 秒、24 条命令、660 万 token、7.74 美元**（第 1 次只走完 49%、花费 2.01 美元）；Claude Fable 5.1＋Claude Code 最高 45%，Grok 4.6＋Cursor 11%，GPT-5.6 Sol＋Codex 6%，均未完成。

24 条命令花掉 660 万 token，说明瓶颈在每一步重新读取上下文，而不在动作次数；这种「模型×代理运行框架（harness）横评＋逐次成本」的口径可以直接借用。边界：单赛道、单次尝试、未同行评审；「真车」由作者自述与视频佐证，未独立核实。

### 6. claude.dev 复盘：两周把 claude.ai 做快 3 倍，「测量」是方法论核心

Anthropic 工程博客（09-23，HN 183 分）：两周内把 claude.ai 网页版与桌面端的核心体验做到约 3 倍（p75 口径的几何均值 3.1 倍，网页首屏从 3,085 毫秒降到 550 毫秒）。方法上最有价值的一点：把性能变成可在实验室复现的确定性指标，然后循环执行「找慢点→建基准→加开关上线→读线上数据→把基准要求往下调」；协作方式是人机同频道，agent 负责找瓶颈、写基准、开改动，人负责取舍与批准；两周合并 3,000 多处改动，没有产生客户可见的事故。

这是「agent 主导性能工程」目前最完整的一篇流程披露，可迁移的是「棘轮式基准＋发布开关」的纪律。边界：官方自述；3 倍为 p75 口径。

### 8. Cursor 发布两个「上线后」bot：Rollouts 与 Security Reviewer

Cursor 官方博客（09-23）发布两个常驻 bot：Rollouts 从提交（PR）一路盯到生产——先写监控计划（风险、预期效果、仪表盲区），部署后对比基线，发现回归时归因到具体改动，并按配置执行通知作者、暂停渐进发布或开一个回滚 PR；Security Reviewer 在每个 PR 上用整库上下文找漏洞（注入、鉴权、密钥、反序列化、依赖、配置），每条给严重度、攻击路径与一键修复。两者已在 Teams/Enterprise 套餐提供。

### 9. 「Jev 无法校准」：输出应按分数而非概率使用
