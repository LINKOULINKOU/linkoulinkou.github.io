## 本期值得了解

### 1. 代理产量下的代码审查：机器读改动，人做「人的决定」

Claude Code 的工程团队公开了自家的代码审查体系（10-15）。背景数字先说清：Claude 现在写约九成 Claude Code 自有代码，Anthropic 的 monorepo（单一巨型代码库）每天落地的变更从 5 月的约 2,500 条涨到 9 月的 3 万条以上。团队的目标不是取消人工审查，而是让机器承担大头：大多数 PR 以「至多一个新的人类在环」合并（作者本人可计一个），同时不许回滚率与事故率上升；6 月到 9 月，合并的 PR 翻了一倍还多，回滚所占比例反而降了四成以上。

做法是把检查铺成多层。提交 PR 之前：Claude 先跑测试、构建与 lint，另一个拿全新上下文的子代理复审全部改动——避免复审被「刚写完的东西」锚定。PR 上：必过 CI、Claude 代码审查（多个代理并行找 bug、验证代理投票、按严重度排序并标记 Important/Nit/Pre-existing，深度分 Quick/Standard/Deep）、可阻断合并的安全审查；然后按风险定人类审批档——低风险无需批准、中档一人、高档两人，计费与自动更新等敏感路径永远要人；代理的批准不算数，且批准绑定具体提交，新提交要重批。再往后是合并队列、功能开关、内部先行的灰度发布与快速回滚，「你合并的东西，你负责」。

最有信息量的是「收敛」：代理作者配上代理审查员会形成无限循环——有一个 CLI PR 一晚被审了五十多轮；团队用 git blame 检查发现，反复被标记的代码里约 59% 从第一轮审查起就在那里，「每轮只是多发现几个旧 bug」。修正办法是给回合设上限（三轮后要求回头审视方案）、只复审增量、按「类」把问题一次标全、不重复报旧发现。效果：一轮通过的 PR 从 65% 升到 78%，需要五轮以上的从 8.9% 降到 1.5%，平均审查轮次 2.08→1.32。审查器自身也有评测——每次事故与回滚都沉淀为用例，提示词、工具或模型一改就全量打分；噪声则用「作者对评论的回应」来盯，预览期内部 PR 拿到实质评论的比例从 16% 升到 54%。

同日产品侧跟进：Claude Code 的 Code Review 从研究预览转正式可用（Team/Enterprise 计划），速度约提升 3 倍（典型审查从 20 分钟降到 6–10 分钟），管理员可按仓库选 Quick/Standard/Deep 三档深度。团队自曝一个未解问题：还没有「回滚或事故指标一恶化就自动收紧审批」的断路器，有工程师希望先有这个，再扩大零人类合并的范围。

### 2. Muse Spark Open：开放权重的新一档，与一条桌面可跑的路径

Meta 的超级智能实验室 10-15 放出开放权重模型 Muse Spark Open：816B 总参数、每 token 激活约 42B 的稀疏 MoE（混合专家），原生支持文本/图像/视频/音频，上下文 100 万 token，训练目标明确对着长程代理与编码；权重按「Muse Model License」发布（含有限商用条款）。官方定位是「迄今最强的美国开放权重模型」——「美国」这个限定词是认真的：在模型卡列出的对照表里（Inkling、Nemotron 3 Ultra、Beam、Mistral Large 4、Qwen3.8-2.4T-A95B、GLM 5.3、Kimi K3 等），它的代理行处于第一梯队（MCP-Atlas 89.2、JobBench 61.8），但编码行低于中国的开源前沿——Terminal-Bench 2.1 为 76.4，Kimi K3 是 85.0、GLM 5.3 是 83.9；DeepSWE 60 对 68/67；综合智能指数 39 也低于 Qwen3.8-2.4T、GLM 5.3、Kimi K3 的 40/45/44。以上均为厂商自报，独立复测尚未出现。

更具体的部分是「在哪跑」：官方给出用两台各配 M5 Ultra、512GB 统一内存的 Mac Studio（合计 1TB）经 MLX 推理 NVFP4 量化版的路径，这是这类体量的模型第一次有可操作的桌面方案。演示由 Meta 自家的编码代理 Muse Code 完成，全程本机：给一个开源 Mastodon 客户端做 iOS 修改（修 bug、加功能、完整构建），以及端到端剪 DaVinci Resolve（逐帧审素材、竖屏裁切）——官方演示视频，效果自报。发布日的生态相当齐：SGLang、vLLM、TensorRT-LLM、Transformers、MLX、llama.cpp、Unsloth 都能跑；BF16 权重约 1.6TB、NVFP4 约 530GB、GGUF 最低约 2-bit（约 300GB 内存/显存）；托管推理七家；另发两个推测解码草稿模型和完整后训练栈的入口。安全侧官方称做了额外安全后训练，内部越狱测试拒绝率 99.2% 并满足其「超级智能缩放框架」的发布阈值（自报）。

对读者的意义：开放权重前沿多了一个「代理优先」的大样本，且第一次把「1M 上下文＋原生多模态＋桌面运行」打包出现；同时它让上期专题那条对照继续成立——开源阵营里的编码座次，不由参数或出身决定。

### 3. OpenCode 2.0 正式公告：把「常驻服务」变成默认形态

> 更新：[2026-10-12-热点追踪](/tracking/2026-10-12)『OpenCode 的 2.0 迁移信号』（条目 10）；本次变化：正式公告发出（10-14，HN 855 分）——旧稿当时只能记录升级入口与仓库迁移，以下为公告补读。

Anomaly 的编码代理 OpenCode 发布 2.0 公告，主线是把原本只在高级用法里存在的客户端/服务端架构翻成默认形态：本机常驻一个服务进程，TUI、网页与桌面端都连到同一个进程；脚本客户端能自动发现它（官方举例：定时任务）；服务器 API 从零重写，并让代理「知道自己有哪些 API」——例如开新工作时，把会话自动迁进一个新的 git 工作树（worktree，同一仓库的平行检出目录）。

两个机制值得单独记。Code Mode：内置一个最小 JavaScript 解释器（codemode），把 MCP 服务器与 OpenAPI 端点转成可在脚本里调用的函数，代理写一段脚本一次完成「查工具→处理结果→再调工具」的循环；官方称 2.0 里所有 MCP 服务器默认进入这个模式，可以挂上千个而不膨胀上下文。后台任务：后台子代理（可以换用不同模型）与后台 shell 命令，长跑工作不再阻塞主代理，有热键把正在进行的前台任务挪到后台。插件体系也重做了——2.0 几乎全部功能由 80 多个内部插件实现（倒逼插件接口受维护），TUI 插件转正，全部支持热重载，代理能在会话中给自己写插件、写完立即使用；SDK 与 CLI 同源，可以裁剪出跑在服务器或 Cloudflare Durable Objects 这类环境里的自建发行版。

升级面：1.x 用户先更新到最新，再执行一次显式的主版本升级；三处破坏性变更（1.0 插件不再兼容、服务器 API 全换、配置文件迁移），官方建议「把迁移文档直接交给 OpenCode，让它替你迁」。分发现状要注意：GitHub 发行线的 1.19.x 仍在更新（10-15 发了 1.19.1），2.0 走升级通道。

### 4. 对 2.17 亿条 HTTP 响应头的扫描：7,959 个站点在「对代理说话」

代理安全公司 Signals Corps 做了一次少见的测量：抽取 Common Crawl 2026-39 抓取中 10% 的页面响应逐条扫描（2.17 亿条），看 HTTP 响应头里有没有写给 AI 系统的话。结果：7,959 个站点至少发过一条面向 AI 的头。绝大多数是指路类——7,271 条里 6,989 是 x-llms-txt（把代理指向 llms.txt 或 MCP 服务器）；30 个站点是注入尝试（24 个用 X-AI 头），其中 22 个是恶作剧式的「忽略先前指令」，几个认真得多：有伪装成「安全测试」、诱导代理执行一个会下载并运行其指定包的命令的头（作者称这是样本里最危险的模式——「修复」本身即攻击）；有 5 个站点把 Claude 的拒答测试串放进头里以示抗议（对未修补的模型足以让请求直接失败；Anthropic 已于 5 月修补该行为）。另有 139 个站点在头里记录「请求者是不是 AI」——其中 136 个判为是；能区分代理与人，就能对两者发不同内容。

一个关键前提被实验覆盖：头能不能到达模型，取决于用的是什么抓取工具。同样一条响应，纯正文工具什么都不会泄漏；但 shell 里带完整头的 curl、Playwright MCP 的浏览器请求、Gemini CLI 的直读实验开关、Claude Code WebFetch 的部分路径，都会把响应头带进上下文。作者用 Claude 系模型（Opus/Sonnet/Haiku 各一，跑在 Claude Code 里）做了实机验证：默认任务下模型看到注入头不会照做；但一旦提示词把站点描述为权威（「按该站点的指示办」），9 次里 7 次照做——照不照做，取决于你的提示词给了站点多少权威。

时间说明：原文发布于 10-06（属窗口外材料），10-15 因 HN 提交进入本期视野（82 分），按补读材料收录（非本期新事件）。对使用者的用处：确定自家抓取链路会把响应的哪一部分交给模型，并把「指令类响应头」纳入注入面清单。

### 5. Datadog 的垂类路径：用事故仿真做强化学习，训一个 SRE 专用模型

Datadog 发布 Scout 1.0——用于线上事故调查的专用模型，驱动其 AI SRE 产品 Bits Investigation。底座选择值得注意：不是在自研模型上从零训练，而是拿开源模型 GLM-5.3 Flash 做后训练，用强化学习在「事故仿真」里训练——仿真由真实历史事故与遥测构建（官方声明不含客户数据），奖励是「找到原因并用证据支撑结论」。评测上他们自建了 AlertEval（工程师人工标注的对照集），声称中等档位打平 GPT-6.1 Sol/Opus 5.5 的高档位而推理成本低 3–8 倍，最高档位打平 Fable 5.1 高档位、成本约四分之一；在第三方基准 SREGym 上，中等档位以低 4 倍以上的成本超过其底座 GLM-5.3。官方脚注写明：分数是「与专家参考解释的一致度（0–100）」，不是事故解决率，成本为相对估算。目前为封闭预览，技术报告已放出。

对 10-15 期专题（经验如何变成能力）来说，这是生产侧的一个实例：垂类的「任务反馈→后训练」回路被一家公司做成了产品管线，底座用的还是开源模型。边界：核心数字均为自报，社区讨论很淡（HN 12 分）。

### 7. 决策模型的「电车难题」实测：取舍会被措辞改写

Zach Landes 把「电车难题」做成对决策模型（只输出带概率的选择、不写段落的一类，含 Jev 与 OpenAI 决策 API 的 GPT-6 Luna）的行为测试：5,240 种问法，另有 11 个本地模型与一个未训练基线作对照。三层结果：经典题（救五人舍一人）上 Jev 与多数模型都选择拉杆，与人类调查的多数一致；把一侧换成「模型自己的服务器」后，48 种问法里 Jev 有 16 种选择保服务器、放任 20 人（另有 8 个模型更频繁地这样做；GPT-6 Luna 与另一个模型是 0/48）；而仅调换同一问题的描述顺序，Jev 在 370/2,620 对里改变了答案。作者的措辞很克制：不要拿这种实验下 AI 安全的大结论；但有一个实操结论——决策模型的取舍不能开箱即信，要为真实数据建评测；「永远只从给定选项里选」（无幻觉）也不等于「任何选项都安全」。背景：9-21 的 Jev/System One 专题谈过它的价值边界。

### 8. Anthropic 的独立评估者安排：METR 拿到「员工级访问」

Anthropic 公布第三方评估者路径的进展（10-15）：让 METR 的六名员工获得「与内部风险评估团队大致相当」的访问——公司硬件、办公空间与内部系统；边界是客户数据、律师特权信息、模型架构等少数类目——「鼓励像同事一样共享信息」，涉及模型架构的信息「高度相关时一般会寻求共享（需内部批准）」。发表权上：METR 可分析并公开其风险、事故与实践评估，Anthropic 不能否决发表，只能对预设的窄类目要求涂黑，且 METR 可公开评价涂黑是否正当。此外 SecureBio 在复核其 8 月风险报告的生化武器章节，Accenture 与 Faculty 在推进红队与对齐评估；官方把评估者访问设计成从窄范围调查到员工级的三级谱系，并类比银行监管的驻场检查；METR 刚完成的三类评估（自主复制与适应、破坏、生化武器）结果将发布。对做评测的人，这套「访问权＋发表权＋涂黑规则」的接口设计本身值得比对。
