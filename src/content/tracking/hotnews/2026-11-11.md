这一周最重的一条是验证：Google DeepMind 让跑在 Gemini Carbon 上的 agent 在四周内产出 600 多万行 Lean，把 Signal 协议的实际实现证到「设备被临时攻破前后消息仍受保护」这一层，人类只审 agent 标出的 1%。产品侧，Antigravity 的 `/swarm` 把「一支 agent 团队」做进 IDE，用共享只追加消息板和 git worktree 解决协作与冲突；决策模型拿到标准接口，不再靠模型「按 JSON 老实输出」；浏览器四家把平台知识做成 agent 技能。发布速览收 Carbon、Muse Ember、Qwen Code 与 Kimi Code。

## 本期值得了解

### 1. 四周、600 万行 Lean：agent 证完 Signal 协议的实际实现

Google DeepMind 11-10 公开 AlphaProof Code，一个多 LLM 的 agent 框架，把形式化验证拆成研究团队式的分工：人类专家先与一组模型合作，把 Signal 协议的安全目标写成形式化规约，逐条审核；之后由跑在 Gemini Carbon 上的 agent 完成证明，产出超过 600 万行 Lean。Lean 自动检查绝大部分，agent 再标出约 1% 的代码库供人复核，专家只审这部分。

关键在验证的层次。多数协议验证停在设计层，这次证的是实际编译后运行的代码满足「设备被临时攻破前后消息仍受保护」这类性质，把设计与实现之间的缝隙也覆盖了。作者称这是首次用 AI 对广泛部署的密码协议做到这个深度，四周完成过去要专家团队数年的工作。为确认不是自说自话，他们把两个已修复的真实漏洞重新注入隔离版本，系统都给出了「该版本不安全」的机器可检证明。验证产物已开源。

来源：[Introducing AlphaProof Code](https://deepmind.google/blog/introducing-alphaproof-code/)｜Google DeepMind｜2026-11-10；[HN 讨论](https://news.ycombinator.com/item?id=50439193)（578 分、177 评论）

### 2. /swarm：协调者在 worktree 里开工人，验证者专门挑刺

Google 11-10 在 Antigravity 里预览 `/swarm`：一条提示交给一个协调 agent，它按角色拉起并行 worker，每个 worker 在独立的 git worktree 里改代码，改动不会互相覆盖；另有一组专职「对抗验证」agent 跑测试、质疑 diff。agent 之间不靠逐级转述，而是在同一块只追加的消息板上直接协作；空闲 agent 以零 token 挂起，有人需要输入时立刻唤醒。团队可以按角色钉不同模型：Carbon 做协调、架构、审计与对抗验证，轻量模型做并行的文件编辑。

可观察性也做进了产品：侧栏的 Board feed 看争论、Members roster 直接跳进某个 agent 的轨迹接管、Graph replay 回放团队从 brief 到验证通过的收敛过程；CLI 里用 `/swarm board` 或 Alt+S。

五周内部试用里，Google 工程师用它做多包迁移、跨子系统根因和架构重设计。

来源：[Gemini 4 Carbon and /swarm](https://antigravity.google/blog/gemini-4-carbon-in-google-antigravity)｜Google Antigravity｜2026-11-10；[Gemini 4 Carbon is now available](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/)｜Google｜2026-11-10

### 3. 决策模型有了标准接口：给选项打分，而不是让模型「说」

Hugging Face 11-10 把「决策模型」做成 transformers 的一等任务：输入一段 state 和若干命名问题，每个问题带自己的类型——`choice`（在给定选项里选）、`score`（有序档位，返回期望值）、`noul`（对一句话成立的概率）——模型返回选择、置信度和每个选项的概率，全程不生成文本。

接口已经落到具体工具上：`pipeline("decision")`、`AutoModelForDecision`；`transformers serve` 和 llama.cpp 都提供 `/v1/systemone`，两边请求体一致；Hub 新增 decision 模型标签，既有 ModernBERT 这类编码器，也有从生成模型改出来的版本；微调可以直接用 Trainer，对一个 choice 问题就是选项上的交叉熵，TRL 的一等支持还在 PR 里，Unsloth 另有把生成模型加上决策头的配方。

一个容易被忽略的实现细节：普通自回归模型也能走这套接口。transformers 自己构造决策提示，对答案标签的 logits 做一次批量前向再 softmax，不采样、不生成，返回的 usage 里 `output_tokens` 是 0。这让「先判后送检」的级联不必再依赖模型老实输出 JSON，概率可以直接当阈值用。

来源：[Decision Models in Hugging Face](https://huggingface.co/blog/decision)｜Hugging Face｜2026-11-10

### 4. 浏览器四家把「现代 Web 用法」做成 agent 技能

HN 11-10 上 263 分：Chrome、Edge、Firefox 与 MDN 团队共同维护的 Modern Web Guidance，把约 250 个现代 Web 特性整理成一组 skills，装进 coding agent。动机写得很直白：训练数据里堆满旧代码，agent 会默认写出 2019 年的实现，为浏览器已经原生支持的东西引入几十行 JS 或一个依赖；就算模型知道某个 API，也缺少可直接上生产的用法密度。

做法不是把文档整篇塞进上下文，而是让 agent 按需检索：`search` 找相关指南、`retrieve` 取回单条，另有 `legacy-scan` 扫出代码库里的旧模式。指南按 token 效率设计，用评测把模型已经会的内容剪掉，项目还公开了 eval dashboard。覆盖 CSS、HTML/DOM、JS/API、表单、可访问性和浏览器内置 AI。

来源：[modern-web-guidance](https://github.com/GoogleChrome/modern-web-guidance)｜GoogleChrome（Chrome/Edge/Firefox/MDN 共同维护）｜2026-11；[HN 讨论](https://news.ycombinator.com/item?id=50443812)（263 分、77 评论）
