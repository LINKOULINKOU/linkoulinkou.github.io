这期最值得看的是两条「把模型放进循环里」的做法：Genie 4 让 Gemini 3.8 Flash 在世界模型外面当指导者，逐帧核对每一小步是否做成；Codex 把记忆写入拆成提取与合并两段，各段可以指定不同模型，合并那一段是在带写权限的沙箱里跑的一个 agent。另外两件事都在定义谁能设默认：Copilot 把命令权限的初判交给分类模型并允许企业改默认档位，Kimi Code 把「进入计划模式」的决定权从模型手里收回。

## 本期值得了解

### 1. Genie 4：世界模型外面套一个逐帧核对的 agent

10-27 发布的 Genie 4 是实时交互式世界模型，按键盘操作与文本指令逐帧生成可玩场景，原生带音频（环境声，以及会随场景互动的角色对话），并声称在空气动力、碰撞这类物理表现上更逼真。技术上它把 Gemini 家族拆了工：Gemini Omni 负责把画面锚定在真实世界的样貌与行为上，其他 Gemini 模型负责维持模拟的连贯与延续。

与 agent 直接相关的是这段架构描述：**Gemini 3.8 Flash 在循环里当指导者**——Genie 4 实时生成世界的同时，3.8 Flash 持续观察画面、把目标拆成一串步骤、再回看新到的帧来跟踪进度并核对每一步是否真的做成；世界状态或用户操作一变，它当场改计划。官方把用途写成两句：为机器人和 agent 造训练环境；在把 AI 系统放进真实世界之前，先在可变的模拟里测它怎样应对不同环境。

判断边界：这是研究预览，先给受信测试者，随后才轮到 Google AI Ultra 订阅者的 Project Genie 与 Gemini API／AI Studio 的早期伙伴，还要排队申请。官方没有披露生成延迟、帧率、单场景成本，也没有给出任何「用 Genie 训练出的 agent 变强了」的对照数据——「训练环境」目前是能力主张，不是已发表的实验结果。讨论度很高（Hacker News 970 分、555 条评论，截至 10-28 23:59），但高讨论不等于上述用途已被验证。

### 2. Anthropic 的药物研发进展：文档核对有硬数字，分子设计靠 Claude Code

10-27 的这份更新列了六个合作方（BigHat Biosciences、Bristol Myers Squibb、Divergence Labs、Enveda、Generate Biomedicines、The Column Group），加上 Anthropic 自己收购的一人公司 Mithril Medicine。它想说明的不是「AI 能设计分子」，而是把药物开发拆成一串任务后，agent 分别能接下哪些。

数字最硬的是 Enveda 的文书环节：制造化学家原本最多 75% 的时间花在文书上。他们把全部制造文档接到 Claude，让它标出可能的问题，在一千零六十一页文档上测试，Claude 找全了人工复核者发现的 11 个问题，另外标出 7 个人工漏掉的；人工复核时间从 25 小时以上降到 3 小时以内，官方口径是减少 89%。同一套东西还写了两份监管文件初稿：一份 4 小时完成，手工约需三个月；另一份经人工复核发现一处小错——这一句比前面的百分比更有信息量，说明复核环节没有被取消。

分子设计这边是 Generate Biomedicines：六名科学家用 Claude Code 提出 CAR-T 疗法的构件设计，其中一个设计比标准版短约 70%，体外测试里让免疫细胞表面的受体数量增加约十倍、杀伤肿瘤细胞更有效、维持活性更久。Mithril 更接近运营案例：一人公司用 Claude 管合同、物流与 11 家外部实验室，18 个月内把一种肌营养不良的候选药物从想法做到小鼠身上的初步结果，预计最早 2028 年底进入人体临床。

判断边界：全部处于临床前阶段，效果数字由 Anthropic 与各合作方自报，细节推给各自的技术报告；「4 小时对三个月」是初稿时间，不含后续修订与审评；这一轮没有出现任何「agent 自主决定实验方向」的描述，人仍在复核、签字与选方向的环节上。

### 3. Codex 的记忆写入拆成两段，各自可指定模型

读 `openai/codex` 主分支可见，记忆写入在 `codex-rs/memories/write/` 下分成两段。第一段在启动时领任务：`phase1.rs` 用 `config.memories.extract_model`（未配置时取 provider 的 `memory_extraction_preferred_model()`）跑一次严格结构化输出，同时负责清理过期条目。第二段 `phase2.rs` 才是合并：用 `config.memories.consolidation_model`，输入按 `max_raw_memories_for_consolidation` 的条数上限与 `max_unused_days` 的天数上限选取，靠水位线推进，并且**以 agent 的形式在沙箱里跑**——未显式跳过沙箱时默认 `WorkspaceWrite`，推理档位与服务档位分别由 `stage_two::REASONING_EFFORT`、`consolidation_service_tier` 给出。

值得比较的是这个形状本身：提取可以便宜、快、只看单条；合并要跨条比较、要写文件、还要多步动作，于是它被做成一个有工具与写权限的 agent，而不是一次补全。两段分离也让「用哪个模型」变成两个可独立调的旋钮。第三方梗概帖（10-27）称默认提取用 GPT-5.6 Luna、合并用 GPT-6.1 系模型，并给出 `config.toml` 的键名——键名与两段结构能在源码里对上，具体默认型号属 B 级说法。

边界：以上是 main 分支源码事实，不等于已发布到你机器上的版本默认行为；社区帖给的是配置覆写方法，不是官方文档。

### 4. 命令权限交给模型初判：Copilot 转正式可用，另一头已有人在线这么用

GitHub 10-26 把 assisted permissions 转正式可用，覆盖 Copilot CLI、Copilot app 与 VS Code。机制是：当 Copilot 请求执行命令、访问某个文件路径或打开 URL 时，先由一个语言模型评估这次请求，判为「明确安全」的自动放行，其余仍要人批准。企业侧可屏蔽 Allow All 而保留 Assisted，也可单独关掉 Assisted，还能设定新会话的默认权限模式；默认模式不可用或被策略禁止时，会话退回逐条手动批准。

同一批讨论里还有一处同型用法：一位工程师说他用 Decisions API 给用于修复主机与集群问题的 RShell 命令打分，原本离线做，现在因为够快、准确度够（配上好的置信阈值）改成在线。这与 Copilot 是同一个形状——把「这条命令能不能跑」变成一次模型判断——区别在于一个内建在产品权限层，一个是自己接的判定服务。

判断边界：GitHub 没有披露用的模型、阈值与误放率；那位工程师只给了定性描述，没有阈值、样本与误判率。这类设计的风险我们 10-25 那期记过一次：同一个 Decisions API 在 3,600 道题的第三方测试里，自报置信度 99% 以上时实际正确率只有 68%。闸门交给分类模型，省下的是确认次数，付出的是可测性。

### 5. Kimi Code 2.4.0：会话可跨产品导入，计划模式改由人开启

10-28 的 2.4.0 里有三条与运行框架的所有权有关。第一，新增 `/import-sessions`（命令行同名），可以导入 Claude Code 与 Codex 最近 15 天或 30 天的会话——把别家的会话历史搬进自家，等于承认会话记录已经是可迁移的状态，而不是产品私有物。第二，Plan mode 收紧：只有用户主动开启才进入，每个计划都等人评审；agent 不能再自己进入计划模式，Never Ask 也不再自动批准计划，非交互运行默认跳过它。第三，并发默认值从 16 提到 256，同时支持已有的运行上限与按次选择模型。

前两条合起来是一个方向的两次收紧：一边让会话状态更容易搬走，一边把「什么时候进入计划、计划算不算批准」的决定权从模型手里收回。第三条是相反方向——把默认并发放宽两个数量级，代价与风险也随之换了默认值。发行说明没写这些改动的理由，也没说明跨产品导入的保真度（工具调用、附件、审批记录是否保留），这条只能算可观察的产品决策。
