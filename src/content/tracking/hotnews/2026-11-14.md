今天最值得看的是两处「换掉调用方式」的改动：Antigravity 的 Orchestrator 不再静态路由，而是在同一条轨迹里让 Carbon 与 Hydrogen 双向交接；DeepSeek 把 App 里的搜索、文件、URL、安全与语音能力做成 API 的内置工具。另有一条回退：Claude Code 2.1.323 移除了子代理状态行；以及 LLMON 用特殊 token 给上下文加结构、ChatGPT Wallet 给出 agent 支付的凭据方案。

## 本期值得了解

### 1. Orchestrator：同一条轨迹里让两个模型来回交接

Google 11-12 随 Gemini 4 Hydrogen 在 Antigravity 推出 Orchestrator：不再用静态路由按首条提示猜难度，而是在同一条轨迹里让 Carbon 与 Hydrogen 双向交接——Carbon 先只读探索、解决歧义、定计划，Hydrogen 接手写代码、更新依赖、跑测试，遇到阻力再交回 Carbon 修计划后继续。官方称在 Terminal-Bench 上接近 Carbon 的成功率，同时平均少用 24% 配额、快 19%；需要并行时，Carbon 做协调者，Hydrogen 做 worker 与验证者。这比「按首个提示选一个模型跑到底」多了一层：难度是在执行中暴露的，换模型也发生在执行中。

来源：[Gemini 4 Hydrogen and Orchestrator](https://antigravity.google/blog/gemini-4-hydrogen-in-google-antigravity/)｜Google Antigravity｜2026-11-12；[Gemini 4 Hydrogen](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)｜Google｜2026-11-12

### 2. DeepSeek 把 App 的搜索、文件、URL、安全与语音做进 API

DeepSeek 11-13 发布全功能 App API：V4.1-Flash（deepseek-flash）在 Messages、Responses、Chat Completions 三个入口里内置联网搜索（带引用）、深度思考搜索（多步推理里边搜边读）、文件输入（PDF、Office、图片）、URL 读取与输入输出安全筛查，工具调用与上下文组装都在服务端完成；用 `deepseek_web_search`、`deepseek_read_url` 等参数开启，面向公众的应用必须开安全筛查。搜索、抓取、OCR、ASR、TTS 另有独立 API，工具用量在 token 之外单独计费；官方还开源了前端 demo，支持导入 DeepSeek 历史会话。

来源：[The full DeepSeek App experience, now via API](https://api-docs.deepseek.com/news/news261113)｜DeepSeek｜2026-11-13；[构建指南](https://api-docs.deepseek.com/guides/build_a_chatbot)

### 3. Harness Leaderboard：同一个模型，换个 harness 排名就翻

一个 11-13 更新的公开榜把 8 个 coding-agent harness 跑在同一个开放模型、同一 reasoning effort 上，三次尝试、给出置信区间，轨迹全部公开；每个格子 594 次尝试。v0.1.6 里，Hermes 在 DeepSeek-V4.1-Flash 上从第一掉到第九，在 Flint 上又排第一（与四个并列）；OpenClaw 升到 2026.11.1 后在 V4.1-Flash 上从 33/38 升到约 54。榜还单独列「harness vs 噪声」：换 harness 带来的任务翻转如果没有超过同一 harness 重跑，就说明差异在随机范围内；另有 38 次通过被 atif-scan 判为作弊。

来源：[Harness Leaderboard](https://joelniklaus-harness-leaderboard.hf.space/)｜2026-11-13；[HN 讨论](https://news.ycombinator.com/item?id=50484709)

### 4. Claude Code 的 Code Mode：模型写 JavaScript 调工具

Claude Code 2.1.323 加入实验性 Code Mode：开启后 Claude 写 JavaScript 来调用工具，而不是逐条发起工具调用；默认关闭，需要按文档开启，组织也可以统一关掉。官方 changelog 只有一句说明，文档链接目前返回 404，JavaScript 在什么沙箱里跑、工具如何桥接、失败如何回传都还没有公开。它的意义在于把「多步工具编排」从模型逐轮决策挪到一段代码里，和 Orchestrator 的动态换模型是同一个方向：减少每步都走模型的固定成本。

来源：[Claude Code v2.1.323](https://github.com/anthropics/claude-code/releases/tag/v2.1.323)｜Anthropic｜2026-11-12；[Code Mode 文档](https://code.claude.com/docs/en/code-mode)（当前 404）

### 5. ChatGPT Wallet：agent 付款不拿卡号，每笔都要本人确认

OpenAI 11-13 发布 ChatGPT Wallet：用户绑一次卡，之后每笔由 agent 发起的购买都要本人核对商品、金额与卡，并用 Face ID 或指纹确认；支付网络返回一个代替卡号的 payment token，商家只拿到 token，拿不到真实卡信息，原有卡权益与争议保护保留。首批与 Amex、Mastercard、Visa 合作，先通过 dots 向美国 ChatGPT Pro 用户开放；OpenAI 同时给商家发了接入指引，要求风控能识别「agent 发起的合法购买」。它补的正是前一天「航司与银行封堵 agent」里缺的那块：可验证的授权与受限凭据。

来源：[Introducing ChatGPT Wallet](https://openai.com/index/introducing-chatgpt-wallet/)｜OpenAI｜2026-11-13

### 6. 同一版本移除了子代理状态行：每个子代理的上下文与花费看不见了

2.1.323 还移除了 `subagentStatusLine` 设置，没有替代，子代理行固定用默认样式；settings 里残留该键会静默失效，启动时没有警告。issue #109446 指出，这是 Claude Code 里唯一能按运行中的子代理看到上下文占用、已花 token 与美元、模型与 effort、状态与缓存命中的地方；2.1.322 仍会执行该命令，2.1.323 不再调用。多后台代理的会话从此看不到哪个代理快撑爆窗口、哪个切到了贵模型、哪个在重复付缓存过期的钱。

来源：[issue #109446](https://github.com/anthropics/claude-code/issues/109446)｜2026-11-13

### 7. LLMON：用特殊 token 给上下文加结构，顺手压住间接注入

IBM Granite 11-12 放出 LLMON（LLM Object Notation）：用保留的特殊 token 包住有语义的标签，把数据 schema、嵌套和唯一 ID 显式写出来，让一条指令能指向上下文任意位置的数据并绑定作用对象。官方称隐藏在用户数据里的间接注入大多会被模型忽略，因为指令与数据的分界不再靠自然语言约定；同时放出两个预览模型 granite-4.1-3b/8b-LLMON-preview 和一个工具包。它针对的是「上下文结构靠 JSON 与约定、模型只能猜」的老问题，代价是需要模型专门训练过才认这套标记。

来源：[LLMON: An LLM-Native Markup Language](https://huggingface.co/blog/ibm-granite/llmon-an-llm-native-markup-language-now-in-granite)｜IBM Granite｜2026-11-12

### 8. 安全评测怎么建：Anthropic 给了一份施工规范

Anthropic 11-13 的工程文把安全评测当成一门需要改革的测量学：评测容易被 game、不总是测它声称测的东西、记录不足到无法复现，连选项顺序都能改变结果。它借心理学复现危机后的做法，建议先预注册假设与分析计划，再按设计、运行、报告三段执行，并给出系统卡里的实例。对做 agent 评测的人，可直接迁移的是「先写判据再跑」和「把失败样本与运行条件一起公开」这两条。

来源：[Building strong safety evaluations](https://www.anthropic.com/research/building-strong-safety-evaluations)｜Anthropic｜2026-11-13

### 9. PostHog 的决策模型用法：98.7% 的摘要完全跳过 LLM

PostHog 11-09 的实战笔记给了决策模型（Jev）的四个用法：给贵模型做闸门、做模型路由、做表面检查、替代过强的 LLM。生产里最具体的一个是会话摘要的 PII 闸门：每条摘要先过两个 yes/no 问题「是否出现真人姓名」「是否包含联系方式或证件」，任一得分 ≥0.4 才交给 Gemini 重写并复检，否则直接放行；结果 98.7% 的摘要完全跳过 LLM。作者称决策模型比前沿模型便宜最多 444.6 倍、快 193.6 倍，同时提醒它们会犯错、路由时不能假设可互换。

来源：[Not everything needs an LLM](https://posthog.com/newsletter/decision-models)｜PostHog｜2026-11-09

### 10. 玛雅遗址被核查为「重新发现」：agent 漏了已发表的论文

The Verge 11-12 核查后确认，那处玛雅遗址去年已在学术期刊发表，并非新发现；考古学家批评业余者带着 AI 闯入专业领域、把已知遗址当成果。作者 Miotti 对 The Verge 说这是个人副业、没有使用 Google 的计算资源，并称已向 INAH 查过登记。这是对 11-12 稿第 4 条的更正：48 个 agent 看图找候选的流程成立，但「查文献确认未登记」这一步漏掉了已发表论文，而这一步恰恰最需要领域知识。

来源：[No, AI agents did not discover a previously unknown Maya site](https://www.theverge.com/ai-artificial-intelligence/1032125/ai-agents-maya-site-archeology-discovery)｜The Verge｜2026-11-12

### 11. 航司与银行开始封堵个人 AI agent

PCWorld 11-13 汇总：United 禁止第三方个人 AI agent 代订机票，理由包括凭据共享、误购，以及 FAA/DOT 要求本人确认行李声明；Bank of America 警告不要把账号交给包括 AI agent 在内的外部服务，JPMorgan、Charles Schwab、Citi 已直接禁止；Amazon 封禁 Meta 的 Muse，Yelp 只允许签约合作方。共同点是 agent 没有可被识别的身份与受限凭据，平台只能用「禁止登录」来兜底——这正好是 ChatGPT Wallet、MCP 的 OAuth 委托与 agent 支付协议想补的空位。

来源：[AI agents have a big problem: Nobody wants to let them in](https://www.pcworld.com/article/3283946/ai-agents-have-a-big-problem-nobody-wants-to-let-them-in.html)｜PCWorld｜2026-11-13
