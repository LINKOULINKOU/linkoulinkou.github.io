## 本期值得了解

### 1. 上下文工程现状：六种处理从提示词搬进运行框架

Drew Breunig 在 10-24 的 MCP 会议（AGNTCon）上讲了一份现状梳理，10-26 凌晨被提交到 Hacker News 后拿到 80 分、22 条评论。他要回答的问题是：模型上下文到了百万 token 之后，为什么"把东西全塞进去让模型自己理"反而更常出错。

他把旧问题归成四类失败模式，每类都给了一个可以对照的现象。上下文中毒（poisoning）：错误事实一旦进了上下文，模型就绕不过去——Gemini 2.5 在技术报告里玩《宝可梦》时，因为训练数据里另一版本的游戏需要给守卫送冰茶，它坚信当前版本也要送茶，在待办里写下这条之后花几个小时找茶，尽管手上的版本需要的是柠檬水。上下文分心（distraction）：上下文一长，模型开始更信上下文而不是自己的先验；他引了一项指令跟随实验，让模型"把每个问题翻译成俄语回答"，再在对话里堆一批法语回答的示例，示例只要几张，小模型遵循指令的比例就掉到一半以下，而强模型需要更多示例但同样会掉。上下文混淆（confusion）：与任务无关的信息改变模型对你的假设，比如同时记录工作和家庭两套项目笔记，模型会把两边串起来。上下文冲突（clash）：运行框架里的工具、技能和资料互相打架。

对应的六种处理办法，他的排序是从"往上下文里加"到"从上下文里减"：检索增强、工具装载（按任务裁剪暴露给模型的工具与技能）、上下文隔离（给子代理一段空白历史但共享环境）、剪枝、外置（把信息存进文件或数据库）、摘要（也就是常说的压缩）。其中两处细节有实操价值：一家企业的代理突然表现变差，排查发现是启动时给每个工程师加载了 600 个技能；而压缩一般会先剥掉不需要的工具返回，再总结剩余的对话。

真正的主张在"这些办法搬到哪里"：他认为 2023 年叫提示词工程、2025 年叫上下文工程，现在的工作重心是把上下文装配从概率性的模型调用挪到确定性的代码里。他用 DSPy 写了一个演示：一个 ReAct 循环，大模型负责干活，另一个小决策模型（Jev，一种专门做快速判定的模型）被反复调用做三种判断——这个工具对当前请求需不需要、这条历史还要不要留、压缩前哪些片段值得留。四处改动合起来大约 16 行，四个修法、一个循环。

他据此提出两种新失败模式，其中第二种是这轮讨论里最具体的一条。"对抗权重"（fighting the weights）：模型在不熟悉的工具上会先犯错再纠正，因为训练环境里的工具长得不一样；他的判据是翻系统提示词——如果同一句要求被反反复复写、还带全大写，多半是在和训练出来的倾向较劲。他举的例子是 Claude Code 的提示词与工具说明里"独立调用请并行"这句话被分别重复了七次、四次、两次、三次。

"上下文惯性"（context inertia）：模型会盯住一个假设或子任务不放，过了该停的时候还继续试同一件事。他给的可核来源是 Anthropic 10-12 那份自我复制实验报告里的编排器 Memento——它是搭在开源 Pi 编码代理上的运行框架，测试中发现代理跑久了会陷在一个子任务上反复试同一做法，于是改成每隔 1.5 小时让代理写一份短笔记、清空对话、保留工作区，下一个周期从新视角重新开始（这份报告 10-14 期已收录，此处补的是编排细节）。报告里对应的数字是：搭建推理服务这项任务上，六代 Qwen3.5-9B 各自继承上一代的笔记，完成率从第一代的 45% 升到 61%–84%。他说同期还有另外几组人独立走到"定期清空上下文、保留环境产物"这条解法上；其中未正式发表的预印本按本工作区的论文门槛没有展开核验，本文只用 Memento 说明机制。他自己现在的经验法则也更粗：上下文到二十万 token 附近就该考虑重开，而不是继续在八十万 token 里找 bug。

值得了解的地方不在术语新，而在这套东西给出了可检验的判据：提示词里的重复和全大写是训练偏好的反证，长上下文里的小错误会累积成行为漂移，而"清空对话、保留环境"这种粗糙做法按作者的说法已被多组人独立采用，Memento 是其中能查到原文的一例。限制也在这里：16 行的演示没有公开代码，小模型逐轮判定工具与历史的漏判率和延迟没有数据，600 个技能那类例子是咨询中的个案，Memento 的收益只在它自己的测试台上测过，作者也注明这套编排并非普适的强框架。

### 2. 给人工审批算风险：farol 把合并风险排到文件级

代理写代码、代理审代码之后，剩下一个人决定"合不合"。farol 这个 10-21 才建仓的工具（CLI 与 GitHub Action，117 星）就针对这一步：它跑在 AI 审查之后，用静态分析看这次改动碰了哪些文件、每个文件的风险有多高，给审批者一张按风险排序的清单，让低风险的小改动快速通过、高风险的文件被逐行读。这个切分有道理——审查代理擅长评论具体行，但很难替审批者回答"接受这次改动有多危险"。它还只是一个九次提交的新项目，风险评分怎么算、误报多少都没有独立评测，Show HN 上的 60 分、37 条评论只能说明有讨论。
