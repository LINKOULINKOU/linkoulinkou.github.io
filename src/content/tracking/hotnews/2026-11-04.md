这两天几乎只有一件事值得展开：MIT CSAIL 的一篇研究博客声称前沿模型能直接读写神经网络权重——只看原始权重就能说出网络在玩什么游戏，还能在不做梯度下降的情况下把 Qwen3.5-0.8B 的 MATH-500 从 7.9% 提到 48.1%。它在 Hacker News 上拿到 2,924 分，隔天又被 spaCy 作者 Matthew Honnibal 以 916 分的专文反驳「misleading」。争的不是数据造假，而是**这到底算不算一种能力**：所有涉及真实语言模型的实验都用了 Python 和若干次前向传播，真正「只看原始权重」的只有几万个参数的小网络。另一条短讯是 Claude Code 修了一个空闲压缩的 bug——它会把会话替换成一条不是摘要的回复。

## 本期值得了解

### 1. 权重空间编程：一个 2,924 分的声明，与一份 916 分的反驳

先说原报告做了什么。作者是 Rikiya Takehi、Jayden Teoh、Alex Zhang 与 Omar Khattab（MIT CSAIL），11-02 发布在个人博客上，标题为「Sparks of Weight-Space Programming」，并公开了全部实验日志与在 Hugging Face 上重建的被编辑模型。它把结论分成三档：

- **读权重**：给 GPT-6 Astra 四个用 PPO 训练、输入输出与网络结构完全相同的游戏策略网络（500→32→32→5，17,253 个权重），只把权重当文本喂进去，它能说出各自是哪个游戏；扩散模型（23,824 权重）只给权重，它能说出生成的是圆、方还是三角形；字符级语言模型去掉输入输出层、只留四个 transformer block，它能认出训练语料是 Python、罗马字日语还是英语，并指出复制头（copying head，让模型重复前文的结构）在哪一层哪个头——与实测一致。
- **改权重**：一个卡在坡道前的 PPO 小车策略，Astra 只改 3.5% 的权重，让 1,024 个测试回合全部成功；Qwen3.5-0.8B 在 MATH-500 上只有 7.9%，Astra 定位到「思维循环」这个病灶，从第 15、19 层 MLP 写出的一个方向下手，减掉 64 个输出列（131,072 个权重，占 0.016%），MATH-500 升到 48.1%、GSM8K 从 13.8% 到 67.1%、IFEval 从 21.0% 到 62.3%。
- **从零写权重**：MinAtar 三个游戏，只给规则、源码与网络形状，不给数据、损失、梯度与工具，Astra 直接以文本写出权重，在三个游戏上都超过训练一亿步的 PPO；9×9 围棋网络（148 万权重，超出上下文）改成在 Python 沙箱里写，允许 0 到 50 次前向传播，50 次时超过同规模、训练两千万局的 PPO。

报告自己也留了负面证据，这点很重要：Qwen 的收益来自**把循环去掉**——编辑前 93% 的 MATH-500 回答撞满 32,768 token 上限，编辑后降到 33%；作者补了一句「修掉循环不等于让模型更会做数学，它只是让模型能把本来就会的题做完」。他们又拿不循环的 Gemma 3 270M 做对照（只有 8.5% 撞上限），同样流程下 MATH-500 从 6.8 只挪到 7.0–7.7，Astra 自己都报告「提升不成立」。结论写得很克制：编辑权重能移开挡住能力的障碍，但不能凭空加进能力。

反驳的靶子是**框架**，不是数字。Honnibal 逐条列了八个实验的设置：真正「原始权重进上下文、无工具、不跑网络」的只有实验 1、2、4，规模在 1.7 万到 17 万个权重之间；凡是涉及真实语言模型的（实验 6、7、8），Astra 都拿到 Python 沙箱，Qwen 那个还额外获得最多 50 次前向传播、每次 512 道练习题。他的核心论点是：摘要把这些混成一句「just by looking at the raw weights」，读起来像一种统一的技术；实际上这是两种不同的能力——一种是对小网络权重的直觉，另一种是「LLM 被提示去做一个 ML 工程师会做的事：写代码分析甚至改写权重」，后者不平凡（一两年前的模型做不到），但不该和前者塞进同一篇。他还指出 MinAtar 那组被标题化了：只有 Breakout 大幅超过 PPO-5 亿步（517 对 25），Seaquest 与 Asterix 是输的（53 对 89、53 对 55）。

这场争论值得读的地方在于「什么才算证据」。双方对实验设置没有分歧，对数字也没有分歧；分歧在**归因**：如果结论成立需要一种技术同时做到「从小网络里读出结构」和「改好一个 8 亿参数模型」，那么现在的证据是两套方法各做一半。能分辨的实验其实很清楚——让模型在只有原始权重、没有 Python、没有前向传播的条件下改 Qwen——但作者没做，也没有解释为什么做不了。反过来，原始数据里还留着一个双方都没拆开的问题：Gemma 对照说明这套编辑「只移开障碍」，那么 0.016% 的编辑把 MATH-500 推到 48.1% 这件事里，「能做完」与「做得对」各占多少，现有表格没有分开。

判断边界：这是一篇带日志与模型产物的研究博客，不是同行评议论文，也不是 arXiv 预印本；数字可追溯、有 Hugging Face 重建，但仍属作者自报，报告里写明了采样设置（温度 0.6、top-p 0.95、presence penalty 1.5），但没有给换设置后的复测。反驳方是 spaCy 作者、也在做面向编码 agent 的产品，属有立场的专业评论，不是中立第三方。双方都没有做交叉复现。

## 其他值得关注

### 2. 空闲压缩的失效方式：会话被替换成一条不是摘要的回复

空闲压缩 10-14 就有了（终端里 20 万 token 以上的会话闲置约 54 分钟即压缩，赶在一小时提示词缓存过期之前），2.1.314 又把它扩到 VS Code 与桌面端 Code 页。2.1.318 的修复说明写的是「空闲压缩会把会话替换成一条不是摘要的回复」——也就是说这条通路出错时不是「摘要质量差」，而是**把对话本身换掉**。这正好回答 10-30 那期的追问：后台改写历史的风险不在压缩率，而在它静默执行、损坏后用户未必立刻发现。同一批更新里还有两个与失败语义有关的改动：2.1.317 给 Agent SDK 的 hook 回调加了 `onFailure: "block"`（回调失败时阻断动作，而不是放行），2.1.318 给 mod 的模型分叉加了 `effort` 选项（快速侧任务可以固定用低档，不继承会话档位）——后者延续了 2.1.316 把子代理推理档位从「继承」改成「可单独设默认」的方向。

## 值得继续追问

- 条目 1：0.016% 的编辑让 MATH-500 从 7.9% 到 48.1%，其中多少只是「不再撞 32k 上限」？作者给了撞限比例 93%→33%，但没有把基线的输出上限放宽后重测，这一步能直接拆开「能做完」与「做得对」。
- 条目 1：反驳的核心是「这不是一种技术」。能分辨的实验是让模型在只有原始权重、没有 Python 与前向传播的条件下改 Qwen；作者没做，也没说为什么做不了——这是这条路线成立与否的关键缺口。
- 条目 2：空闲压缩这类后台改写，出错时怎么被及时发现？这次是「替换成非摘要回复」，说明损坏可以是静默的；值得看它的触发条件与日志是否对用户可见。
