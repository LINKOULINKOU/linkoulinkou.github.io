MIT CSAIL 那篇「模型能直接读写权重」的报告（11-02，2,924 分）在这两天长出了三层后续：11-03 有人用笔记本上的 27B 开源模型把**读权重**那部分复现了四个里的三个；同一天两位作者先后撰文，把它拆成「两种能力」并给出更简单的解释——读权重靠的是算第一层权重的范数，改 Qwen 靠的是现成的 steering／abliteration 套路，而那个模型的问题本来就不是「不会数学」，是 32k token 处死循环。所以现在能说清的是：**读权重这件小事是真的、可复现；「模型直接改进权重」这个头条还在争**。另一条短讯是 Claude Code 修了空闲压缩的一个失效——它会把会话替换成一条不是摘要的回复。

## 本期值得了解

### 1. 权重空间编程 36 小时：一次本地复现，两篇拆解

**原报告说了什么。** 作者是 Rikiya Takehi、Jayden Teoh、Alex Zhang 与 Omar Khattab（MIT CSAIL），11-02 发布，公开了全部实验日志与在 Hugging Face 上重建的被编辑模型。结论分三档：只把权重当文本喂进去，GPT-6 Astra 能说出四个同构 PPO 网络各在玩哪个游戏、扩散模型在生成什么形状、字符级语言模型用的是哪种语料并指出复制头在哪；改 3.5% 权重能让卡在坡道前的小车 100% 通过；对 Qwen3.5-0.8B，它定位「思维循环」，改 0.016% 的权重，把 MATH-500 从 7.9% 提到 48.1%、IFEval 从 21.0% 到 62.3%。作者自己也写了负面证据：编辑前 93% 的 MATH-500 回答撞满 32,768 token，编辑后降到 33%，并说「修掉循环不等于让模型更会做数学」；换不循环的 Gemma 3 270M 做同样的事，只有 6.8 → 7.0–7.7。

**第一次独立复现：读权重在 27B 本地模型上也成立。** Simon Willison 把仓库里 `exp1_which_game` 的提示词原样拿出来（除权重外四个提示词完全相同），用笔记本上的 Qwen 3.8 27B（17GB，LM Studio）跑：Pac-Man 对（46 分 12 秒、43,506 个推理 token、自报置信 72%），Pong 对（1 小时 4 分、75%），Breakout 对（52 分、88%），Freeway 错（当成了 Pac-Man 类游戏）。同一批提示词交给 OpenRouter 上的 Kimi K3.1 Pro，9 分 41 秒、19,493 个推理 token 认出 Breakout。这是第三方、可重跑的复现，只覆盖「读」这一档，且是小网络（17K 权重）。

**第一篇反驳：把两种能力混成了一种。** Matthew Honnibal（spaCy 作者）逐条列了八个实验的设置：真正「原始权重进上下文、无工具、不跑网络」的只有实验 1、2、4，规模 1.7 万到 17.2 万权重；凡是涉及真实语言模型的（6、7、8），Astra 都拿到 Python 沙箱，Qwen 那组还额外获得最多 50 次前向传播、每次最多 512 道练习题。他的论点是：摘要把两者写成一句「just by looking at the raw weights」，读起来像一种统一技术；实际是两种能力各做一半——一种是对小网络权重的直觉，另一种是「LLM 被提示去做 ML 工程师会做的事」。他还指出 MinAtar 那组被标题化：只有 Breakout 大幅超过 PPO-5 亿步（517 对 25），Seaquest 与 Asterix 是输的（53 对 89、53 对 55）。

**第二篇反驳：读权重没那么神秘，改权重是现成套路。** Sean Goedecke 给了一个具体得多的解释。游戏识别之所以看起来像「读懂权重」，是因为输入通道本来就按语义标注（agent、moving objects、reward targets…）、并且直接对应 8×8 格子的每个单元；把第一层权重按通道取 L2 范数、画成热力图，三行 Python 就能看出「玩家在底行＝Breakout」「迷宫形状＝Pac-Man」。他甚至把四张热力图贴出来，说外行看图也能猜出前三个。至于 Qwen：那个模型的毛病不是数学能力差，而是 32k token 处陷入循环，**32k 以内能解的题它原本就都做对了**；而 Astra 的做法是写几段循环文本与不循环文本、测量哪些权重贡献了这个差异、逐步削减并验证——这正是 abliteration／steering 的标准玩法，一个熟练的人类研究员会做同样的事。他的类比是：LLM 能直接改权重，就像它能吐机器码、能改编译后的二进制——是个漂亮的技巧，但要改模型，正道仍是训练。

把四条放在一起，结论比任何单方都窄：**「小模型能读权重」已经可复现**（第三方、本地、同一提示词），但可复现不等于神秘——Goedecke 的解释说明它可能是「带标注的输入结构 + 范数计算」，而不是对网络功能的整体理解；**「模型直接改进权重」仍未证明是能力**：Qwen 的收益与「不再撞 32k 上限」纠缠在一起，作者自己的 Gemma 对照也不支持「凭空加能力」。两边都没有做能分辨这两件事的实验——对读权重，是把通道标签去掉后再跑一遍；对改权重，是放宽原模型的输出上限、看它本来能不能做对那些题。

判断边界：四篇都是博客，没有同行评议；原报告有日志与模型可核，复现只测了读权重这一档的四个样本，两篇反驳都是有立场的专业评论（一位在做编码 agent 产品，一位是长期写 LLM 评论的工程师）。时间与 token 消耗是单机单次测量，不能当性能指标。

## 其他值得关注

### 2. 空闲压缩的失效方式：会话被替换成一条不是摘要的回复

空闲压缩 10-14 就有了（终端里 20 万 token 以上的会话闲置约 54 分钟即压缩，赶在一小时提示词缓存过期之前），2.1.314 又把它扩到 VS Code 与桌面端 Code 页。2.1.318 的修复说明写的是「空闲压缩会把会话替换成一条不是摘要的回复」——也就是说这条通路出错时不是「摘要质量差」，而是**把对话本身换掉**。这正好回答 10-30 那期的追问：后台改写历史的风险不在压缩率，而在它静默执行、损坏后用户未必立刻发现。同一批更新里还有两个与失败语义有关的改动：2.1.317 给 Agent SDK 的 hook 回调加了 `onFailure: "block"`（回调失败时阻断动作，而不是放行），2.1.318 给 mod 的模型分叉加了 `effort` 选项（快速侧任务可以固定用低档，不继承会话档位）——后者延续了 2.1.316 把子代理推理档位从「继承」改成「可单独设默认」的方向。

## 值得继续追问

- 条目 1：把四个游戏提示词里的通道名（agent／moving objects…）去掉再跑一次，27B 还能认出来吗？Goedecke 的解释如果成立，这一步就会掉一大截——这是区分「读结构」与「算范数」最便宜的一次实验。
- 条目 1：把 Qwen3.5-0.8B 的输出上限从 32k 放宽后，它在 MATH-500 上原本能到多少？作者给了撞限比例 93%→33%，但没拆开「能做完」与「做得对」，这是判断「改权重是不是真本事」的关键对照。
- 条目 2：空闲压缩这类后台改写出错时怎么被及时发现？这次是「替换成非摘要回复」，说明损坏可以是静默的；触发条件与日志是否对用户可见值得看。
