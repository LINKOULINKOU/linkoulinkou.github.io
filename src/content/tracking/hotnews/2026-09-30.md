## 本期主线：DevDay 把「代理」从会话工具推向常驻系统与专用原语

OpenAI 在 9/29 DevDay 上给出三层变化：模型层，GPT-6.1 Sol 以「接近 Astra 的智能、五分之一价格」落地，昨日撤版事件由此有了接续（条目 1）；产品层，Dots 让代理第一次以常驻形态运行——有自己的云电脑与浏览器、主动研究默认只读、可被监控暂停（条目 2）；接口层，Decisions API 把「分类/路由/选下一步动作」从主模型对话中剥离成独立低延迟原语（条目 3），同场还有 Agents API 的 Computer Use 工具与 Codex 可复用云环境。综合判断：与上期「失控治理落地」相接，这一轮的方向是**把代理变成长期运行的系统组件来供给**——定价（缓存输入大降价）、形态（常驻+监控）、原语（决策/计算机操作专用接口）三面同时到位。

### 1. GPT-6.1 Sol 发布：近 Astra 智能、五分之一价格

**发生了什么**：OpenAI 于 DevDay 发布 GPT-6.1 Sol，官方定位为 GPT-6 Sol 的升级：代理编码、计算机操作与专业工作接近 GPT-6 Astra，价格为 Astra 标准 API 价的约五分之一（每百万 token 输入 \$2/输出 \$10）。对代理工作流最有分量的定价点：**缓存输入 \$0.10，比标准输入低 95%、比 GPT-6 Sol 的缓存价再低一半**——复用上下文的运行方式被显式定价奖励。官方自报基准：DeepSWE v1.1 以约五分之一成本匹配 Astra；OSWorld 2.0 离线档超 GPT-6 Sol 7 个点；安全口径上官方称其「更少隐瞒工具故障、更守用户限制」（自报对比：工具故障瞒报率 2.1%，GPT-6 Sol 4.9%、Luna 28.7%），并发布系统卡附录。可用性：当日进入 ChatGPT Work 与 Codex（API 名 gpt-6.1-sol），暂不在 ChatGPT 对话中；**Ultrafast 版（官方称 8 倍生成速度）数日内**；GitHub Copilot 同日上架。与昨日归档条目 1 的关系：撤版的 GPT-6.1 Astra 未见重新排期，本次以更低价的 Sol 接续「6.1」代际——是撤版事件的最新状态变化。

**为什么值得关注**：缓存输入降到输入价 5% 是明确信号——厂商按「代理反复携带长上下文」的用法设计价格；预算敏感的自建工作流可以把「同一长上下文多次复用」当一等的成本设计对象。

**我的判断与边界**：基准与安全数字全部为官方自报；「接近 Astra」的具体含义以系统卡附录口径为准。Ultrafast 未落地前不要按 8 倍速度做估算。

### 2. Dots 常驻代理：自带云电脑，主动研究默认只读

**发生了什么**：OpenAI 发布 Dots——常驻运行的代理（always-on agent），由 GPT-6 Astra 驱动。形态要点：每个 dot 有自己的云电脑与浏览器，经许可才可连到用户本机（现场演示为驱动本机上的 Codex 建应用）；可在 ChatGPT、Slack、Teams 中被触达，在 Slack 有独立身份；学习用户反馈形成持久偏好；宣称 4,000+ 应用集成。控制与安全设计是本次值得抄的部分：**主动研究默认只读工具**；监控系统可暂停或停止 dot；自定义规则分「允许/需批准/禁止」三档；后果性操作自动复核，改密码等敏感操作始终留给用户；有活动视图可查。企业侧另有「专家 dot」：独立身份、独立凭据、IT 配置的硬件，接 Microsoft Agent 365。可用范围：Pro、Business Premium、Enterprise（管理员 beta），订阅含首个 dot。Codex 负责人在问答中给出因果解释：**dots 的可行性源于 Codex harness 可靠性提升、代理才扛得住更长的任务**。同场另发布 ChatGPT Space（共享协作空间）。

**为什么值得关注**：常驻+主动+独立凭据是代理形态的一次实质变化，其权限分层（只读默认、三档规则、敏感操作留人）与监控暂停是可迁移的控制设计；「harness 可靠性决定任务时长上限」与本期条目 6 的 Codex 恢复语义互为印证。

**我的判断与边界**：绑定 OpenAI 托管栈，能力边界（尤其「4,000 集成」）为官方口径；现场演示行为以 Simon 现场记录为准。官方 RSS 的 pubDate 存在数小时偏差（上轮扫描时 feed 尚无此条），发布时点以 DevDay 与 HN 首帖为准。

### 3. 决策原语两路并进：官方 Decisions API 与开源 Jeeves

**发生了什么**：OpenAI 发布 **Decisions API**（限量预览）：用 GPT-6 Luna 在预定义选项集中做选择，「几分之一秒」返回，官方给的三个用途是内容分类、请求路由、**选择代理的下一步动作**；Simon 在现场直指这是对决策模型（Jev）形态的官方回应。开源侧同日，PostHog 发布 **Jeeves**：9B 推理型决策模型（Qwen3.5-9B 加适配器与指针头，先推理再判定），自报留出集超过 Kev-9B 与 Jev（0.889 对 0.822/0.857），兼容 Jev 请求格式，单卡不思考约 0.3 秒、开启思考中位 3.3 秒；社区同日还有把 Jev 蒸馏到本地并带分歧界的 Jevstiller（HN 61 分）。

**为什么值得关注**：两周内这条线走完了「新形态（Jev）→ 本地复刻（Jeff）→ 官方原语 + 推理增强开源版」——分类、路由、下一步动作选择正从主模型对话中剥离成专用低延迟组件。对自建工作流，「守卫/路由决策」现在有官方 API 与开源权重两条可落地路径。

**我的判断与边界**：Jeeves 数字全部为 PostHog 自报（对比列取自对方发布值）；Decisions API 在限量预览，接口与价格未定。两路是否收敛到同一用法（尤其「选下一步动作」）值得下轮跟踪。

- **缓存输入定价已成为显式设计对象**（条目 1）：\$0.10/M 的缓存价意味着「同一长上下文反复使用」的工作流在成本结构上被奖励；自建工作流值得把重复上下文的复用率当一等的优化项，而不是顺手行为。
