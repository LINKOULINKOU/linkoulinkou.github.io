## 本期值得了解

### 1. Codex 沙箱不只是容器：权限档、网络代理与三平台实现

OpenAI 11-18 的工程文把 Codex 沙箱讲透了：用户通过「权限档」（permission profile）声明文件系统与网络限制，默认的 `:workspace` 允许在工作区内写、但把 `.git` 与 `.codex` 保持只读，这样一个 agent 改代码不用每次求批准，又不会被提示注入直接改掉 git 钩子。网络侧不靠单点拦截：harness 启动 HTTP 与 SOCKS5 代理并把地址注入 `HTTP_PROXY`、`ALL_PROXY`、`PIP_PROXY` 等环境变量，代理按域名规则决定放行，绕不过环境变量的程序则由操作系统层直接阻断外连。三平台实现不同：macOS 用 Seatbelt，Linux 用 Landlock 与命名空间，Windows 用 AppContainer 一类机制，代理策略逻辑三平台共享。文章还给了一个可直接抄的例子：用 `codex sandbox --permission-profile memory-mcp` 包住 `npx --offline`，让 MCP 记忆服务器只能写 npm 缓存与自己的数据目录、且不能联网。

来源：[Inside the Codex sandbox](https://openai.com/index/inside-the-codex-sandbox)｜OpenAI（Michael Bolin）｜2026-11-18

### 2. 工具库太大怎么办：Gemini 让模型按需加载参数 schema

Google 11-19 在 Interactions API 预览 Tool Retrieval：给请求加一个 `tool_search` 工具、把长尾工具标上 `defer_loading: true`，模型仍能看到每个工具的名字与描述，但完整参数 schema 不进上下文；需要时模型按名索取，API 在同一次请求内载入 schema 并发出函数调用，三步都出现在 `interaction.steps` 里，方便排查是名字还是描述写坏了。服务端检索，不用自建索引；延迟工具放在 prompt 尾部，前缀缓存因此保持稳定。也支持把一整个远程 MCP server 标为延迟加载；自带工具注册表或按用户权限过滤的场景可以声明 `execution: "client"` 换成客户端检索，代价是每次多一次往返，但能在对话中途接入新工具。

来源：[Introducing Tool Retrieval in the Gemini API](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval)｜Google｜2026-11-19

### 3. 用 agent 跑两周把服务撞坏再修好：Claude Docs 的 chaos loop

Anthropic 11-17 记录了 Claude Docs 上线前的做法：距发布两周时，服务还只是单节点的概念验证，作者在 Claude Code 里开了一个长期会话当协调者，把活派给子 agent（最忙一周约 11 个并行、峰值 30 个），循环是「挑场景→跑压测→读 Datadog 遥测→提修复→发到 staging→重跑」。场景刻意夸张：单日 1,000 万新文档、2.2 万连接同时重连、热点文档数百人围观时杀掉正加载的服务器、数据库卡住。两条硬规则贯穿：文档要几乎瞬开、服务器确认过的编辑必须还在。结果 9-16 上线，一周内 460 万文档、20 亿请求只有 60 次 5xx，未回滚，约 50 个内存优化 pod。作者强调这依赖两件事：把系统做得对模型可读（避免 GC 这类模型控制不了的运行时行为，每条查询都报扫了多少行、返回多少行），以及前沿模型现在能连续几周盯住一个目标。

来源：[Using a "chaos loop" to harden the Claude Docs launch](https://claude.dev/blog/chaos-loop-claude-docs-launch/)｜Anthropic（Vivek Nair）｜2026-11-17

### 4. Claude 解出两个黑洞物理的开放问题

Anthropic 11-17 公开：Claude 完成了一个物理学家 20 多年前提出、一直没人解出的计算，结果显示「黑洞形成相关的突变」在时空不再有确定形状的地方依然存在；另一个是量子引力检验技术的最简版本，Claude 找到了精确极限。两篇预印本已放出，文章先给普通读者版本再给技术细节。这不是 benchmark 分数，而是在一个需要长期推演的领域里，agent 把「已提出的问题」推到「有答案」。

来源：[Claude solves two open problems in the physics of black holes](https://www.anthropic.com/research/claude-black-hole-physics)｜Anthropic｜2026-11-17；[HN 讨论](https://news.ycombinator.com/item?id=50563148)（554 分）

### 5. Inkling 2 Mini：把中间层跑三遍，换取「想得多但写得少」

Thinking Machines 11-20 发布 Inkling 2 Mini：26.4B 总参数、3.4B 激活的 MoE，但中间层对每个 token 跑三遍（looped transformer），用更多内部计算换更少输出 token，在 agentic coding 这类依赖推理质量的任务上收益最大。它称在 100B 以下开放权重模型里领先 DeepSWE v1.1（48.2%）与 Vals Index v2.2（46.5%）。最值得看的是它把「循环」与可监控性放在一起测：随循环次数增加，思维链变短但仍然可读，无 CoT 情形下的时间视野从单次 16 秒提到三次 37 秒，串行推理基准上的表现一直涨到十次循环——是训练时的两倍。作者也承认循环让模型更少把推理写出来，这正是监控的难点。

来源：[Introducing Inkling 2 Mini](https://thinkingmachines.ai/news/inkling-2-mini/)｜Thinking Machines｜2026-11-20；[HN 讨论](https://news.ycombinator.com/item?id=50581260)（850 分）

### 6. 一颗由 AI 从指令集设计到 GDS 的 CPU

Architect Labs 11-18 发布 Frostbite：一颗全新的通用 CPU 与指令集，从编译器、ISA、架构、微架构、RTL、验证一路到最终 GDS 都由 AI 系统自主迭代完成。它借「交互网」（interaction nets）的性质——每步都是局部的、依赖显式、每个值只有一个属主——把原本要在运行时重新发现依赖关系的开销提前消掉。在 25 个负载（其中 15 个藏到最终评测才用）上，相对一颗现代、已流片的超标量顺序核，性能功耗比达到 4.59 倍。作者称发现了人类工程师不容易想到的硬件实现与运行时特性；这类结果的可复现性仍待外部验证。

来源：[Introducing Frostbite](https://architectlabs.com/blog/frostbite)｜Architect Labs｜2026-11-18；[HN 讨论](https://news.ycombinator.com/item?id=50572503)（637 分）

### 7. KPMG 用 100 多个 agent 做审计：比人类问得更好

KPMG UK 11-18 公开 Project Exponential：100 多个 AI agent 在一家 FTSE 250 公司的账目审计中，与传统审计团队并行工作，覆盖信息收集、数据分析与文档、起草结论等整个流程，而不是只做零散行政活。审计主管 Cath Burnet 说，agent 在若干处比人类团队挖得更深，指出了需要进一步调查的地方、提出了审计师没想到的问题。这是专业服务里少见的、跨整个工作流的 agent 部署案例，但具体由哪个模型驱动、如何保证审计留痕与责任归属，公开信息尚未交代。

来源：[AI Agents Ask Better Questions Than KPMG Accountants](https://europeanbusinessmagazine.com/ai-agents-better-questions-kpmg/)｜European Business Magazine（转述 FT）｜2026-11-18；[HN 讨论](https://news.ycombinator.com/item?id=50547777)（497 分）
