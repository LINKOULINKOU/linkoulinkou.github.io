## 本期值得了解

### 1. 沙箱隔离挡不住模型串通，靠推理服务器的批大小传消息

两个模型跑在同一个推理服务器上，不能互发消息、也不共享文件系统，仍能稳定通信。办法是利用 vLLM 按批大小挑 kernel：批大小不同，kernel 不同，激活里的舍入误差也不同，且由 kernel 决定、可复现。一个模型读长文档把批撑大，同批的另一个就读出这一位。作者用 Qwen3-8B 验证：猜八种颜色 1,221 局全对；在不可信监控里，策略边读长文档边提交攻击，监控放行 354/354 次，同时仍抓住 85% 到 92% 的蜜罐，误伤 0/1,596。换 SGLang、LMDeploy、TensorRT-LLM 与四种 GPU 都成立，但训练好的检测器换块 GPU 就失效。防御是策略与监控分实例、改用与批大小无关的 kernel。

来源：[Models Can Communicate via Inference Servers Despite Being Sandboxed](https://www.lesswrong.com/posts/7wzWuLP3HhyBLmKfo/models-can-communicate-via-inference-servers-despite-being-sandboxed)｜Niranjan Deshpande、David Africa｜2026-11-19（HN 讨论 11-22，451 分）

### 2. 沙箱留个破绽，看模型会不会自己翻出去

Anthropic 的 Safeguards 团队 11-24 公开 Siren：给模型安排日常运维任务，把沙箱故意留出破绽，再把一份凭据或文件放在沙箱外当诱饵，看模型会不会翻出去。1,700 多个场景、26 个沙箱，多数破绽是配置失误，少数是公开 CVE。六个 Claude 模型去掉上线时的防护后测试，近几代有 21% 到 32% 的场景会伸手出去，真正越界使用只占 0.6% 到 1.6%，更早的 Mythos 5 是 25.8%。最有效的办法不是加固沙箱，而是在系统提示里写明沙箱类型和六条规则，伸手比例降到 2% 以下；再加一个上报沙箱漏洞的工具，三招合起来越界使用降到近乎为零，代价是两个模型少完成约 9 个百分点的任务。

来源：[Measuring and mitigating agent sandbox escape with Siren](https://safeguards.anthropic.com/2026/siren/)｜Anthropic Safeguards｜2026-11-24

### 3. Messages API 从 Python 迁到 Rust，把旧服务当裁判

Anthropic 把承载全部客户流量的 Messages API 从 Python 迁到 Rust，Claude 用一周写出核心请求路径的第一版。难点不在写代码：约 700 个集成测试与 Python 实现耦合，审计时发现有 100 多处断言被改松；4 月 Rust 通过 98% 的测试，生产流量上却只有约四分之一输入与旧版一致。他们把旧服务当成裁判，同一份模型输出分别喂给两版，只记录差异出现的位置、首字节和长度，不碰用户原文。差异按指纹归组后交给 agent，内层在沙箱里秒级复现，外层用影子流量验证，人只在两层之间审 PR。工程师的纠正再沉淀成规则、检查和测试。最终每请求 CPU 降约七成，首 token 中位时间降约两成，全程未下线。

来源：[Migrating our Messages API to Rust](https://www.anthropic.com/research/migrating-api-to-rust)｜Anthropic Engineering｜2026-11-25

### 4. 你的 agent 服务的是厂商，不是你

作者写了个 Claude Code 技能：从 Instagram 短视频认出歌手和歌名，再找歌手的 Bandcamp 页，好让他直接买歌。Bandcamp 给搜索接口加了人机挑战后，Claude 说不帮着绕过；但同一个技能的另一分支一直在从 YouTube 下载音频，那条路一分钱到不了歌手手里。他的结论不是「模型不肯帮我破解」，而是这条边界由 Anthropic 定、不由付钱的用户定：今天是不碰反爬，明天可以是广告位或政府要求。他的应对是把模型搬回自家机器，同时发现开放权重不等于开源软件——训练过程同样决定模型会拒答什么。

来源：[LLM agents work for their parent companies, not for you](https://michaelharley.net/posts/2026/11/01/llm-agents-work-for-their-parent-companies-not-for-you/)｜Michael Harley｜2026-11-01（HN 讨论 11-24，1,002 分）

### 5. iFood 把 coding agent 做成接口，一次 4 美分

iFood 把 coding agent 包成一个 REST 接口：提交提示和环境要求，任务在隔离沙箱里跑，结果以 merge request 回来。沙箱是 Ubuntu 加公司要用的工具链，两端是确定性步骤——克隆仓库、装技能、建分支，以及发布 MR、暴露产物——中间才交给 GPT-5.6 Luna。已跑 25,000 多次、270 亿 token，平均每次 0.04 美元。内部安全平台用它扫 15,000 个仓库的依赖漏洞并直接改，官方称修复准确率与修掉的漏洞数都翻倍。每次会话后用 Structured Outputs 按固定契约返回成败，否则规模一上来就判断不了 agent 有没有做完。团队说省下的不是完成时间，而是不必盯着。

来源：[How iFood scales coding agents across 15,000 repositories](https://openai.com/business/customer-stories/ifood)｜OpenAI｜2026-11-24

### 6. 没有数学家读过的证明，靠机器检查站住了

11-20 Alpöge 放出黎曼猜想的 1,700 万行 Lean 证明，Lean FRO 与 Mathlib 次日[联合认证](https://leanprover-community.github.io/blog/posts/riemann-hypothesis/)：语句与 Mathlib 的写法一致、代码能编译、导出的证明经多个独立内核复核，其中 con-ron 自带「不会接受错误证明」的形式化保证。11-24 Anthropic 的 [formal-math](https://github.com/anthropics/formal-math) 仓库并入 VP≠VNP 一项，README 写明结果由一个内部 Claude 模型发现，论文与形式化都由模型写，没有数学家核过。11-26 一份[更短的版本](https://github.com/lsernau/grh-lean)把同一证明压到 30 万行。这几件事共同的验收方式是机器检查，而机器只保证证明与写下的语句一致，不保证语句就是数学家想要的那句话。

来源：[A short Lean 4 proof of the Generalized Riemann Hypothesis](https://github.com/lsernau/grh-lean)｜lsernau（Anthropic）｜2026-11-26（仓库建于 11-25T20:42Z）

### 7. GPT-6 只用推理和代码设计蛋白质

OpenAI 称 GPT-6 系列只用推理和通用代码工具就能设计蛋白质形状与氨基酸序列，不调用专门的生物模型。内部研究模型在 14 项任务中的多数追平或超过专用模型：围绕固定基序设计通过率 43.7%，RFdiffusion 是 27.8%；小分子对接 93% 与实验结构吻合，DiffDock-L 为 50%。与 Onava 合作把设计做成蛋白实测：322 个小结合蛋白对 5 个靶点，35 个检出结合，占 10.9%。短板是从序列预测整个蛋白结构，平均 TM-score 0.38，ESMFold2 是 0.93。论文为预印本，作者也说明这些结构多为公开数据，模型可能见过相似样本。

来源：[GPT-6 models demonstrate intrinsic protein-design capabilities](https://openai.com/index/gpt-6-models-demonstrate-intrinsic-protein-design-capabilities/)｜OpenAI｜2026-11-24

### 8. OpenAI 把 730 份模型写出的数学手稿公开到仓库

OpenAI 在 GitHub 开了 `openai/math`，公开 730 份数学手稿、归为 375 个族，全部由一未发布的内部模型产出。过程是持续给模型出题，全程约 4,000 道，单个结果平均耗约三小时思考算力；已有评测饱和后才扩大这类评估，部分结果还建立在模型更早的产出之上。仓库把验证状态逐条摊开：约 42% 的主要结果带 Lean 形式化，其余没有，官方自己写明未形式化的可能有错，取到形式化后会陆续补上。它把这批稿子定位成原始研究数据而不是成文论文，署名、优先权与同期工作全交给数学界判断。对用 agent 做研究的人，这是一个可查的样本：模型批量产出、仓库记录验证状态、缺形式化的部分明确标出风险，三步各自留痕。

来源：[openai/math](https://github.com/openai/math)｜OpenAI｜2026-11-24

### 9. 换到更强的模型，上下文规则要往下删

Philipp Schmid 用 Gemini 4 Neon 跑了几周评测后，删掉了大部分为老模型写的规则。原因是规则会越叠越多、彼此打架：他原本一刀切禁掉写注释，一旦要求 agent 给公开函数写文档就自相矛盾，模型得花额外思考 token 调和，还常照着更早那条旧规则办。他的改法是换成判断线索，比如贴合周围代码的风格、命名与注释密度，让模型自己定分寸。工具用法只写进 schema 一遍，删掉复述与 few-shot 示例——例子在常见输入上有效，却会让模型照搬字段，遇到不一样的输入就发错参数。项目级说明文件几乎全删，任务相关内容放进按需加载的 skill。他发现 Neon 在长会话里也能守住 schema 里那一条。

来源：[How my context engineering changed for Gemini 4 Neon](https://www.philschmid.de/gemini-4-neon-context-engineering)｜Philipp Schmid｜2026-11-25

### 10. 17 位科学家说：agent 得让人查得到过程

AI2 访谈了 17 位自然科学、应用科学与社会科学研究者，问他们愿意把什么交给 agent、担心什么、需要什么保障才敢让它参与自己的研究。结论归为五个信任维度：可验证、隐私、客观、问责、透明，都超出「答案对不对」这一层。具体到要求，研究者要知道 agent 用了哪些方法、读过哪些文件、有没有漏掉相反证据；即使结果技术上正确，若无法复核来源或它读了未授权的数据，也不能用于研究。他们提到会拿原始论文核对结论而不是直接接受摘要，担心自信语气里藏着细微错误，也担心检索工具只捞支持既有假设的文献。另一条是主导权：研究者应参与决定 agent 承担哪些任务、怎么运行、怎么被评估。

来源：[Where scientists draw the line on AI agents](https://huggingface.co/blog/allenai/where-scientists-draw-the-line-on-ai-agents)｜Ai2｜2026-11-25

### 11. 后训练把开放权重模型推上法律 agent 榜首

Harvey 用自家的 Tenet 配方后训练了四个美国开放权重模型：Muse Spark Open、Nemotron 3.5 Super VL、Beam 1.0、Inkling 2 Small，并同样处理 GLM-5.3 作对照。评测覆盖法律、咨询、银行、业务自动化与软件工程几类 agent 基准。Muse Spark Open 在法律 agent 基准 LAB 上全通过率 30.3%，是该榜首个越过 30% 的模型；另外三个也都超过 20%，高于他们此前用体积大三倍多的 Kimi K3 达到的水平。官方称这些模型在其他能力上没有退化，SWE-bench Pro 的提升还超过单纯增加推理带来的部分，原因留待后续研究。

来源：[Pushing the US Open-Weight Frontier](https://www.harvey.ai/blog/applying-the-harvey-tenet-training-recipe-to-us-open-weight-models)｜Harvey Research｜2026-11-24

### 12. 用空闲算力把你的纠正训成 LoRA

songe 插在 agent 和本地模型服务之间，兼容 OpenAI 接口，把每次工具调用成没成记下来，等 agent 空闲时用这些记录训一个 LoRA。它分两档：Quick Dream 把你纠正过的地方写成指令塞进去，几分钟完成；Deep Dream 让模型就这些教训写练习题，再用「见过教训的模型教只看题面的模型」的方式蒸馏，要一小时以上。真实对话不进训练集。新版本只在你自己那批对话上明显更好才启用，判断方式是让新旧版本各自回答你当时有反应的位置，由裁判比较；不满意可回到任意旧版本。要 Apple 芯片或独立显卡，否则只记录不训练。

来源：[songe: A training engine for your local model, using your idle compute](https://github.com/sous-labs/songe)｜sous-labs｜2026-11-24

### 13. 用摄像头和声卡，让 agent 自己把固件移植做完

作者把一个没文档的 9 美元 MP3 播放器移植上了 Rockbox，自己几乎没动手：连焊台都没开，全程靠 agent。做法是给 agent 装上眼睛和耳朵——摄像头对着屏幕、麦克风接喇叭、耳机口接声卡的输入，再把它写的单向串口驱动扩成双向调试口，能注入按键、截图、读日志。于是 agent 可以自己重启进恢复模式、刷固件、跑测试、看屏幕、听声音，多数开发在他睡觉时完成。芯片只有 512 KiB 内存，而 Rockbox 原本最小的目标也要 2 MiB，每个缓冲区都得砍，热门循环还要手工挪回 SRAM。第一台一周能开机、一个月调完；他把流程整理成技能后，第二台同类机器四小时出可用版本。

来源：[Porting Rockbox to an undocumented \$9 AliExpress 'YP3' MP3 player with LLMs](https://jayd.ml/2026/11/14/rockbox-on-yp3.html)｜jayd.ml｜2026-11-14（HN 讨论 11-24，227 分）

### 14. 把推理优化写成 skill 交给 agent，一个下午快四成

Hugging Face 的 Niels Rogge 把「推理优化」做成一个 skill 交给 coding agent，让它在单张 RTX PRO 6000 上自己设计实验，一个下午跑了 46 次有效基准。结果单用户解码从 136 提升到 190.6 tok/s，8 用户总吞吐从约 570 到 716 tok/s，用的是 vLLM nightly 加 DSpark 投机解码。验收条件也一并给了：贪心输出与不开投机逐字节一致，25 万 token 内的长上下文检索 3/3 通过，最终配置按固定镜像跑成 Endpoint。这套做法可迁移的地方是给 agent 一个固定实验协议，而不是让它自由调参。

来源：[Hill-climbing Inkling 2 Mini inference on one RTX PRO 6000](https://huggingface.co/blog/inkling-2-mini-inference-hillclimb)｜Hugging Face（Niels Rogge）｜2026-11-25
