## 本期值得了解

### 1. OpenAI 把 730 份模型写出的数学手稿公开到仓库

OpenAI 在 GitHub 开了 `openai/math`，公开 730 份数学手稿、归为 375 个族，全部由一未发布的内部模型产出。过程是持续给模型出题，全程约 4,000 道，单个结果平均耗约三小时思考算力；已有评测饱和后才扩大这类评估，部分结果还建立在模型更早的产出之上。仓库把验证状态逐条摊开：约 42% 的主要结果带 Lean 形式化，其余没有，官方自己写明未形式化的可能有错，取到形式化后会陆续补上。它把这批稿子定位成原始研究数据而不是成文论文，署名、优先权与同期工作全交给数学界判断。对用 agent 做研究的人，这是一个可查的样本：模型批量产出、仓库记录验证状态、缺形式化的部分明确标出风险，三步各自留痕。

来源：[openai/math](https://github.com/openai/math)｜OpenAI｜2026-11-24

### 2. 换到更强的模型，上下文规则要往下删

Philipp Schmid 用 Gemini 4 Neon 跑了几周评测后，删掉了大部分为老模型写的规则。原因是规则会越叠越多、彼此打架：他原本一刀切禁掉写注释，一旦要求 agent 给公开函数写文档就自相矛盾，模型得花额外思考 token 调和，还常照着更早那条旧规则办。他的改法是换成判断线索，比如贴合周围代码的风格、命名与注释密度，让模型自己定分寸。工具用法只写进 schema 一遍，删掉复述与 few-shot 示例——例子在常见输入上有效，却会让模型照搬字段，遇到不一样的输入就发错参数。项目级说明文件几乎全删，任务相关内容放进按需加载的 skill。他发现 Neon 在长会话里也能守住 schema 里那一条。

来源：[How my context engineering changed for Gemini 4 Neon](https://www.philschmid.de/gemini-4-neon-context-engineering)｜Philipp Schmid｜2026-11-25

### 3. 17 位科学家说：agent 得让人查得到过程

AI2 访谈了 17 位自然科学、应用科学与社会科学研究者，问他们愿意把什么交给 agent、担心什么、需要什么保障才敢让它参与自己的研究。结论归为五个信任维度：可验证、隐私、客观、问责、透明，都超出「答案对不对」这一层。具体到要求，研究者要知道 agent 用了哪些方法、读过哪些文件、有没有漏掉相反证据；即使结果技术上正确，若无法复核来源或它读了未授权的数据，也不能用于研究。他们提到会拿原始论文核对结论而不是直接接受摘要，担心自信语气里藏着细微错误，也担心检索工具只捞支持既有假设的文献。另一条是主导权：研究者应参与决定 agent 承担哪些任务、怎么运行、怎么被评估。

来源：[Where scientists draw the line on AI agents](https://huggingface.co/blog/allenai/where-scientists-draw-the-line-on-ai-agents)｜Ai2｜2026-11-25

### 4. 后训练把开放权重模型推上法律 agent 榜首

Harvey 用自家的 Tenet 配方后训练了四个美国开放权重模型：Muse Spark Open、Nemotron 3.5 Super VL、Beam 1.0、Inkling 2 Small，并同样处理 GLM-5.3 作对照。评测覆盖法律、咨询、银行、业务自动化与软件工程几类 agent 基准。Muse Spark Open 在法律 agent 基准 LAB 上全通过率 30.3%，是该榜首个越过 30% 的模型；另外三个也都超过 20%，高于他们此前用体积大三倍多的 Kimi K3 达到的水平。官方称这些模型在其他能力上没有退化，SWE-bench Pro 的提升还超过单纯增加推理带来的部分，原因留待后续研究。

来源：[Pushing the US Open-Weight Frontier](https://www.harvey.ai/blog/applying-the-harvey-tenet-training-recipe-to-us-open-weight-models)｜Harvey Research｜2026-11-24

### 5. 把推理优化写成 skill 交给 agent，一个下午快四成

Hugging Face 的 Niels Rogge 把「推理优化」做成一个 skill 交给 coding agent，让它在单张 RTX PRO 6000 上自己设计实验，一个下午跑了 46 次有效基准。结果单用户解码从 136 提升到 190.6 tok/s，8 用户总吞吐从约 570 到 716 tok/s，用的是 vLLM nightly 加 DSpark 投机解码。验收条件也一并给了：贪心输出与不开投机逐字节一致，25 万 token 内的长上下文检索 3/3 通过，最终配置按固定镜像跑成 Endpoint。这套做法可迁移的地方是给 agent 一个固定实验协议，而不是让它自由调参。

来源：[Hill-climbing Inkling 2 Mini inference on one RTX PRO 6000](https://huggingface.co/blog/inkling-2-mini-inference-hillclimb)｜Hugging Face（Niels Rogge）｜2026-11-25
