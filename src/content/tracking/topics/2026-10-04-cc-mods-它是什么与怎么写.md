## 先回答问题

Mods 是 Anthropic 10-01 随 Claude Code v2.1.287 发布的扩展机制：运行在 Claude Code 进程内的一段 JavaScript 或 TypeScript 事件处理函数，装进插件里分发。它要补的是此前扩展点的空白——设置文件里跑脚本的钩子（settings hook）、给模型读的指令文件（skill）、提供外部工具的服务器（MCP）都从进程外或外围工作，不能改写事件本身、不能画界面、不能替换内置功能；mod 可以。

本篇查清三件事：它怎么接进运行时、怎么写一个、边界在哪。先给答案：

- **机制**：Claude Code 每做一件事就发出事件（工具调用、提示词提交、界面绘制……），mod 的处理函数在事件处被调用，可以选择观测（放行）、改写（带改动放行）或接管（不让默认行为发生）；同一事件的多个 mod 组成中间件链，先加载者先见事件、最后见结果。它能改写发给模型的提示词、阻止或改写或重试工具调用、批准或拒绝权限请求、在工具输出进入模型前脱敏、替换界面元素——明确的例外只有权限提示本身不可改。
- **上手**：两条路——直接在会话里描述需求让 Claude 自己写（内置写 mod 的技能，写完会话内热重载）；或按三个文件自己写（插件清单、登记代码文件的 hooks 配置、代码本体），用 `--plugin-dir` 在单个会话里加载、保存即重载。装前可审查：一个静态检查命令能在不运行代码的前提下列出它会接什么事件、调用什么能力；自动化测试无需登录与网络。
- **边界**：mod 与 Claude Code 同权限、不被沙箱隔离——能读写文件与密钥、看到你全部会话、代替你批准工具调用、花你的额度；版本门槛 2.1.287+；接口标「早期访问」、跨版本可能变化，以本机生成的类型声明为准；企业侧与个人侧各有停用层级，另有一个服务端远程开关兜底。

## 1. 它是什么：站在事件管道中间的插件

先理清一个词。Claude Code 把两类东西都叫 hook：设置文件里配置的（跑 shell、发 HTTP、发提示词）这段时间在文档里叫 **settings hook（设置钩子）**；mod 里的处理函数就直接叫 **hook**。两者都挂在事件上，差别在运行位置——settings hook 从进程外进场，mod 的代码跑在 Claude Code 进程内。

位置决定能力边界。官方对照如下：

| | Mod | 设置钩子 | Skill | MCP 服务器 |
|---|---|---|---|---|
| 是什么 | 插件里被 Claude Code 在自身进程内调用的函数 | 生命周期事件上运行的外部脚本或请求 | 模型阅读的指令文件 | 给模型工具的进程或服务 |
| 能改什么 | 工具调用、提示词、命令、轮次、界面 | 拦、放或记录事件，改工具参数与结果，补上下文 | 模型知道什么、做什么 | 模型有哪些工具 |
| 能画界面 | 能 | 不能 | 不能 | 不能 |
| 用什么写 | JavaScript / TypeScript | 脚本 + 设置文件条目 | Markdown | 任意语言的服务器 |
| 何时选它 | 想要面板、提示条、自定义命令，或想改写事件 | 用现成脚本拦、放、记录事件 | 老往对话里贴同样指令 | 需要接外部系统 |

mod 本身也是插件：安装、版本、市场分发、组织管控全走插件通道，一个插件里可以同时装 mod、skill 和 MCP 服务器。判断一个插件是不是 mod，看它的 hooks 配置里有没有登记代码文件的 `modules` 字段。

补一段来历：这套机制的源码 09-23 在一次灰度开关失误事件里被社区从打包产物中读到（读 AGENTS.md 的功能受一个服务端开关控制），官方随后确认并预告「数周内正式发布」；发布前的设计稿也在 GitHub 上公开征集过意见。当时社区可见的内置项是四个，正式发布时文档列出六个（见第 5 节）。前情见 [2026-09-24-热点追踪](/tracking/2026-09-24) 条目 1。

## 2. 实际怎样运行：一个事件走完一条中间件链

从加载讲起。插件被加载时（会话启动、安装后，或 `--plugin-dir` 监视到保存），Claude Code 读插件的 hooks 配置，找到代码文件，调用它导出的注册函数，把一份「注册器」交给它；注册函数每调用注册器一次，就登记一条规则：接哪个事件、什么筛选条件（matcher，可以是精确值、候选数组或正则，也支持通配）、用哪个处理函数。登记完成后，这个 mod 就挂在了它关心的所有事件上。

事件发生时，处理函数收到三样东西：`$`（mods API，mod 唯一的外部能力入口）、`e`（事件数据，只读的纯数据）、`next`（把事件交给链上下一个处理函数；链的尽头是 Claude Code 自己的默认行为）。用不用 `next`、怎么用，决定三种结局——观测：调 `next(e)` 原样放行；改写：调 `next({ ...e, 改动 })` 带改动放行；接管：直接返回结果、不调 `next`，默认行为不发生（比如返回一条拒绝理由，工具就不会跑，权限框也不会弹，Claude 把理由当工具结果读到）。

链的顺序有硬规则。同一事件的所有处理函数排成一条中间件链，**先加载者在最外层**：先见到事件、最后见到结果、能决定后面的处理函数是否运行（后面的不能阻止前面的看到事件）。加载顺序分四层：组织侧守卫与前置名单插件在最前，然后是用户安装的，再是组织追加的，最后是其他内建项；用户安装的 mod 之间按依赖关系排，同一模块内部按注册顺序。设置钩子有两个固定插入点：托管设置里的 PreToolUse 钩子在第一个 mod 之前（它的阻止是终局，没有 mod 能看到这次调用）；其他设置文件与插件里的 PreToolUse 在最后一个 mod 之后、作为默认行为的一部分——mod 接管了调用就轮不到它们，调了 `next` 则能在返回结果里读到它们的裁决。工具调用还有一个事后复核事件 `tool.check`：在权限规则和上述钩子都裁决完之后触发，处理函数可以把裁决翻案（官方例子：当前分支是 main 时拒绝 `git push`，即使规则允许；注意它匹配的是命令文本，只算提醒，真正的分支保护要在 Git 服务端做）。

串一个完整例子：Claude 想跑 `git push --force` → 事件沿链传下来 → 某个 mod 的处理函数发现命令匹配风险模式，返回拒绝理由（没有调 `next`）→ 工具不执行、权限框不弹 → 链回溯结束。若它改成先挂起、调用界面询问（弹一个带选项的对话框，工具调用保持等待；提问前先给默认答案「拒绝」，没人回答也不会默许），效果就是「先问后跑」。若它什么都不干预、只放行，则照常走权限检查与执行——执行完的结果再沿链回溯，所以脱敏、记录类逻辑拿得到「跑了之后」的结果去改写或留痕。官方给三个例子正好覆盖接管、挂起、包装三类用法：拒绝 force push、危险命令挂起询问、记录提示词缓存命中量。

最典型的「前后都做事」载体是一次模型请求（`turn.step`，一个用户轮次里可能有多个）：它的处理函数是异步生成器，把流式响应原样放出去、等它求值出最终结果后再读 token 用量、记一行日志。整轮结束的事件拿得到答复文本、时长与 token 总量，被中断的轮次也有标记；它还可以返回一小段展示文本，压在回答下方。

状态放在哪，取决于要活多久：

| 存放位置 | 活到 | 适合 |
|---|---|---|
| 模块级变量 | 重载（开发时每次保存）为止 | 丢了无所谓的值 |
| `$.state` | 会话结束，或 /clear、/resume、/branch | 绘制依赖、需扛住重载的值 |
| `$.store` | 主动删除，或机器上所有会话长期不读写 | 设置、历史等跨会话数据（机器级共享，JSON 存储） |

热重载会把注册函数重跑一遍、模块变量清零——计数类 mod 每次保存后从零开始，这是机制而非故障。

失败语义也有明确分工。处理函数抛错或超时不会掀翻会话：失败且还没轮到它交出结果——跳过它，链上后续处理函数顶上；已经交出结果后失败——结果照用，不会跑第二遍（会在对话流或日志里留一行带 mod 名与原因的记录）。想让关键守卫 fail-closed（一失败就拦住），可以给这条注册串一个兜底处理函数，入参里带着失败类型（抛错还是超时），返回拒绝即可。界面绘制的失败曾经更严重：早期版本里绘制函数异步抛错会让受管会话直接结束，2.1.289 改为引擎自己画一行兜底——这类「单个扩展把宿主拖下水」的问题，正是上线头几天的修补重点。

工程上先知道几个限额：单个处理函数一次事件内 10 秒（个别提示词编辑事件只有 50 毫秒），兜底处理 1 秒，单文件读写 4 MiB，跨会话存储 4 MiB，单个文本节点 1 万字符，界面重绘按每秒 10 次（终端可见区 30 次）节流。

最后是「写出来了在哪生效」：终端（含编辑器内置终端与 JetBrains 插件）可运行、可绘制；桌面应用的 Code 标签页可运行、可绘制（个别元素仅终端）；VS Code 扩展的聊天面板与 `claude -p`、Agent SDK 只运行、不绘制；WSL 会话里插件整体不可用；云端会话只对能带上去的插件运行、且不绘制。能画的东西：十余个界面位点（面板、提示区、消息与工具行、提问框、spinner、轮次时长、状态提示等）和十余种元素（容器、文本、按钮、输入框、选择器、链接、代码块、SVG、图片……），权限提示本身是明确的禁区。所有对外动作（画界面、加命令、调模型、读写文件、发网络请求）都必须经过 `$` 的命名空间——界面、命令、工具、子代理、模型、提示词、轮次、会话通信、配置、环境变量、文件、网络、进程、MCP、存储、状态、定时器。

## 3. 怎么写一个：两条路，一个热重载循环

第一条路：让 Claude 写。在会话里直接描述需求（例：「做一个在当前提示上方显示 git 分支的 mod」），Claude 就会调用内置的 plugin-authoring 技能（里面装着当前版本有哪些事件、哪些方法、文件写到哪、怎么加载的知识）把 mod 写出来。文件落在该会话专属的目录（`~/.claude/dev-mods/<会话 id>/<名字>/`）；因为这里是受保护路径，默认模式下它会逐个文件征求你的同意。第一个文件保存时，Claude Code 会问是否为这个会话打开热重载：同意后，mod 在「回合结束」时加载，之后每次改动也在回合结束时重载，改完即试。这个 mod 只属于写出它的那个会话，会话目录超过保留期会被清理；要留存就把目录拷出去，用 `--plugin-dir` 加载，或者做成市场条目给别人装。

第二条路：自己写。最小 mod 是三个文件——插件清单（无特殊字段）、hooks 配置（`modules` 字段指向代码文件，有它才是 mod）、代码本体（导出注册函数，在里面对注册器登记事件处理器；没有构建步骤，`.js` / `.ts` 家族由 Claude Code 直接加载）。官方入门例子里，代码做四件事：会话开始时注册一个 `/tally` 命令、每次工具调用把计数加一、回答该命令时返回计数文本、画 spinner 时把计数缀在词后。加载用 `claude --plugin-dir ./first-mod`：这个目录会被监视，保存后回合结束自动重载，注册函数重跑、处理器全部刷新，下一回合就能试新行为。

官方给静态分析定了硬约束（违反会加载失败）：事件名必须是字符串字面量、`$` 必须写全称（`$.命名空间.方法`）、不能解构或转存 `$`、文件之间只用相对导入、整体是 ES 模块。这些不是洁癖——它们是「不运行代码就能列出全部 hooks 与 calls」的前提，而这份静态清单又是安装前审查与组织治理的基础（见第 4 节）。

类型不用手写：每次从目录加载或重载时，Claude Code 会把当前版本确切的事件、方法与元素定义生成 `.d.ts` 放进插件目录；官方口径是「跨版本可能变化，信这些文件胜过任何页面」。仓库里有一份可浏览的副本，首行标明由哪个版本生成（当前副本是 2.1.277，落后于最新发布——这也是「以本机生成为准」的实例佐证）。

测试与排查都有离线路径：`claude plugin test` 在无会话、无登录、无网络的环境里跑测试文件，可以给工具调用喂假答案、断言命令返回值；「没反应」类问题先跑静态检查（拼错的事件名会直接报出来）；运行期错误行的位置分三种情形——带热重载的会话在对话流里出暗行，其他交互会话要开调试日志，`claude -p` 场景到 stderr。拿不准这台机器允不允许 mod：在任意不含 mod 的目录跑一次 `claude plugin test`，三种提示消息分别对应「可用」「被本机设置关闭」「被服务端远程关闭」（后者本机任何设置都打不开）。

分发不需要新流程：mod 打包在插件里，版本、更新、私有或公开市场、组织托管全部沿用插件通道；名字不能起得像 Anthropic 自家（`claude-` 开头会被静态检查拒绝）。

## 4. 边界：同权限、不沙箱，但可预审、可管制

先说风险面，官方写得很直白。一个 mod 加载后可以：以你的身份读写任意文件、启动进程、发网络请求；读环境变量与设置文件（可能含 API key）；看到你发的每条提示和 Claude 的每次工具调用；改写提示词或工具调用、以你的名义提交提示、向你的其他会话发消息；在你被问到之前替你批准工具调用（包括某些本会弹窗的、甚至被非托管 PreToolUse 拦下的）；花你的额度调模型。而且 mods 不被沙箱隔离——沙箱只罩 Bash 工具，mod 启动的进程在沙箱之外。安装建议因此只有一条：只装可信来源，和装任何本机代码一样。

控制手段分三层。第一层是装前审查：静态检查能列出这个 mod 接的所有事件、调用的所有 API（文件、进程、网络、环境与密钥读取、模型调用等一望可辨）、读写哪些环境变量与状态——安装前看完「它打算干什么」。第二层是权限结构：默认 deny 规则优先于用户 mod 的批准，托管设置里的 PreToolUse 拦截是终局；`tool.check` 能翻案的只是常规裁决，托管侧另有开关决定是否允许 mod 覆盖 deny 规则。第三层是停用与托管：单个 mod 可在 /plugin 里禁用；一个会话可用 `--safe-mode` 全停（连其他自定义一起）；本机全局可以设 `disableAllHooks`（连设置钩子和自定义状态行一起停，但组织托管的东西照跑）；组织侧还有「只放行组织自家与内建」「禁止目录侧载」等一串开关，外加内建守卫 sec-default。

sec-default 值得单说。它在「机器有托管设置」或「用户是 Team/Enterprise 方案」时最先加载、用户关不掉，作用是保护组织管理的东西不被用户装的 mod 改动——托管的钩子裁决、系统提示、托管指令文件、托管 MCP 的工具与描述、以及 deny 规则。它 fail-closed：读不到托管设置就拒绝所有用户 mod 加载。组织还可以在前置名单里挂自己的审查 mod：在每个 mod 加载前拿到与静态检查相同的清单，逐个放行或拒绝，甚至按 API 方法名拦截（例如把「起进程」类调用对第三方 mod 全面拉黑，官方给了完整示例）。再兜底一层是服务端远程开关：诊断信息里存在「Anthropic 已远程关闭安装的 mods」这一状态，本机任何设置都恢复不了——这是把「灰度失误」的教训制度化的那一层。

对个人使用者两条实用规则：插件来源与市场选择是主防线（同装任何代码）；另外早期访问时期的环境变量 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` 已废弃——v2.1.287 起被忽略，设成 0 不会关掉 mods，要关用上面那三层开关。

## 实现资料（要复现一个最小 mod 时）

前置：`claude --version` 需 ≥ 2.1.287（本机 10-04 实测 2.1.282，未满足，本节内容取自官方教程、未在本机执行）。以下结构与代码取自官方 create 教程的 first-mod 样例，10-04 核对。

**目录结构**

```text

├── .claude-plugin/
│   └── plugin.json
└── hooks/
    ├── hooks.json
    └── register.js
```

**插件清单** `first-mod/.claude-plugin/plugin.json`

```json
  "name": "first-mod",
  "version": "0.1.0",
  "description": "Counts Claude's tool calls, shows the count beside the spinner, and adds a /tally command",
  "author": { "name": "Your Name" }
}
```

**hooks 配置** `first-mod/hooks/hooks.json`（`modules` 字段是「这是一 mod」的标志）

```json

  "modules": ["./register.js"]
}
```

**代码本体** `first-mod/hooks/register.js`（四个处理器：注册命令、计数、回答命令、改写 spinner）

```javascript
// The count, shared by the hooks below
let calls = 0

// Claude Code calls this once when the mod loads
export function register(on) {
  // Runs when the session starts, before your first prompt
  on('session.start', async ($, e, next) => {
    // Add the /tally command
    await $.command.register({
      name: 'tally',
      description: 'Show how many tool calls Claude has made',
    })
    // Let the session start as usual
    return next(e)
  })

  // Runs each time Claude is about to use a tool
  on('tool.call', async ($, e, next) => {
    calls += 1
    // Ask Claude Code to draw the interface again, so the new count shows
    $.ui.invalidate('ui.render')
    // Let the tool run as usual
    return next(e)
  })

  // Runs when you type /tally, and only then, because of the matcher
  on('command.run', { command: 'tally' }, async () => {
    // The text to print in the transcript
    return { text: 'Claude has made ' + calls + ' tool calls since this mod loaded' }
  })

  // Runs each time Claude Code draws the spinner
  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    // Keep Claude Code's spinner, with the count added after its word
    return next({ ...e, props: { ...e.props, suffix: ' · tool calls: ' + calls + '…' } })
  })
}
```

**加载与验证**

```bash
# 单会话加载（目录被监视，保存后回合结束自动重载）
claude --plugin-dir ./first-mod

# 非交互环境下验证命令（不启动交互会话）
claude -p "/tally" --plugin-dir ./first-mod
# 输出示例：first-mod: Claude has made 0 tool calls since this mod loaded

# 静态检查：不运行代码，列出会接的事件与调用的 API
claude plugin validate ./first-mod
# 输出示例：
#   ❯ ./register.js hooks: session.start, tool.call, command.run{command=tally}, ui.render{component=Spinner}
#   ❯ ./register.js calls: $.command.register, $.ui.invalidate
# ✔ Validation passed
```

**自动化测试**（存为 `first-mod/tests/first-mod.test.ts`，在 first-mod 目录内跑 `claude plugin test`；无会话、无登录、无网络）

```typescript
import { expect, test } from 'claude-code/testing'

test('/tally reports the tool calls the mod has seen', async ($, on) => {
  // Answer each tool call in Claude Code's place, so no tool runs
  on('tool.call', () => ({ result: 'ok' }))

  // Fire two tool calls, which the mod's tool.call hook counts
  await $.tool.call({ tool: 'Bash', command: 'ls' })
  await $.tool.call({ tool: 'Read', file_path: 'README.md' })

  // Run /tally and check the text its hook returns
  const answer = await $.command.run({ command: 'tally', args: '' })
  expect(answer.text).toBe('Claude has made 2 tool calls since this mod loaded')
})
```
